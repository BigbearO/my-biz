# 多环境配置方案

> 本文是脚手架模板级文档,随模板复制到每个派生项目。目标是提供与 springboot `application-{profile}.yml` 同体验的多环境配置:不同环境使用不同的配置文件,差异文件只写差异。

## 环境选择

优先级从高到低:

1. 命令行 `-e <env>`(如 `server -conf ./configs -e test`)
2. 环境变量 `APP_ENV`(容器/CI 用,`docker run -e APP_ENV=test`)
3. 默认 `dev`

env 名校验仅允许 `[a-z0-9_-]`,非法值(如 `-e Dev`)启动即失败,不带病运行。
二者皆未指定时默认按 `dev` 处理——configs 里的 `*.dev.yaml` 覆盖文件会自动生效。

## 文件组织

```
configs/
├─ bootstrap.yaml      # 引导配置(app/nacos/trace/log),始终单文件,不分环境
├─ server.yaml         # 基础配置
├─ data.yaml           # 基础配置
├─ server.dev.yaml     # dev 差异覆盖:只写与基础不同的键
├─ data.dev.yaml
├─ server.test.yaml    # test 差异覆盖
└─ data.test.yaml
```

- 覆盖文件匹配规则:`<name>.<env>.<ext>`,且 name 去掉 `.<env>` 后中间不含其他点。
  `server.dev.yaml` 算;`server.test.extra.yaml` 不算(避免误伤多段命名)。
- 覆盖文件只写差异键,其余键沿用基础文件(kratos 深合并语义)。
- 镜像/构建产物打包**全部** `*.yaml`(与 springboot 打包所有 profile 文件一致),运行时按环境挑选。

## 合并优先级

低 → 高:

```
基础 yaml  <  <base>.<env>.yaml 覆盖文件  <  nacos dataId(业务段)  <  WIND_* 环境变量
```

`app.env`(OTEL `deployment.environment.name` 标签)的归属链:

```
WIND_APP_ENV  >  覆盖文件里的 app.env  >  -e/APP_ENV(显式指定时)  >  bootstrap.yaml 的 app.env  >  "dev"
```

注意:`app.env` **不参与配置文件选择**(文件选择只看 `-e`/`APP_ENV`/默认 dev),只影响 OTEL 标签。

## 实现原理

实现全部位于 `pkg/bootstrap` 单包,纯标准库,零新依赖:

| 文件 | 职责 |
|---|---|
| `envfile.go` | 环境名校验、目录扫描(基础/覆盖分组)、覆盖文件是否定义 app.env 的判定;顶部为完整使用约定 |
| `config.go` | `loadConfig` 按"基础文件 → 覆盖文件 → nacos → WIND_*"顺序组装逐文件 source |
| `bootstrap.go` | `Run` 内统一注册 `-conf`/`-e` flag(APP_ENV 作默认值) |
| `envsource.go` | `WIND_*` 环境变量源(既有) |

两个关键技术点:

1. **必须逐文件 source,不能用整目录 source。** kratos 的优先级 = source 注册顺序(后注册覆盖先注册);整目录 source 内部按 `os.ReadDir` 文件名字典序合并,`"server.dev.yaml" < "server.yaml"`(`d` < `y`),基础文件反而后合并、会覆盖掉环境差异——方向正好相反。
2. **向后兼容可严格证明。** 无覆盖文件时,逐文件 source 的合并顺序(字典序)与深合并语义和原整目录 source 完全一致,行为逐字节等价。

## 使用约定(红线)

1. **覆盖文件不要写 `nacos:` 段。** 配置中心的挂载参数(addr/namespace/group/dataId)由 `readLocalNacosSection` 只读 `bootstrap.yaml` 预读固化;而 nacos 注册客户端用的是 Scan 合并后的值。覆盖文件写了会导致「配置读 A 环境、服务注册到 B 环境」的静默分裂。nacos 侧的环境隔离正道是 **namespace/dataId 区分**。
2. **覆盖文件不建议写 `app.env`**(会压过 `-e` 选定值,语义混乱)。
3. **`WIND_*` 只适合覆盖字符串值**(DSN、地址等)。值以原始字符串注入,Scan 到 bool/int 字段会报 `cannot unmarshal string into ...`;布尔与数字差异请用覆盖文件或远端配置。
4. `-conf`/`-e` 由 `bootstrap.Run` 统一注册,服务 `main` 不得重复注册(否则 flag redefined panic)。

## 已知限制

- `app:` 下深层嵌套键(如 `app.foo.env:`)会被误判为覆盖文件定义了 `app.env`——按约定覆盖文件不写复杂 app 段,可接受。
- 若未来需要 per-env 的 nacos **连接参数**(而非 namespace/dataId 切换),需扩展 `readLocalNacosSection` 支持 `bootstrap.<env>.yaml` 合并预读,当前不支持。
- watch 热更新:逐文件 watcher 与原整目录 watcher 行为等价(变更整文件重载),机制未变。

## 用法速查

```bash
# 本地
go run ./cmd/server -conf ./configs -e dev
go run ./cmd/server -conf ./configs            # 默认 dev
APP_ENV=test go run ./cmd/server -conf ./configs

# Makefile(仓库根或服务目录)
make run APP_ENV=test

# Docker
docker run -e APP_ENV=test <image>             # 运行时指定
docker build --build-arg APP_ENV=test -t x .   # 构建期固化默认
```
