# 提案：添加订单管理系统

## 摘要
实现一个全面的代练订单管理系统，支持Excel批量导入、多平台订单同步（从闲鱼开始），以及基于游戏类型、账号和商品SKU的自动会员时长计算。

## 类型
新能力

## 动机
当前项目缺乏跨多平台管理订单的系统。手动处理订单既耗时又容易出错。我们需要一个统一的系统，能够：
- 通过Excel批量导入订单
- 自动从闲鱼等平台同步订单
- 智能计算和跟踪会员时长
- 提供订单和账号的集中视图

## 目标
- 实现高效的Excel批量订单导入
- 支持从闲鱼（未来包括其他平台）自动同步订单
- 实现智能的会员时长计算：
  - 如果账号不存在：创建新账号，从支付时间开始
  - 如果账号存在且在会员期间：将天数加到现有过期时间
  - 如果账号存在但不在会员期间：从当前时间开始
- 提供全面的订单和账号管理API
- 支持两种游戏类型：原神和星穹铁道

## 非目标
- 用户游戏账号的认证和管理（游戏账号是预先分配的）
- 代练任务的调度和执行
- 支付处理（订单导入时默认为"已支付"）
- 账号过期的实际处理（仅筛选，实际处理在单独的日常任务中）
- MQ功能（接口预留，但在v1.0中未主动使用）

## 成功标准
- [ ] Excel导入可以在30秒内处理1000+订单
- [ ] 闲鱼订单同步可以自动（每小时）和手动工作
- [ ] 会员时长计算准确并遵循指定规则
- [ ] 所有15+个RESTful API端点正常工作
- [ ] 定时任务无误执行
- [ ] 单元测试覆盖率 > 80%
- [ ] 多租户数据隔离正常工作
- [ ] 系统可部署并可用于生产

## 风险和缓解措施

| 风险 | 概率 | 影响 | 缓解措施 |
|------|-------------|--------|------------|
| 闲鱼API变更 | 中 | 高 | 封装API调用以便快速适应 |
| Excel导入性能 | 中 | 中 | 使用流式读取、批量处理 |
| 多租户数据泄露 | 低 | 高 | 使用MyBatis Plus拦截器自动过滤 |
| 时长计算错误 | 低 | 高 | 全面的单元测试、边缘情况覆盖 |

## 已考虑的替代方案
- **手动订单录入**：太慢且容易出错
- **无自动化**：不可扩展
- **每个平台的独立系统**：增加维护开销

## 待解决问题
1. 在v1.0中我们是否应该在闲鱼之外添加更多平台？
   - **答案**：不，仅从闲鱼开始，在未来的迭代中添加其他平台
2. 我们应该立即处理过期账号还是仅筛选它们？
   - **答案**：仅筛选它们，实际处理在单独的日常任务中进行
3. 我们应该在v1.0中使用MQ处理账号过期事件吗？
   - **答案**：不，保留接口但不主动使用

## 相关变更
- 数据库：添加7个新表（game_type_config、commodity_sku、platform_config、trade_order、game_account、account_duration_record、order_sync_log）
- 配置：添加闲鱼API配置
- 定时任务：添加2个新任务（闲鱼同步、账号过期扫描）

## 依赖项
- **外部**：闲鱼开放API（需要AppKey和AppSecret）
- **内部**：Pig微服务框架、Nacos、MySQL
- **模块**：order-api（需要先创建）
