# 项目背景

## 目的
LogViewer 是一个基于 Elasticsearch 的日志查看和分析系统，提供高效的日志查询、过滤和可视化功能，帮助开发者快速定位问题和监控系统运行状态。

## 技术栈
- **后端框架**: Go 1.25
- **Web 框架**: 双框架架构
  - **Gin v1.11.0**: 位于 `gin/` 目录，传统 REST API 实现
  - **go-zero v1.9.2**: 位于 `gozero/` 目录，微服务框架实现
- **搜索引擎**: Elasticsearch v8 (go-elasticsearch v8.19.0)
- **配置管理**: Viper v1.21.0
- **API 文档**: go-zero API (.api 文件)
- **前端**: 静态文件服务 (HTML/CSS/JavaScript)

## 项目规范

### 代码风格
- 使用 Go 标准代码格式化（gofmt）
- 遵循 Go 官方编码规范
- 包名使用小写单数形式
- 导出的函数、类型和常量使用 PascalCase
- 私有变量和函数使用 camelCase

### 架构模式
- **双框架分离架构**: 两个框架代码位于独立目录，共享基础设施层
  ```
  project/
  ├── gin/              # Gin 框架（入口 + 路由 + Handler）
  ├── gozero/           # go-zero 框架（入口 + Handler + Logic）
  ├── infra/            # 共享基础设施层（ES 客户端 + 查询逻辑）
  ├── static/           # 共享静态资源
  └── etc/
      ├── gin/          # Gin 配置文件
      └── gozero/      # go-zero 配置文件
  ```
- **共享基础设施**: `infra/es/` 层提供 ES 查询构建和执行函数，两个框架共用
- **框架职责分离**: 框架层只负责 HTTP 处理和响应，查询逻辑在 `infra/es/` 层
- **依赖注入**:
  - Gin: 使用全局 ES 客户端变量
  - go-zero: 使用服务上下文（ServiceContext）管理依赖
- **API 定义优先**: go-zero 使用 .api 文件定义接口规范

### 测试策略
- 单元测试覆盖核心业务逻辑
- ES 客户端集成测试使用测试环境
- API 接口测试覆盖主要查询场景

### Git 工作流

## 领域背景

### 日志数据结构
日志文档包含以下关键字段:
- `@timestamp`: 日志时间戳
- `level`: 日志级别 (INFO, WARN, ERROR 等)
- `message`: 日志消息
- `app`: 应用名称
- `trace_id`: 链路追踪 ID
- `env`: 环境标识 (dev, test, prod)
- `logger_name`: Logger 名称
- `thread_name`: 线程名称

### 核心功能
1. **日志查询**: 支持多维度条件查询（级别、应用、环境、时间范围等）
2. **标签过滤**: 支持自定义标签和操作符的复杂查询
3. **分页查询**: 支持大数据量的分页返回
4. **健康检查**: 提供系统健康状态接口

## 重要约束
- Elasticsearch 版本: 8.x
- 索引命名规范: logs-* 前缀
- 单次查询最大返回数: 由分页参数控制（默认 15，最大 100）
- 服务端口: 两个框架默认都使用 8008（可通过配置修改为不同端口）
- 跨域支持: 允许所有来源（开发阶段）
- **架构约束**: ES 查询逻辑必须在 `infra/es/` 层，框架层只负责 HTTP 处理

## 外部依赖
- **Elasticsearch**: 日志存储和搜索引擎
- **Redis**: （可选）缓存层
- **静态资源**: 前端页面和资源文件
