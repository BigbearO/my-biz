# 日志收集改造方案：统一格式 + 纯网络推送

## 一、总体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│  三端业务服务 —— 全部通过 forward 协议 (TCP 24224, msgpack) 推送日志  │
├─────────────┬─────────────────┬─────────────────────────────────────┤
│ Spring      │ kratos          │ Quarkus                             │
│ ai-biz      │ bear-admin      │ template-provider                   │
│             │                 │                                     │
│ FluentBit   │ tx7do fluent    │ FluentBitHandler                    │
│ Appender    │ (自动注入 app)  │ (Fluency forward)                   │
└─────┬───────┴────────┬────────┴──────────────┬──────────────────────┘
      │                │                        │
      └────────────────┼────────────────────────┘
                       │ TCP :24224 msgpack（纯网络，不落盘）
                       ▼
            ┌──────────────────────┐
            │     Fluent Bit       │
            │  forward input       │
            │  + Lua filter 归一化 │  ← 唯一归一化点
            │  + http output       │
            └──────────┬───────────┘
                       │ HTTP JSON /_json
                       ▼
            ┌──────────────────────┐
            │    OpenObserve       │
            │    :5080             │
            └──────────────────────┘
```

**核心原则**：
- 三端只推送"原始字段"，不做任何格式归一化
- 所有格式归一化收敛到 **Fluent Bit 的 Lua filter** 一处处理
- 三端全部走网络推送（forward 协议），不写本地日志文件给 Fluent Bit 读取
- 最终落库到 OpenObserve 的字段集合和值格式**三端完全一致**

---

## 二、统一日志 Schema

落库到 OpenObserve 的每条日志记录字段完全一致：

| 字段 | 类型 | 说明 | 来源 |
|------|------|------|------|
| `timestamp` | string (ISO8601) | 统一时间格式 | Fluent Bit 事件时间 |
| `level` | string | TRACE / DEBUG / INFO / WARN / ERROR | 三端推送 → Lua 归一 |
| `app` | string | 服务名：ai-biz / bear-admin / template-provider | 三端显式推送 |
| `logger` | string | 类名 / logger 名（无则空串） | 三端推送 |
| `thread` | string | 线程名（无则空串） | 三端推送 |
| `message` | string | 日志正文 | 三端推送 (kratos 的 msg 由 Lua 改名) |
| `trace_id` | string | 链路追踪 ID（无则空串） | MDC / 上下文携带 |
| `exception` | string | 异常堆栈（无则空串） | 错误时推送 |
| `host` | string | 产生日志的主机名 | Fluent Bit Lua 注入 |
| `tag` | string | 客户端原始 tag | Fluent Bit 注入 |
| `collector` | string | 固定 `fluent-bit` | Fluent Bit Lua 注入 |

## 三、基础设施改造（`container/`）

### 3.1 新建归一化脚本：`container/fluent/normalize.lua`

```lua
function normalize(tag, ts, record)
    -- 服务名兜底
    if not record["app"] or record["app"] == "" then
        record["app"] = "unknown"
    end

    -- 级别归一：主要处理 Quarkus/JUL 的 WARNING/SEVERE 等
    local lvlmap = {
        WARNING = "WARN", SEVERE = "ERROR", FINE = "DEBUG",
        FINER = "DEBUG", FINEST = "DEBUG", CONFIG = "INFO",
        INFO = "INFO", DEBUG = "DEBUG", ERROR = "ERROR",
        WARN = "WARN", TRACE = "TRACE"
    }
    local lvl = string.upper(tostring(record["level"] or ""))
    record["level"] = lvlmap[lvl] or "INFO"

    -- 消息字段统一：kratos 用 msg，其余用 message
    if not record["message"] or record["message"] == "" then
        record["message"] = record["msg"] or ""
    end
    -- 清理冗余字段
    record["msg"] = nil
    record["time"] = nil    -- 丢弃原始时间，统一用 Fluent Bit timestamp

    -- 保证所有 key 集合一致（缺的填空串）
    if not record["logger"]    then record["logger"]    = "" end
    if not record["thread"]    then record["thread"]    = "" end
    if not record["trace_id"]  then record["trace_id"]  = "" end
    if not record["exception"] then record["exception"] = "" end

    -- Fluent Bit 侧补充字段
    record["host"]      = os.getenv("HOSTNAME") or ""
    record["collector"] = "fluent-bit"

    return 1, ts, record
end
```

### 3.2 重写：`container/fluent/fluent-bit.conf`

```ini
[SERVICE]
    Flush        1
    Daemon       off
    Log_Level    info
    parsers_file parser.conf

# 网络接收：fluentd forward 协议，三端通用
[INPUT]
    Name          forward
    Listen        0.0.0.0
    Port          24224
    Mem_Buf_Limit 50MB

# 唯一归一化点：Lua filter 保证三端最终格式完全一致
[FILTER]
    Name          lua
    Match         *
    script        /conf/normalize.lua
    call          normalize

# 输出到 OpenObserve
[OUTPUT]
    Name          http
    Match         *
    Host          openobserve
    Port          5080
    URI           /api/default/application/_json
    Format        json
    Json_Date_Key     timestamp
    Json_Date_Format  iso8601
    HTTP_User     root@example.com
    HTTP_Passwd   lk123456A@
    Compress      gzip
    Tls           off
    Include_Tag_Key On
    Tag_Key       tag
```

### 3.3 修改：`container/fluent.yml`

```yaml
services:
  fluent-bit:
    image: fluent/fluent-bit:4.0
    container_name: fluent-bit
    volumes:
      - ./fluent:/conf:rw
    ports:
      - "24224:24224"          # 新增：接收 forward 日志
    command: ["/fluent-bit/bin/fluent-bit","-c","/conf/fluent-bit.conf"]
```

> **变更说明**：
> - 新增 `ports: 24224:24224` 暴露 forward 端口
> - 删除原有文件挂载 `/logs:/logs:ro`（不再需要读本地日志文件）
> - `fluent/fluent-bit:4.0` 内置 lua filter，无需额外插件

### 4.2 Spring（`java/ai/ai-biz`）

#### step 1：添加依赖

**文件**：`pom.xml`

```xml
<!-- fluent forward 客户端：msgpack 协议推送到 Fluent Bit -->
<dependency>
    <groupId>org.fluentd</groupId>
    <artifactId>fluent-logger</artifactId>

</dependency>
```

#### step 2：新建 FluentBitAppender

**文件**：`src/main/java/com/bigbear/aibiz/log/FluentBitAppender.java`

```java
package com.bigbear.aibiz.log;

import ch.qos.logback.classic.spi.ILoggingEvent;
import ch.qos.logback.classic.spi.ThrowableProxyUtil;
import ch.qos.logback.core.AppenderBase;
import org.fluentd.logger.FluentLogger;

import java.util.HashMap;
import java.util.Map;

public class FluentBitAppender extends AppenderBase<ILoggingEvent> {

    private String host = "localhost";
    private int port = 24224;
    private String tag = "app.ai-biz";
    private String app = "ai-biz";
    private FluentLogger fluentLogger;

    public void setHost(String host) { this.host = host; }
    public void setPort(int port) { this.port = port; }
    public void setTag(String tag) { this.tag = tag; }
    public void setApp(String app) { this.app = app; }

    @Override
    public void start() {
        fluentLogger = FluentLogger.getLogger(tag, host, port);
        super.start();
    }

    @Override
    public void stop() {
        if (fluentLogger != null) {
            fluentLogger.close();
        }
        super.stop();
    }

    @Override
    protected void append(ILoggingEvent event) {
        Map<String, Object> data = new HashMap<>();
        data.put("app", app);
        data.put("level", event.getLevel().toString());
        data.put("logger", event.getLoggerName());
        data.put("thread", event.getThreadName());
        data.put("message", event.getFormattedMessage());

        if (event.getMDCPropertyMap() != null && !event.getMDCPropertyMap().isEmpty()) {
            data.putAll(event.getMDCPropertyMap());  // trace_id 等
        }

        if (event.getThrowableProxy() != null) {
            data.put("exception", ThrowableProxyUtil.asString(event.getThrowableProxy()));
        }

        fluentLogger.log(tag, event.getTimeStamp(), data);
    }
}
```

#### step 3：修改 logback 配置

**文件**：`src/main/resources/logback-spring.xml`

在 `<appender ...>` 区块中新增：

```xml
<!-- 网络推送到 Fluent Bit（forward 协议），非本地环境启用 -->
<springProfile name="!local">
    <appender name="fluentBit" class="com.bigbear.aibiz.log.FluentBitAppender">
        <host>${FLUENT_BIT_HOST:-localhost}</host>
        <port>${FLUENT_BIT_PORT:-24224}</port>
        <tag>app.ai-biz</tag>
        <app>ai-biz</app>
    </appender>
</springProfile>
```

在 `<root>` 中挂载：

```xml
<root level="INFO">
    <appender-ref ref="console"/>
    <springProfile name="!local">
        <appender-ref ref="fluentBit"/>
    </springProfile>
</root>
```

> **说明**：通过 `springProfile` 仅在非 `local` 环境启用，避免本地开发时往外推送日志。原有的 `logback-plus.xml` 中 `app.json` 文件 appender 可以删除（不再落盘）。

### 4.3 Quarkus（`java/xxs-micro/xxs-quarkus-template`）

#### step 1：添加依赖

**文件**：`pom.xml`

#### step 2：新建 FluentBitHandler（JUL Handler）

**文件**：`template-provider/src/main/java/.../log/FluentBitHandler.java`

```java
package ... .log;

import org.komamitsu.fluency.Fluency;

import java.util.HashMap;
import java.util.Map;
import java.util.logging.Handler;
import java.util.logging.LogRecord;

public class FluentBitHandler extends Handler {

    private final Fluency fluency;
    private final String tag;
    private final String app;

    public FluentBitHandler(Fluency fluency, String tag, String app) {
        this.fluency = fluency;
        this.tag = tag;
        this.app = app;
    }

    @Override
    public void publish(LogRecord record) {
        if (!isLoggable(record)) return;

        Map<String, Object> data = new HashMap<>();
        data.put("app", app);
        data.put("level", record.getLevel().getName());   // 级别由 Fluent Bit Lua 归一
        data.put("logger", record.getLoggerName());
        data.put("thread", Thread.currentThread().getName());
        data.put("message", record.getMessage());

        try {
            fluency.emit(tag, record.getMillis(), data);
        } catch (Exception ignored) {
            // 静默丢弃，避免日志收集异常影响业务
        }
    }

    @Override public void flush() {}
    @Override public void close() { fluency.close(); }
}
```

#### step 3：新建启动注册类

**文件**：`template-provider/src/main/java/.../log/FluentLoggingSetup.java`

```java
package ... .log;

import io.quarkus.runtime.Startup;
import jakarta.enterprise.context.ApplicationScoped;
import jakarta.enterprise.event.Observes;
import jakarta.enterprise.event.ObservesAsync;
import org.komamitsu.fluency.Fluency;

@ApplicationScoped
public class FluentLoggingSetup {

    void onStart(@Observes @io.quarkus.runtime.Startup Object event) {
        Fluency fluency = Fluency.defaultFluency("fluent-bit", 24224);
        java.util.logging.Logger.getLogger("").addHandler(
                new FluentBitHandler(fluency, "app.template-provider", "template-provider"));
    }
}
```

> **说明**：在 Quarkus 启动最早阶段（`@Initialized(Startup.class)`）注册 handler，确保全部日志（包括框架日志）都被捕获推送。`SEVERE`/`WARNING` 等 JUL 级别名会由 Fluent Bit 的 Lua filter 归一为 `ERROR`/`WARN`。

## 五、部署与网络

### 5.1 Docker Compose 网络

确保所有服务在同一 Docker 网络内，地址用服务名即可：

| 地址 | 服务 |
|------|------|
| `fluent-bit:24224` | 三端推送 forward 日志 |
| `openobserve:5080` | Fluent Bit HTTP 输出 |
| `localhost:5080` | 浏览器访问 OpenObserve UI |

若当前 `fluent.yml` 与 `openobserve.yml` 是独立 compose 文件，建议合并为一个或创建公共 network：

```yaml
# 公共 network 示例
networks:
  monitoring:
    name: monitoring
    external: true
```

### 5.2 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `FLUENT_BIT_HOST` | `localhost` (Spring 本地外)/`fluent-bit` (容器内) | Spring 的 forward 地址 |
| `FLUENT_BIT_PORT` | `24224` | forward 端口 |
| `ZO_ROOT_USER_EMAIL` | `root@example.com` | OpenObserve 账号 |
| `ZO_ROOT_USER_PASSWORD` | `lk123456A@` | OpenObserve 密码 |

## 六、验证步骤

1. **启动基础设施**
   ```bash
   cd container
   docker-compose -f fluent.yml up -d
   docker-compose -f openobserve.yml up -d
   ```
   打开浏览器访问 `http://localhost:5080`，用 `root@example.com` / `lk123456A@` 登录。

2. **逐个启动业务服务**（在对应的 profile 下）

3. **制造测试日志**（每个服务各打一条 INFO + 一条 ERROR + 一条含异常）

4. **在 OpenObserve 中验证**
   - 选择 stream `application`
   - 搜索查看日志记录
   - **逐字段对比三个服务的记录**，确认字段集合完全一致

5. **重点验证项**
   - [ ] Quarkus 的 `WARNING` / `SEVERE` 是否显示为 `WARN` / `ERROR`
   - [ ] kratos 的 `msg` 字段是否已转为 `message`
   - [ ] 三条记录的 `timestamp` 是否均为 ISO8601 格式
   - [ ] `app` / `host` / `collector` / `tag` / `trace_id` 等字段是否全部存在
   - [ ] 各服务不会再往本地落日志文件（除非 console 输出）

## 八、设计决策说明

| 决策 | 理由 |
|------|------|
| Lua filter 作为唯一归一化点 | 避免三个端各自实现字段映射，保证一致性且易于维护 |
| forward 协议而非 tail 读文件 | 满足"全部走网络推送"要求，省去磁盘 IO、部署时不需共享 volume |
| 不按服务分 stream | 先统一 `application` 单 stream，通过 `app` 字段区分；后期需要再分 |
| Spring 用 `springProfile` 控制 | 本地开发不推日志，避免依赖 Fluent Bit 环境 |
| Quarkus 用 JUL Handler | 兼容 JBoss Log Manager，在最早启动阶段注册，捕获全量日志 |
