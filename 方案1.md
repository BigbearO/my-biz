# Fluent Bit + OpenObserve 日志收集改造方案

## 一、概述

将 Spring (ai-biz)、Go-Kratos (bear-admin)、Quarkus (xxs-quarkus-template) 三个业务模块的日志通过**网络直接推送**到 Fluent Bit，最终存入 OpenObserve 实现统一日志管理。

### 整体架构

```
┌──────────────────────────────────────────────────────────────────┐
│                          应用层                                  │
│                                                                  │
│  ┌───────────────┐  ┌───────────────┐  ┌──────────────────────┐ │
│  │ Spring ai-biz │  │ Go bear-admin │  │ Quarkus template     │ │
│  │               │  │               │  │                      │ │
│  │ LogstashTCP   │  │ kratos fluent │  │ quarkus-logging-gelf │ │
│  │ JSON over TCP │  │ Forward协议   │  │ GELF over TCP        │ │
│  └───────┬───────┘  └──────┬────────┘  └──────────┬───────────┘ │
│          │                 │                       │             │
└──────────┼─────────────────┼───────────────────────┼─────────────┘
           │ TCP :5170       │ Forward :24224        │ GELF :12201
           ▼                 ▼                       ▼
┌──────────────────────────────────────────────────────────────────┐
│                        采集层                                     │
│                                                                   │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │                    Fluent Bit v4.0                           │ │
│  │                                                              │ │
│  │  INPUT:                                                      │ │
│  │    • forward :24224  (Go-Kratos)                            │ │
│  │    • tcp     :5170   (Spring)                                │ │
│  │    • gelf    :12201  (Quarkus)                               │ │
│  │                                                              │ │
│  │  FILTER:                                                     │ │
│  │    • Go: msg→message, module→logger_name                     │ │
│  │    • Quarkus: _app/_env/_trace_id 去GELF前缀                │ │
│  │    • 通用: 添加 collector=fluent-bit 标签                   │ │
│  │                                                              │ │
│  │  OUTPUT:                                                     │ │
│  │    • OpenObserve (:5080)                                     │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                                                                   │
└──────────────────────────────┬────────────────────────────────────┘
                               │ HTTP ingest
                               ▼
┌──────────────────────────────────────────────────────────────────┐
│                       存储与展示                                  │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │                    OpenObserve                               │ │
│  │  UI:     http://localhost:5080                              │ │
│  │  Ingest: http://localhost:5081                              │ │
│  └─────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

### 技术选型一览

| 模块 | 日志格式 | 传输协议 | Fluent Bit 端口 | 选型原因 |
|------|----------|----------|----------------|----------|
| **Spring** | JSON（LogstashEncoder） | 裸 TCP | `:5170` | Logback 原生 `LogstashTcpSocketAppender`，无需中间层 |
| **Go-Kratos** | MsgPack（kratos fluent logger） | Fluentd Forward | `:24224` | kratos-bootstrap 内置，含 ACK+心跳，可靠性高 |
| **Quarkus** | JSON（GELF） | GELF TCP | `:12201` | `quarkus-logging-gelf` 扩展原生支持，应用层直接推送 |

## 二、Fluent Bit 改造

### 2.1 `container/fluent/fluent-bit.conf` — 重写

```ini
[SERVICE]
    Flush        1
    Daemon       off
    Log_Level    info
    parsers_file parser.conf

# ═════════════════════════════════════════════
# INPUT 1: Fluentd Forward 协议
# 来源：Go-Kratos（kratos fluent logger）
# ═════════════════════════════════════════════
[INPUT]
    Name         forward
    Listen       0.0.0.0
    Port         24224
    Tag          app.forward

# ═════════════════════════════════════════════
# INPUT 2: TCP 接收 JSON 日志
# 来源：Spring（LogstashTcpSocketAppender）
# ═════════════════════════════════════════════
[INPUT]
    Name         tcp
    Listen       0.0.0.0
    Port         5170
    Tag          app.spring
    Format       json
    Chunk_Size   32
    Buffer_Size  64k

# ═════════════════════════════════════════════
# INPUT 3: GELF TCP
# 来源：Quarkus（quarkus-logging-gelf）
# ═════════════════════════════════════════════
[INPUT]
    Name         gelf
    Listen       0.0.0.0
    Port         12201
    Tag          app.gelf

# ═════════════════════════════════════════════
# FILTER 1: 统一 Go 端字段命名
# msg → message, module → logger_name
# ═════════════════════════════════════════════
[FILTER]
    Name         modify
    Match        app.forward
    Rename       msg      message
    Rename       module   logger_name

# ═════════════════════════════════════════════
# FILTER 2: 统一 Quarkus GELF 字段
# GELF 自定义字段以 _ 开头，去掉前缀
# ═════════════════════════════════════════════
[FILTER]
    Name         modify
    Match        app.gelf
    Rename       _app         app
    Rename       _env         env
    Rename       _logger_name logger_name
    Rename       _trace_id    trace_id

# ═════════════════════════════════════════════
# FILTER 3: 统一添加 collector 标签
# ═════════════════════════════════════════════
[FILTER]
    Name         modify
    Match        app.*
    Add          collector fluent-bit

# ═════════════════════════════════════════════
# OUTPUT: OpenObserve
# ═════════════════════════════════════════════
[OUTPUT]
    Name         openobserve
    Match        app.*
    Host         openobserve
    Port         5080
    Organization default
    Stream       logs
    Http_User    root@example.com
    Http_Passwd  lk123456A@
    tls          off
```

### 2.2 `container/fluent/parser.conf` — 调整

```ini
[PARSER]
    Name        json
    Format      json
    Time_Key    @timestamp
    Time_Format %Y-%m-%dT%H:%M:%S.%L%z
    Time_Keep   On
```

### 2.3 `container/fluent.yml` — 调整

```yaml
services:
  fluent-bit:
    image: fluent/fluent-bit:4.0
    container_name: fluent-bit
    volumes:
      - ./fluent:/conf:rw
    command: ["/fluent-bit/bin/fluent-bit","-c","/conf/fluent-bit.conf"]
    ports:
      - "5170:5170"       # TCP JSON 输入（Spring）
      - "24224:24224"     # Fluentd Forward（Go-Kratos）
      - "12201:12201"     # GELF TCP（Quarkus）
    networks:
      - observability
    depends_on:
      - openobserve

networks:
  observability:
    driver: bridge
```

> **变更说明**：原来挂载了宿主机 `logs` 目录用 `tail` 采集，现在改为纯网络输入，不再需要文件挂载。

### 2.4 Fluent Bit 改动清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `container/fluent/fluent-bit.conf` | **重写** | 三个网络输入（forward + tcp + gelf），OpenObserve 输出 |
| `container/fluent/parser.conf` | **修改** | 时间字段对齐 `@timestamp` |
| `container/fluent.yml` | **修改** | 暴露 5170/24224/12201 端口，移除文件挂载 |

## 三、Spring (ai-biz) 改造

### 3.1 新增 Maven 依赖

在 `java/ai/ai-biz/pom.xml` 中新增：

```xml
<dependency>
    <groupId>net.logstash.logback</groupId>
    <artifactId>logstash-logback-encoder</artifactId>
    <version>8.0</version>
</dependency>
```

### 3.2 修改 `logback-spring.xml`

`java/ai/ai-biz/src/main/resources/logback-spring.xml` — 在现有 Console + File appender 基础上，新增 TCP JSON appender 和异步包装：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration debug="false" scan="false">
    <springProperty scope="context" name="spring.application.name"
        source="spring.application.name" defaultValue="ai-biz"/>
    <springProperty scope="context" name="spring.profiles.active"
        source="spring.profiles.active" defaultValue="dev"/>

    <property name="log.path" value="logs/${spring.application.name}"/>
    <property name="CONSOLE_LOG_PATTERN"
        value="${CONSOLE_LOG_PATTERN:-%clr(%d{yyyy-MM-dd HH:mm:ss.SSS}){faint} %clr(${LOG_LEVEL_PATTERN:-%5p}) %clr(${PID:- }){magenta} %clr(---){faint} %clr([%15.15t]){faint} %clr(%-40.40logger{39}){cyan} %clr(:){faint} %m%n${LOG_EXCEPTION_CONVERSION_WORD:-%wEx}}"/>

    <conversionRule conversionWord="clr" converterClass="org.springframework.boot.logging.logback.ColorConverter"/>
    <conversionRule conversionWord="wex" converterClass="org.springframework.boot.logging.logback.WhitespaceThrowableProxyConverter"/>
    <conversionRule conversionWord="wEx" converterClass="org.springframework.boot.logging.logback.ExtendedWhitespaceThrowableProxyConverter"/>

    <!-- ========== 控制台输出（保留） ========== -->
    <appender name="console" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${CONSOLE_LOG_PATTERN}</pattern>
        </encoder>
    </appender>

    <!-- ========== 新增：TCP 推送 JSON 到 Fluent Bit ========== -->
    <appender name="fluentBit" class="net.logstash.logback.appender.LogstashTcpSocketAppender">
        <!-- Docker Compose 内用服务名 fluent-bit，本地开发可改为 localhost -->
        <destination>fluent-bit:5170</destination>
        <connectionTimeout>5000</connectionTimeout>
        <reconnectionDelay>10000</reconnectionDelay>
        <ringBufferSize>8192</ringBufferSize>
        <encoder class="net.logstash.logback.encoder.LogstashEncoder">
            <customFields>{"app":"${spring.application.name}","env":"${spring.profiles.active}"}</customFields>
            <includeMdc>true</includeMdc>
            <includeMdcKeyName>trace_id</includeMdcKeyName>
            <includeContext>true</includeContext>
            <includeCallerData>true</includeCallerData>
            <fieldNames>
                <timestamp>@timestamp</timestamp>
                <version>[ignore]</version>
            </fieldNames>
        </encoder>
    </appender>

    <!-- 异步包装：避免网络阻塞影响业务线程 -->
    <appender name="async_fluentBit" class="ch.qos.logback.classic.AsyncAppender">
        <appender-ref ref="fluentBit"/>
        <queueSize>2048</queueSize>
        <neverBlock>true</neverBlock>
    </appender>

    <!-- ========== 文件输出（保留） ========== -->
    <appender name="debug" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${log.path}/debug.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${log.path}/%d{yyyy-MM, aux}/debug.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxFileSize>50MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <appender name="error" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${log.path}/error.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${log.path}/%d{yyyy-MM}/error.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxFileSize>50MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
        <filter class="ch.qos.logback.classic.filter.ThresholdFilter">
            <level>ERROR</level>
        </filter>
    </appender>

    <logger name="com.alibaba.nacos" level="OFF">
        <appender-ref ref="error"/>
    </logger>

    <root level="INFO">
        <appender-ref ref="console"/>
        <appender-ref ref="debug"/>
        <appender-ref ref="error"/>
        <appender-ref ref="async_fluentBit"/>
    </root>
</configuration>
```

### 4.3 字段兼容性说明

Go 端使用 Fluentd Forward 协议（MsgPack 二进制格式），与 Spring 的 JSON 输出字段名不完全一致。由 Fluent Bit 的 `modify` Filter 统一处理：

| 含义 | Go 字段 | Spring 字段 | 最终字段 | 处理方式 |
|------|---------|-------------|----------|----------|
| 日志消息 | `msg` | `message` | `message` | Fluent Bit `msg → message` |
| 日志级别 | `level` | `level` | `level` | 一致，无需处理 |
| 链路ID | `trace_id` | `trace_id` | `trace_id` | 一致，无需处理 |
| 跨度ID | `span_id` | — | `span_id` | 仅 Go 有 |
| 模块名 | `module` | `logger_name` | `logger_name` | Fluent Bit `module → logger_name` |
| 时间戳 | `time`(MsgPack) | `@timestamp` | 统一 | Fluent Bit 自动处理 |

## 五、Quarkus (xxs-quarkus-template) 改造

Quarkus 使用 **GELF 协议**直接从应用层推送日志到 Fluent Bit，不依赖 Docker logging driver。

### 5.1 新增依赖

`java/xxs-micro/xxs-quarkus-template/pom.xml` 新增：

```xml
<!-- GELF 网络推送日志到 Fluent Bit -->
<dependency>
    <groupId>io.quarkiverse.logging.gelf</groupId>
    <artifactId>quarkus-logging-gelf</artifactId>
    <version>4.1.0</version>
</dependency>
```

### 5.2 修改 `application.properties`

#### `template-provider/src/main/resources/application.properties`

追加以下配置：

```properties
# ============================================================
# GELF：结构化日志直接推送到 Fluent Bit（TCP）
# ============================================================
quarkus.log.handler.gelf.enabled=true
quarkus.log.handler.gelf.host=fluent-bit
quarkus.log.handler.gelf.port=12201
quarkus.log.handler.gelf.protocol=tcp

# 携带 MDC 中的 trace_id
quarkus.log.handler.gelf.include-full-mdc=true
# 携带调用位置（类、方法、行号）
quarkus.log.handler.gelf.include-location=true
# 携带异常堆栈
quarkus.log.handler.gelf.extract-stack-trace=true
quarkus.log.handler.gelf.filter-stack-trace=true

# 自定义附加字段
quarkus.log.handler.gelf.additional-field.app=template-provider
quarkus.log.handler.gelf.additional-field.env=dev

# ============================================================
# 控制台保留人类可读格式（开发调试用）
# ============================================================
quarkus.log.console.format=%d{yyyy-MM-dd HH:mm:ss,SSS} %-5p [%c] (%t) %s%e%n

# 日志级别
quarkus.log.level=INFO
```

#### `template-consumer/src/main/resources/application.properties`

同上，将 `app` 改为 `template-consumer`。

## 九、注意事项

1. **主机名**：配置中的 `fluent-bit` 服务名仅在 Docker Compose 网络内有效，本地开发调试时需改为 `localhost`
2. **Go 端无需新增依赖**：kratos-bootstrap 已内置 fluent logger，只需修改配置和取消注释导入
3. **Quarkus 不使用 Docker logging driver**：直接从应用层通过 GELF 协议推送，架构更统一
4. **字段统一由 Fluent Bit 负责**：Go 端的 `msg`/`module` 和 Quarkus GELF 的 `_xxx` 前缀字段均由 Fluent Bit Filter 统一处理
5. **OpenObserve 认证**：Fluent Bit 输出的用户名/密码需与 `openobserve.yml` 中的环境变量一致
6. **异步处理**：三个模块的输出均为异步（Logback AsyncAppender / Fluentd Forward ACK / GELF TCP Async），不会阻塞业务线程
