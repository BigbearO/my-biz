## 一、功能与职责（总）

### 1.1 功能定位

定义北向接口的**鉴权（Authentication）**与**授权（Authorization）**两层安全机制：鉴权由网关统一校验 token（复用 RuoYi 自带能力，零开发项）；授权由**客户端主动校验**（网关不做兜底）。失败码 401 / 403 严格区分，客户端对应不同的处理策略。

### 1.2 职责边界（两个层次必须分清）

| 层次 | 判定对象 | 谁来做 | 失败响应 | 客户端处理 |
|---|---|---|---|---|
| **鉴权**（Authentication） | token 是否有效 / 是否过期 | **网关统一校验**（RuoYi 自带） | HTTP **401**（业务码 `40101`） | **删除本地 token + 跳转登录页**，不自动重登（A27） |
| **授权**（Authorization） | 该用户是否有使用权限（是否在授权期内） | **客户端主动调用** | HTTP **403** + 业务码 `40301` | **停止所有监听 + 弹窗 + 冻结应用**，只允许退出（A42） |

> **为什么必须区分**：401 是"没登录 / 登录过期"，**重新登录可解决**；403 是"登录了但没权限"，**重新登录解决不了**，必须联系管理员。两者若混用同一错误码，客户端会出现"跳到登录页—重登—又被拒"的死循环。

### 1.3 与其他模块的关系

- **ruoyi-gateway**：鉴权执行点（RuoYi `AuthFilter` + Sa-Token），并在鉴权通过后注入用户身份请求头给 Python 服务
- **ruoyi-system**：提供授权校验接口 `GET /system/auth/access`（复用用户表）
- **Python 服务（goodfish-ai-service）**：无法使用 Sa-Token SDK，靠网关注入的请求头还原身份（详见[技术方案-云端-gRPC发现库xxs-nacos-grpc](技术方案-云端-gRPC发现库xxs-nacos-grpc.md)的身份透传实现）
- **客户端（Electron / Python 本地服务）**：token 的存储方与 401/403 的处理方
- 服务调用矩阵与"内部 gRPC 不引入服务间令牌、靠网络隔离"的约定见[技术方案-云端-架构总览](技术方案-云端-架构总览.md) §四

## 二、逻辑实现（分）

### 2.1 鉴权：所有接口必须带 token

| 项 | 约定 |
|---|---|
| **覆盖范围** | 除白名单外，**所有北向接口都必须携带 token**（客户端接口 + 管理后台接口） |
| **白名单** | 由 RuoYi 网关配置 `security.ignore.whites` 管理（登录、验证码等，即 `/auth/login`、`/auth/captcha`）；`/favicon.ico`、`/actuator/**`、`/error` 已内置放行 |
| **传递方式** | HTTP Header：`Authorization: Bearer <token>`；客户端侧 token 存本地 SQLite `config` 表（Electron 与 Python 两端共用） |
| **校验位置** | **网关统一校验** —— RuoYi-Cloud-Plus 6.x 由 `AuthFilter`（Sa-Token `SaServletFilter`）执行 `StpUtil.checkLogin()`，**零开发项**；本服务与各基础服务**不重复解析 token** |
| **附加校验** | 网关还会校验 `clientid` 请求头与 token 是否匹配（RuoYi 内置 `LoginHelper.CLIENT_KEY`） |
| **失败响应** | Sa-Token 抛 `NotLoginException` → 网关返回 **401**（RuoYi `HttpStatus.UNAUTHORIZED`，业务码 `40101`）；无 token 的请求直接 401，不进入业务逻辑 |

**下游服务如何拿到用户身份**：

| 下游类型 | 方式 |
|---|---|
| **Java 服务**（商品 / 客户端元数据 / 模型 / admin BFF） | 直接使用 Sa-Token：`LoginHelper.getUserId()` / `LoginHelper.getLoginUser()`，**不重复解析 token**（token 已在 header 中透传，Sa-Token 从共享 Redis 取 session） |
| **Python 服务**（`goodfish-ai-service`） | 无法使用 Sa-Token SDK → **由网关在转发时注入用户身份请求头**，Python 侧直接读取 |

**网关转发的请求头清单**：

| 请求头 | 含义 | 来源 |
|---|---|---|
| `Authorization` | 原始 token（透传） | 客户端 |
| `clientid` | 客户端 ID | 客户端 |
| `userId` | 登录用户 ID | 网关从 Sa-Token session 提取（头名沿用 `LoginHelper.USER_KEY`） |
| `userName` | 登录用户名 | 同上（`LoginHelper.USER_NAME_KEY`） |
| `deptId` | 部门 ID | 同上（`LoginHelper.DEPT_KEY`） |

**客户端（Python 本地服务）视角的请求头用途**（本服务用不了 Sa-Token SDK，因此靠头传递身份）：

| 请求头 | 含义 | 本服务用途 |
|---|---|---|
| `Authorization` | 原始 token（透传） | 不解析；仅用于排障与透传 |
| `userId` | 登录用户 ID | 写入请求上下文，用于日志与审计 |
| `userName` | 登录用户名 | 日志 |
| `deptId` | 部门 ID | 日志（预留数据权限） |

> - 头名沿用 RuoYi `LoginHelper` 常量（`userId` / `userName` / `deptId`），由**网关在鉴权通过后注入**（Java 服务侧不走请求头，直接用 `LoginHelper.getUserId()` / `getLoginUser()`）
> - **业务标识不依赖 `userId`**：AI 回复的业务主键是请求体里的 `goodfish_account_id`；Python 服务把 `userId` 存入请求上下文（用于日志与审计）
>
> **改造量**：网关侧新增/扩展一个 filter，在 `AuthFilter` 校验通过后把上述身份字段写入请求头（**约十行代码，仅"搬运身份"，不含任何授权判定**）。

### 2.2 401 统一处理（客户端侧）

```
Python 本地服务 或 Electron 渲染层 收到 401
  ├─ 删除本地 token（SQLite config 表 → 两端同时失效）
  ├─ Python 本地服务在 `/api/system/status` 返回登录态过期标记，渲染层轮询感知后跳转登录页
  ├─ Electron 跳转登录页（全屏），清空主界面状态
  └─ 不自动重新登录，需用户手动输入账号密码（A27）
```

> A27 未要求 401 时停止监听，因此**监听保持运行**；用户重新登录后即可继续。若 token 删除期间产生云端调用，一律按 401 处理（不堆积重试）。

### 2.3 授权：客户端主动校验

**决策：网关不做业务授权判定**（不引入授权状态查询、不加兜底 filter）。

| 理由 | 说明 |
|---|---|
| 职责边界 | 网关只做"认证 + 路由 + 限流"；授权是**业务语义**，放入网关会让基础设施依赖业务数据 |
| 成本 | 网关为每个请求查一次授权状态（或维护缓存），收益不匹配 |
| 已有覆盖 | token 校验已覆盖"未登录 / 登录过期"；客户端每小时主动校验覆盖"授权到期" |

**授权校验接口**：

| 接口 | 方法 | 提供方 | 返回 |
|---|---|---|---|
| `/system/auth/access` | GET | `ruoyi-system` | 授权状态：有效 / 过期 / 未授权 |

**客户端调用时机**（对应 A40、A41）：

```
1. 应用启动时调用一次
2. 运行中每小时调用一次
```

**授权失效的处理时序**（A42）：

```
客户端收到 403 / 40301（授权过期或未授权）
  ├─ 删除本地 token（无权限，留着无意义）
  ├─ 调本地 POST /api/account/stop-all  → 停止所有监听
  ├─ 弹窗"授权已过期"（不提供重新登录入口）
  ├─ 应用冻结，只允许退出
  └─ 不再发起任何云端调用
```

**客户端各时机的动作汇总**（A40 / A41 / A42 / A43）：

| 时机 | 动作 | 验收项 |
|---|---|---|
| 应用启动 | 调 `/system/auth/access`；无权限 → 弹窗"授权已过期" + 冻结，只能退出 | A40 |
| 运行中每小时 | 同上 | A41 |
| 收到 **403 / 40301** | **删除本地 token** + 调本地 `POST /api/account/stop-all` 停止所有监听 + 弹窗 + 冻结 | A42 |
| 接口不可用（云端异常） | 停止所有监听 + 弹窗"服务器异常，请联系管理员" + 冻结；**用与 403 不同的错误码** | A43 |

**接口不可用（云端异常）**（A43）：停止所有监听 + 弹窗"服务器异常，请联系管理员" + 冻结应用。**用与 403 不同的错误码**（503 类），避免与"授权过期"混淆。

> **网关不做授权兜底**：网关只负责 token 有效性校验（复用 RuoYi 自带能力，零开发项，网关零改动）；授权状态由**客户端主动校验**。

### 2.4 已签发 token 的处理（不做特殊处理）

**决策：用户被禁用 / 授权过期后，已签发的 token 不做主动失效处理。**

| 场景 | 处理 |
|---|---|
| 用户被禁用 / 授权过期 | 客户端在**下一次授权校验**（启动时或每小时）得到无权限 → **删除本地 token** + 停止监听 + 冻结应用 |
| 已签发但仍有效的 token | **不主动失效**，不做特殊处理 |
| 后续若因此出现问题 | 届时再处理（本期不做） |

> 即：**不引入"服务端 token 黑名单 / 强制下线"机制**，依赖客户端主动校验兜住。客户端校验是 A40/A41 的验收项，不可省略。
