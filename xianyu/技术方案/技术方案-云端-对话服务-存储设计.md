## 一、功能与职责（总）

### 1.1 功能定位

对话服务自有数据的持久化设计，共三张表：

- `ai_conversation`：对话主表（商品ID + 买家ID 维度的会话）
- `ai_conversation_message`：对话消息表（送入大模型的上下文来源，同时是落库记录）
- `ai_reply_log`：回复决策日志（排障、提示词优化、模型用量统计的主依据）

### 1.2 职责边界 / 范围

- 三张表全部**归属本服务**（对话服务拥有的表：`ai_conversation`、`ai_conversation_message`、`ai_reply_log`）；本服务不存商品、不存提示词配置、不存模型配置。
- 对话上下文全部由本服务维护：客户端不感知、不拉取、不清理历史（无会话记录页，相关 REST 接口已删除）。
- 图片消息**只存 URL 不存 base64**：图片实体由本服务存服务器本地磁盘（72h 保留），`content` 存转存后 URL。
- ORM 模型位于 `app/models/`（`conversation.py` / `message.py` / `reply_log.py`），见 [技术方案-云端-对话服务-框架与生命周期](技术方案-云端-对话服务-框架与生命周期.md) §2.4。

### 1.3 与其他模块的关系

| 模块 | 关系 |
|---|---|
| AI 回复编排 | 回复流程第 14 步在同一事务内写 `ai_conversation_message` / `ai_conversation` / `ai_reply_log`（见 [技术方案-云端-对话服务-AI回复编排](技术方案-云端-对话服务-AI回复编排.md) §2.2） |
| 幂等 | `ai_conversation_message.request_id` 关联幂等键，便于排障与去重核对（见 [技术方案-云端-对话服务-接口与幂等](技术方案-云端-对话服务-接口与幂等.md)） |
| 商品服务 / 模型服务 | `model_name` 字符串快照记录当时使用的模型，用于区分"回复错"是模型问题还是配置变了 |
| 文件存储 | 图片文件存本地磁盘并按 `image.retention_hours`（72h）清理，对话记录长期保留 |

## 二、逻辑实现（分）

### 2.1 总体设计（写入流程）

AI 回复生成成功后，**同一事务**内完成落库（编排流程第 14-15 步）：

1. `ai_conversation_message`：写入本条 user 消息（图片项存本服务图片 URL，不存 base64）+ assistant 回复（含 Token / latency）
2. `ai_conversation`：更新 `last_message_at`
3. `ai_reply_log`：渲染后系统提示词 + intent + 模型 + 回复 + 耗时（排障用）
4. 事务提交后再写幂等结果（Redis，TTL = `idempotency.ttl_seconds`），最后返回响应

`ai_reply_log` 的作用：排查 AI 回复异常、优化提示词、统计模型使用情况与 Token 成本。其中 `rendered_system_prompt`（渲染后的完整系统提示词）是**排查提示词问题的唯一依据**；`model_name` 快照用于区分"回复错"是模型问题还是配置变了。

### 2.2 保留策略

| 数据 | 保留策略 |
|---|---|
| 对话历史（`ai_conversation` / `ai_conversation_message`） | **长期保留，不做过期清理**——完整对话是排障（与 `ai_reply_log` 对照）及后续分析、导出的基础数据。无 `conversation.expire_hours` 配置，无"扫 `last_message_at` 删过期记录"的定时任务 |
| 回复决策日志（`ai_reply_log`） | **长期保留，不做清理**；与对话历史一并留存，是排障与后续统计的主依据 |
| 图片文件（本地磁盘） | 按 `image.retention_hours`（默认 72h）保留，过期由 `tasks/cleanup.py` 统一清理（该定时任务仅负责图片文件） |

## 三、数据设计

### 3.1 对话主表 `ai_conversation`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL | 主键 |
| conversation_id | VARCHAR(128) | 对话ID（商品ID_买家ID），唯一索引 |
| goodfish_item_id | VARCHAR(64) | 商品ID |
| buyer_id | VARCHAR(64) | 买家ID |
| goodfish_account_id | VARCHAR(64) | 闲鱼账号ID |
| last_message_at | TIMESTAMPTZ | 最后消息时间 |
| created_at | TIMESTAMPTZ | 创建时间 |
| updated_at | TIMESTAMPTZ | 更新时间 |

> **对话 ID 口径**：`conversation_id = goodfish_item_id + buyer_id`——`goodfish_item_id` 是**闲鱼全局唯一**商品 ID，因此无需再拼 `goodfish_account_id` 也天然唯一（`goodfish_account_id` 仅作关联标识留存）。该值即需求文档中的 `session_id`，**二者为同一概念**。

### 3.2 对话消息表 `ai_conversation_message`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL | 主键 |
| conversation_id | VARCHAR(128) | 对话ID（联合索引） |
| role | VARCHAR(16) | 角色：user/assistant/system |
| content | TEXT | 消息内容（**图片消息存本服务图片 URL，不存 base64**） |
| message_type | VARCHAR(16) | 类型：text/image |
| request_id | VARCHAR(64) | 关联云端请求（幂等键），便于排障与去重核对 |
| model_name | VARCHAR(64) | 使用的模型（assistant 消息） |
| prompt_tokens | INT | 输入 token 数（TODO） |
| completion_tokens | INT | 输出 token 数（TODO） |
| latency_ms | INT | 耗时毫秒（assistant 消息） |
| created_at | TIMESTAMPTZ | 创建时间 |

### 3.3 回复决策日志 `ai_reply_log`

归属本服务的实体表，字段设计另见 [《云端技术方案.md》](../云端技术方案.md)§7.6。

| 字段 | 说明 |
|---|---|
| `request_id` | 幂等键，与客户端上报的 request_id 对应 |
| `conversation_id` | 对话 ID（商品ID + 买家ID） |
| `account_id` / `item_id` / `buyer_id` | 关联标识 |
| `rendered_system_prompt` | **渲染后的完整系统提示词**（排查提示词问题的唯一依据） |
| `intent` | 意图识别结果：price / tech / chitchat / default（仅统计用） |
| `model_name` | 使用的模型 |
| `user_message` / `ai_reply` | 原始消息 / AI 回复 |
| `prompt_tokens` / `completion_tokens` | Token 消耗 |
| `latency_ms` | 大模型耗时（毫秒） |
| `created_at` | 创建时间 |

### 3.4 索引

**`ai_conversation`**：

- `uk_conversation_id`：conversation_id 唯一索引
- `idx_message_conversation_id`：conversation_id + created_at 联合索引

> 原 `idx_last_message_at` 索引**已删除**：它仅为过期清理而设，现行设计对话历史长期保留、不做过期清理，该索引无用。

**`ai_reply_log`**：`idx_reply_log_conversation_id`、`idx_reply_log_created_at`
