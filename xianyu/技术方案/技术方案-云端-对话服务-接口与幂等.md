## 一、功能与职责（总）

### 1.1 功能定位

定义对话服务 `goodfish-ai-service` 的对外接口契约与请求幂等机制：

- **北向 REST**（经网关）：`/api/ai/reply`（生成 AI 回复，核心接口）、`POST /api/ai/image`（图片上传）、`GET /api/ai/image/view/{filename}`（图片静态访问，免鉴权）
- **内部 gRPC**（服务间，不过网关）：本服务作为消费方调用商品服务 / 模型服务；预留被管理后台 BFF 调用的 `DialogService.GetConversationStats`
- **幂等**：客户端在**确定性失败（`50301` 等）重试**时，按 `request_id` 去重，避免重复生成回复、重复落对话历史、重复计 Token（**超时 / 连接中断客户端不重试**，见 §2.2）
- **同步非流式**：`/api/ai/reply` 为**同步请求-响应**，AI 回复一次性返回；**不使用 SSE、不做流式回复**（客户端↔云端与云端↔大模型均如此）

### 1.2 职责边界 / 范围

- 客户端所有请求**经网关直达本服务**（不经 BFF），网关统一校验 `Authorization: Bearer <token>`；失败 401（业务码 `40101`）→ 客户端删 token + 跳登录页；403（业务码 `40301`）→ 客户端冻结应用。
- 原 `/api/ai/conversation/history`、`/api/ai/conversation/clear` 接口**已删除**——需求明确「不做会话记录页」，无页面消费方；**所有大模型对话上下文由本服务维护**，客户端不感知、不拉取、不清理历史。后续若出现真实消费方（如管理后台排障页），再按需新增。
- 原「消息发送结果上报 `/api/ai/send-result`」**已删除**——发送失败仅客户端本地记日志（A19 调整），云端不感知发送结果。
- 内部 gRPC **不过网关**，只在集群内网暴露 gRPC 端口（K8s NetworkPolicy / 安全组限制来源）——**这是内部接口的保护方式，不靠自定义令牌**。

### 1.3 与其他模块的关系

| 模块 | 关系 |
|---|---|
| 网关 | 路由 `/api/ai/**` → `lb://goodfish-ai-service`（路径透传，不 StripPrefix）；统一鉴权；`/api/ai/image/view/{filename}` 加入白名单 `security.ignore.whites` 免鉴权（**仅此路径**，上传接口不放行） |
| 客户端 | 上传图片、发起 AI 回复请求；重试时复用同一 `request_id` |
| 大模型厂商 | 拉取 `/api/ai/image/view/{filename}` 图片 URL（无法携带 token，故免鉴权；公网可达） |
| 商品服务 / 模型服务 | 内部 gRPC 下游，契约见 [《云端技术方案.md》](../云端技术方案.md)§6.4 |
| 文件存储 | 图片存服务器本地磁盘（本版本不上云存储、不使用 ruoyi-file），见 [技术方案-云端-文件存储](技术方案-云端-文件存储.md) |

## 二、逻辑实现（分）

### 2.1 总体设计

- 请求入口先做幂等检查，再进入三段式回复编排（见 [技术方案-云端-对话服务-AI回复编排](技术方案-云端-对话服务-AI回复编排.md)）。
- 幂等基于 Redis 键 `ai:idem:{request_id}`：结果缓存 + 处理中占位两层。
- `request_id` 由客户端生成，同一批次重试**保持不变**：

```
request_id = sha1(f"{account_id}:{item_id}:{buyer_id}:{批次最后一条 message_id}")[:32]
```

### 2.2 请求幂等设计

**问题**：客户端在**确定性失败（`50301`）**时会重试同一批消息；若服务端**已处理但响应丢失**，重试会造成「重复生成回复 + 重复落对话历史 + 重复计 Token」。（**超时 / 连接中断客户端不重试**，见客户端《技术方案-客户端-云端调用与容错》；但并发同 `request_id` 的重复处理仍需幂等拦截。）

**方案**：客户端生成稳定 `request_id`，服务端按此键去重。

| 环节 | 处理 |
|---|---|
| 请求入口 | 先查 Redis `ai:idem:{request_id}`：命中 → **直接返回缓存响应**，不进入后续流程 |
| 处理完成 | 把完整响应体（含 `reply` / `model_name` / `latency_ms`）写入 Redis，TTL = `idempotency.ttl_seconds`（默认 600s） |
| 处理中 | 先 `SET NX` 占位，TTL = `idempotency.processing_ttl_seconds`（默认 **100s = 90s 最坏路径 + 10s 缓冲**——占位必须覆盖最坏处理时长，否则 LLM 慢请求期间占位过期，同 `request_id` 的并发/重试会穿透幂等造成重复生成）；占位存在但无结果 → 返回 50301，客户端退避重试（避免并发重复处理） |
| Redis 不可用 | 降级为"不去重"（记录 WARN），保证可用性优先；重复回复是低频问题，比拒绝服务可接受 |
| 客户端配合 | 同一批次重试时 **`request_id` 保持不变**；只有真正的新消息批次才生成新 ID |

> 与客户端监听流程（[技术方案-客户端-消息处理流水线](技术方案-客户端-消息处理流水线.md) §2.1 步骤 8）呼应：
> - **确定性失败**（`50301` 等）客户端会重试，**必须复用同一个 `request_id`**，否则幂等失效；
> - **超时 / 连接中断**客户端**不重试**——服务端若最终处理完成，其结果仅留在 Redis（客户端本轮不会读取），下一条消息批次会用新 `request_id` 重新发起。

## 三、数据设计（幂等键）

| 键 | 说明 |
|---|---|
| `ai:idem:{request_id}`（结果） | 完整响应体 JSON，TTL = `idempotency.ttl_seconds`（600s） |
| `ai:idem:{request_id}`（处理中占位） | `SET NX` 占位标记，TTL = `idempotency.processing_ttl_seconds`（100s） |

图片消息体不落 base64：`ai_conversation_message.content` 只存本服务图片 URL（表结构见 [技术方案-云端-对话服务-存储设计](技术方案-云端-对话服务-存储设计.md)）。

## 四、接口设计

### 4.1 对外接口（供客户端调用，经网关 `lb://goodfish-ai-service`）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/ai/reply` | POST | 生成 AI 回复（核心接口） |
| `/api/ai/image` | POST | **图片上传**：客户端把下载好的 PNG 上传到本服务，存服务器本地磁盘，返回访问 URL |
| `/api/ai/image/view/{filename}` | GET | **图片访问**（静态）：供大模型厂商拉取，**免鉴权**（需加入网关白名单 `security.ignore.whites`，仅此路径）；文件名用 UUID，不可枚举 |

> 网关路由示例：`Path=/api/ai/**` → `lb://goodfish-ai-service`（路径透传，不 StripPrefix）。客户端请求 `https://<云端域名>/api/ai/reply`。

### 4.2 图片上传与免鉴权静态访问

**上传接口**：

```json
// POST /api/ai/image  （Content-Type: image/png，body 为 PNG 二进制；需带 Authorization）
// 响应
{ "code": 0, "message": "success", "data": { "url": "https://<云端域名>/api/ai/image/view/3f9a6c11e2b84d7a.png" } }
```

- 单张体积 ≤ `image.max_size_mb`，超出返回 40001
- 存储目录 `image.storage_dir`（服务器本地磁盘），文件名服务端生成（UUID），**本版本不上云存储、不使用 ruoyi-file**
- 返回的 URL = `image.public_base_url` + 文件名；大模型厂商侧拉取该 URL 需公网可达
- **长期保留**：图片文件不做过期清理（无 `tasks/cleanup.py`），与对话历史同生命周期

**端到端链路**（云端技术方案 §十一 确定链路）：

```
客户端用闲鱼 Cookie 下载图片 → 转 PNG → POST /api/ai/image（带 token）上传
    ↓
对话服务存服务器本地磁盘（image.storage_dir，UUID 文件名）→ 返回访问 URL
    ↓
/api/ai/reply 携带 image_url 字段（值为对话服务图片 URL）
    ↓
对大模型传该 URL（OpenAI 多模态格式 {"type":"image_url","image_url":{"url":...}}）
```

- **静态访问免鉴权**：`GET /api/ai/image/view/{filename}` 需加入网关白名单（`security.ignore.whites`）——大模型厂商拉取图片无法携带 token；**仅此路径放行**（上传 `POST /api/ai/image` 仍需鉴权）；文件名用 UUID，不可枚举，目录不可列
- `public_base_url` 指向经网关的公网域名（厂商侧拉取需公网可达）
- `ai_conversation_message.content` 存该 URL；历史回放复用同一 URL，**不重复上传**
- **长期保留**：图片文件不做过期清理，与对话历史同生命周期（历史回放中的图片 URL 始终可用）
- 客户端下载 / 上传失败降级为占位文本 `[图片]`，不阻断回复流程

### 4.3 核心接口请求/响应

**POST /api/ai/reply**

```json
// 请求
{
  "request_id": "3f9a6c11e2b84d7a9c0f5a2d1b8e4c07",
  "goodfish_item_id": "商品ID",
  "buyer_id": "买家ID",
  "goodfish_account_id": "闲鱼账号ID",
  "message": "这个多少钱？",                          // 本批合并后的买家消息文本 → 渲染进提示词 {{question}}
  "image_url": "https://<云端域名>/api/ai/image/view/3f9a6c11e2b84d7a.png",  // 图片消息时携带（客户端预先上传后端取得的 URL）；多图时可传数组
  "msg_type": "text"                                  // 闲鱼原始字段，客户端能解析到就传（不参与对话路由）
}

// 说明：
// - 买家消息用 message（单字段，本批合并结果），不再用 messages[] 数组；
// - image_url 为【客户端预先上传到后端得到的 URL】（POST /api/ai/image 的返回值，图片已存服务器本地磁盘）
// - msg_type 属闲鱼原始字段，客户端能解析到则传，无则不传；
// - ★ 客户端**不传 session_id**；对话键由云端用 goodfish_item_id + buyer_id 自行组装（见 §3 / 存储设计）。

// 响应
{
  "code": 0,
  "message": "success",
  "data": {
    "reply": "这个50元包邮，要的话直接拍~",
    "conversation_id": "商品ID_买家ID",   // 云端自行组装（item_id + buyer_id）
    "model_name": "gpt-4o",
    "latency_ms": 1234
  }
}

// ★ 同步请求-响应：一次性返回完整 reply，**不走 SSE、不做流式回复**

// 错误响应（商品不存在）
{
  "code": 40401,
  "message": "商品不存在",
  "data": null
}
```

**错误码说明**：

| 错误码 | 说明 | 客户端处理 |
|---|---|---|
| 0 | 成功 | 发送回复 |
| 40101 | **鉴权失败**（token 无效 / 过期） | **删除本地 token + 跳转登录页**，不自动重登（A27） |
| 40301 | **授权过期 / 无权限** | **删除本地 token** + 停止所有监听 + 弹窗 + 冻结应用，只允许退出（A42） |
| 40401 | 商品不存在 | 不回复 |
| 40402 | **商品未配置提示词**（新同步商品，`system_prompt` 为空） | 不回复，记日志（云端取消本次对话，**不调用大模型**） |
| 50001 | 大模型调用失败 | 不回复（TODO：后续可加降级策略） |
| 50002 | **无启用的模型**（模型全部停用 / 未配置，属云端配置错误） | 不回复、**不重试**，记日志；管理端需在模型管理中启用模型 |
| 50301 | 服务不可用 | 重试 3 次，仍失败则弹窗"服务端不可用"，只监听不回复 |
| 40001 | 参数非法（含 `request_id` 缺失） | 不回复，记日志（属客户端 Bug，需修复） |

### 4.4 内部接口（gRPC，服务间调用）

**原 `/api/internal/**` HTTP 前缀作废**，服务间调用统一走 gRPC，契约见 [《云端技术方案.md》](../云端技术方案.md)§6.4：

| gRPC 方法 | 提供方 | 消费方 | 说明 |
|---|---|---|---|
| `DialogService.GetConversationStats` | 本服务 | 管理后台 BFF | 对话统计（对话数、消息数）【预留，本期未启用】 |
| `LlmService.GetEnabledModel` | 模型服务 | 本服务 | 获取启用模型完整配置（**含解密后 API Key**） |
| `ItemService.GetItemRuntimeConfig` | 商品服务 | 本服务 | 取商品 + 提示词运行时配置 |

**安全要求**：

- 内部 gRPC **不过网关**，只在集群内网暴露 gRPC 端口（K8s NetworkPolicy / 安全组限制来源）——**这是内部接口的保护方式，不靠自定义令牌**
- 身份按项目统一规范透传：`X-User-Id` / `X-User-Info` / `Authorization` / `X-Client-Id`（取服务名），HTTP 头 → `ContextVar` → gRPC Metadata 全程同名（见 [技术方案-云端-gRPC发现库xxs-nacos-grpc](技术方案-云端-gRPC发现库xxs-nacos-grpc.md)）
- `LlmService.GetEnabledModel` 返回**明文 API Key**，属最高敏感级别：严禁经浏览器直连，`api_key` 一律**不进日志、不进异常栈、不进 APM 采样**

## 五、异常与容错

| 异常场景 | 处理方案 |
|---|---|
| **处理中途异常** | 释放幂等占位（DEL），避免客户端被"处理中"卡到 TTL 到期 |
| **占位存在但无结果（并发/重试撞上处理中）** | 返回 50301，客户端退避重试 |
| **Redis 不可用（幂等降级）** | 跳过幂等检查并记 WARN；可用性优先，接受低频重复回复 |
| **图片体积超限** | 返回 40001（参数非法） |
| **图片文件缺失 / 已被清理** | 该图降级为占位文本 `[图片]`，记 WARN，不阻断回复流程 |

## 六、配置项

| 配置键 | 默认值 | 说明 |
|---|---|---|
| `idempotency.ttl_seconds` | 600 | request_id 结果缓存有效期（Redis） |
| `idempotency.processing_ttl_seconds` | 100 | 处理中占位 TTL（90s 最坏路径 + 10s 缓冲；必须 ≥ 最坏处理时长） |
| `image.storage_dir` | `/data/goodfish/images` | 服务器本地磁盘目录 |
| `image.public_base_url` | `https://<云端域名>/api/ai/image/view` | 对外访问基础 URL（经网关；大模型厂商拉取需公网可达） |
| `image.max_size_mb` | 10 | 单张上传体积上限（超过返回 40001） |
（图片文件**长期保留**，不做过期清理：无 `retention_hours` 配置、无 `tasks/cleanup.py`，与对话历史同生命周期）

以上键均位于配置中心 Data ID `goodfish-ai-service.yaml`，完整配置见 [技术方案-云端-对话服务-多环境与配置中心](技术方案-云端-对话服务-多环境与配置中心.md) §2.4。
