## 一、功能与职责（总）

### 1.1 功能定位

通过 Nacos 完成对话服务的**配置管理**与**多环境隔离**：

- 本地 bootstrap 只描述"去哪拿配置"（Nacos 连接属性），业务配置全部放 Nacos 配置中心（Data ID：`goodfish-ai-service.yaml`）
- 用 Nacos **namespace** 做环境隔离（dev / test / prod，一个环境一个命名空间），同一份代码零修改部署到不同环境，只靠环境变量切换
- 运行参数支持热更新（配置监听回调），无需重启

### 1.2 职责边界 / 范围

- **入 bootstrap（本地、部署属性）**：`APP_ENV`、Nacos 连接属性（地址/命名空间/账号/缓存目录）、`server.host` / `server.port`（REST 监听地址）、gRPC 监听端口（预留）、`client_id`。监听地址属于"部署属性"，放 bootstrap 而非远程配置，保证"注册端口 == 实际监听端口"，无需两段式启动。
- **入配置中心（远程、业务配置）**：数据库、Redis、大模型调用、对话历史、回复、幂等、图片存储、意图识别词表、下游 gRPC 服务名与调用参数。
- **热更新边界**：运行参数（llm / conversation / reply 等）监听回调直接生效；数据库、Redis 连接信息与连接池参数**仅启动生效**（改后需重启，回调只标 dirty + 告警）。
- `server.host` / `server.port` 不在远程配置里（已上移到 bootstrap），因此不存在"热更新端口"的问题。

### 1.3 与其他模块的关系

| 模块 | 关系 |
|---|---|
| Nacos 集群 | 配置中心 + 注册中心统一入口；gRPC 长连接端口 = 主端口 + 1000 |
| 服务生命周期 | bootstrap 加载与远程配置应用由 FastAPI lifespan 编排，见 [技术方案-云端-对话服务-框架与生命周期](技术方案-云端-对话服务-框架与生命周期.md) |
| 服务注册与发现 | namespace / Group / Cluster 命名规范与注册中心共用同一套约定，见 [技术方案-云端-服务注册与发现](技术方案-云端-服务注册与发现.md)、[技术方案-云端-对话服务-Nacos注册](技术方案-云端-对话服务-Nacos注册.md) |
| 缓存 | 本服务**不做缓存、不做失效订阅**：下游配置每次直接 gRPC 获取，缓存由提供方（商品/模型服务）承担——TTL 兜底 + 编辑时删除 |

## 二、逻辑实现（分）

### 2.1 总体设计

Nacos 3.2 功能使用总览（本服务）：

| Nacos 功能 | 用途 | 实现方式 |
|---|---|---|
| **配置管理** | DB/Redis/LLM/对话历史/回复/幂等 TTL 参数 | `NacosConfigService.get_config()` 启动拉取（监听地址等部署属性走 bootstrap，不入 Nacos） |
| **配置监听** | 运行参数热更新，无需重启 | `add_listener()`，异步回调 |
| **服务注册** | 本服务对外**只注册 HTTP**（`goodfish-ai-service`）；gRPC 仅作客户端，**本期不注册** | `NacosNamingService.register_instance()`，ephemeral，`metadata.protocol` 由 `-grpc` 后缀推导（详见 [技术方案-云端-对话服务-Nacos注册](技术方案-云端-对话服务-Nacos注册.md)） |
| **服务注销** | 优雅下线，先摘流量再停进程 | `deregister_instance()`（lifespan shutdown 首步，逐个注销已注册实例） |
| **服务发现** | 发现下游基础服务的 `{app}-grpc` 并负载均衡 | `subscribe()` 推平 + 客户端 `enabled and healthy` 过滤 + gRPC 内置 `round_robin`（见 [技术方案-云端-gRPC发现库xxs-nacos-grpc](技术方案-云端-gRPC发现库xxs-nacos-grpc.md)） |

bootstrap 配置加载优先级（高 → 低）：

1. OS 环境变量（容器/部署机注入，**推荐方式**）
2. `.env.{APP_ENV}` 文件（本地开发用，不进 git）
3. `.env` 文件（各环境公共默认值）
4. 代码内默认值（仅 dev 可用的兜底）

### 2.2 多环境隔离模型（dev / test / prod）

**用 Nacos namespace 做环境隔离（一个环境一个命名空间），而不是在 Data ID 上拼环境后缀。**

- 命名空间是 Nacos 最强的隔离边界：配置、服务实例完全隔离，dev 的 ai-service **不可能**发现 test 的模型服务
- 同一份代码零修改部署到不同环境，只靠环境变量切换
- Group 保持 `DEFAULT_GROUP` 不动（Group 的定位是同环境内的业务分组，本项目用不上）

```
Nacos 3.2 集群
├── 命名空间 dev        ← 开发环境
│   ├── 配置：goodfish-ai-service.yaml（指向 dev 的 PG/Redis）
│   └── 服务：goodfish-ai-service、goodfish-item-service、
│            goodfish-client-meta-service、goodfish-llm-service、
│            ruoyi-gateway / ruoyi-system / ruoyi-goodfish-admin 等
│            （每个服务按 {app} / {app}-grpc 注册两个服务名）
├── 命名空间 test       ← 测试环境
│   ├── 配置：goodfish-ai-service.yaml（指向 test 的 PG/Redis）
│   └── 服务：同上，test 的实例
└── 命名空间 prod       ← 生产环境（结构相同，本期预留）
```

服务与配置的命名规范（各环境**同名**，靠 namespace 区分）：

| 项 | 值 | 说明 |
|---|---|---|
| 服务名（对话服务） | `goodfish-ai-service` | 业务；网关路由 `lb://goodfish-ai-service` |
| 服务名（对话服务 gRPC） | `goodfish-ai-service-grpc` | **预留**；本期 Python 不提供 gRPC 服务，故不注册 |
| 服务名（商品服务） | `goodfish-item-service` / `goodfish-item-service-grpc` | 基础；ai-service 经 gRPC 消费其 `-grpc` |
| 服务名（客户端元数据服务） | `goodfish-client-meta-service` / `goodfish-client-meta-service-grpc` | 基础；账号 + 客户端版本（同一进程，两个 gRPC 服务） |
| 服务名（模型服务） | `goodfish-llm-service` / `goodfish-llm-service-grpc` | 基础（即 `backend/llm-manage`）；同上 |
| 服务名（后台 BFF） | `ruoyi-goodfish-admin` | 业务；仅后台跨域聚合读，无自有表 |
| 配置 Data ID | `goodfish-ai-service.yaml` | 每 namespace 一份，内容按环境调整 |
| Group | `DEFAULT_GROUP` | 统一默认 |
| Cluster | `DEFAULT` | 单机房默认；多机房部署再启用 |
| 实例 metadata | `{"protocol":"http"｜"grpc","secure":"false","cluster":"DEFAULT"}` | `protocol` 由 `-grpc` 后缀推导；**发现侧不据此过滤**（见 [技术方案-云端-对话服务-Nacos注册](技术方案-云端-对话服务-Nacos注册.md)） |

### 2.3 bootstrap 配置加载

**原则：本地 bootstrap 只描述"去哪拿配置"（Nacos 连接属性），业务配置全部放 Nacos。** 这样切换环境 = 换一组环境变量，代码与业务配置零改动。

```ini
# .env.dev（本地开发，不进 git）
APP_ENV=dev
NACOS_SERVER_ADDR=127.0.0.1:8848
NACOS_NAMESPACE_ID=dev
NACOS_GROUP=DEFAULT_GROUP
NACOS_USERNAME=dev-svc
NACOS_PASSWORD=******
NACOS_CACHE_DIR=./.nacos/cache/dev
NACOS_LOG_DIR=./.nacos/log
SERVER_HOST=0.0.0.0
SERVER_PORT=8000
```

```python
# app/bootstrap.py —— 引导配置：只含 Nacos 连接属性，不含业务配置
import os

from pydantic_settings import BaseSettings, SettingsConfigDict

APP_ENV_DEV = "dev"
APP_ENV_TEST = "test"
APP_ENV_PROD = "prod"


class BootstrapSettings(BaseSettings):
    model_config = SettingsConfigDict(
        # .env 在前、.env.{APP_ENV} 在后 → 后者覆盖前者；OS 环境变量优先级最高
        env_file=(".env", f".env.{os.getenv('APP_ENV', APP_ENV_DEV)}"),
        env_file_encoding="utf-8",
        extra="ignore",
    )

    app_env: str = APP_ENV_DEV
    nacos_server_addr: str = "127.0.0.1:8848"   # 8848 = SDK 端口；控制台（本项目 18080）不要填这里
    nacos_namespace_id: str = APP_ENV_DEV
    nacos_group: str = "DEFAULT_GROUP"
    nacos_data_id: str = "goodfish-ai-service.yaml"
    nacos_username: str = "nacos"
    nacos_password: str = ""
    nacos_log_level: str = "WARNING"
    nacos_cache_dir: str = "./.nacos/cache"     # 快照目录，Nacos 不可用时的降级来源
    nacos_log_dir: str = "./.nacos/log"
    nacos_context_path: str = ""                # Nacos 自定义 context-path 时填写
    nacos_register_ip: str = ""      # 留空则自动探测本机 IP；容器部署显式指定

    # 监听地址属于"部署属性"，放 bootstrap 而非远程配置，
    # 保证"注册端口 == 实际监听端口"，无需两段式启动
    server_host: str = "0.0.0.0"
    server_port: int = 8000     # 北向 REST（uvicorn）
    grpc_port: int = 9000       # 东西向 gRPC（grpc.aio）；本期不启动服务端，预留
    client_id: str = "goodfish-ai-service"   # 服务间调用标识 → gRPC metadata X-Client-Id（取服务名）


def load_bootstrap() -> BootstrapSettings:
    return BootstrapSettings()
```

### 2.4 配置中心内容（Data ID：`goodfish-ai-service.yaml`）

```yaml
# 数据库配置（各 namespace 下的值指向各环境的实例）
database:
  host: 127.0.0.1        # dev；test 环境为 test 库地址
  port: 5432
  user: postgres
  password: ${DB_PASSWORD}
  dbname: goodfish
  pool_size: 10
  max_overflow: 20

# Redis 配置
redis:
  host: 127.0.0.1
  port: 6379
  password: ${REDIS_PASSWORD}
  db: 0

# 大模型调用配置
llm:
  timeout_seconds: 30
  max_retries: 2
  retry_delay_seconds: 2

# 对话历史配置（v2.9：历史长期保留，不做过期清理）
conversation:
  max_history_messages: 20      # 送入大模型的最近消息条数（只影响上下文，不影响落库）

# 回复配置
reply:
  max_length: 50
  default_temperature: 0.7
  default_max_tokens: 2048

# 幂等控制（客户端重试时避免重复生成回复、重复落历史）
idempotency:
  ttl_seconds: 600               # request_id 结果缓存有效期（Redis）
  processing_ttl_seconds: 100    # 处理中占位 TTL（90s 最坏路径 + 10s 缓冲；必须 ≥ 最坏处理时长，否则占位提前过期会导致重试穿透）

# 图片存储（客户端上传 PNG → 服务器本地磁盘 → URL 给大模型与历史；本版本不上云存储、不用 ruoyi-file）
image:
  storage_dir: /data/goodfish/images     # 服务器本地磁盘目录
  public_base_url: https://<云端域名>/api/ai/image/view   # 对外访问基础 URL（经网关；大模型厂商拉取需公网可达）
  max_size_mb: 10                        # 单张上传体积上限（超过返回 40001）
  retention_hours: 72                    # 本地文件保留时长，过期由 tasks/cleanup.py 统一清理

# 意图识别（关键词词表，仅记日志统计，不参与提示词拼接；可热更新）
intent:
  keywords:
    price: ["便宜", "少点", "优惠", "砍价", "降价", "打折", "包邮吗"]
    tech: ["怎么用", "怎么安装", "参数", "型号", "支持", "配置", "教程"]
    chitchat: ["你好", "在吗", "哈哈", "干嘛", "无聊", "聊聊天"]

# 下游 gRPC 服务名（发现用；结构与《gRPC与Nacos服务发现技术方案.md》§4.5 一致）
grpc:
  discovery:
    services:                    # alias → Nacos 服务名（必须带 -grpc 后缀）
      item: goodfish-item-service-grpc
      llm: goodfish-llm-service-grpc
    debounce_ms: 1500            # 实例变更去抖（滚动发布会连推多次）
    close_grace_seconds: 30      # 旧 channel 延迟关闭，给在途 RPC 收尾
  channel:
    lb_policy: round_robin       # 交给 gRPC 内置策略，不自研轮询
    keepalive_time_ms: 30000
    max_message_mb: 16

# 下游业务调用参数（超时）——服务名不在这里重复定义
# 缓存不在本服务侧：商品/模型配置的缓存由提供方承担（TTL + 编辑时删除），本服务每次直接 gRPC 获取
downstream:
  item:
    timeout_seconds: 3
  llm:
    timeout_seconds: 3
```

> **注意**：`server.host` / `server.port` **不在远程配置里**，已上移到 bootstrap（见 §2.3）。原因：注册实例必须用"实际监听端口"，而端口必须在注册前就确定；放本地可保证两者天然一致，无需"先拉配置再起服务"的两段式启动。

**`${VAR}` 占位符说明**：v2 SDK 是纯 Python SDK，**不会**像 Spring 那样自动替换 `${VAR}`。ai-service 拉到配置后自行解析：敏感值优先从部署环境变量注入（数据库/Redis 密码不落 Nacos 明文也可行），未设置时保留 Nacos 中的原值。

### 2.5 `${VAR}` 占位符解析

```python
# app/utils/env_placeholder.py
import os
import re
from typing import Any

_PATTERN = re.compile(r"\$\{(?P<name>[A-Z0-9_]+)\}")


def _expand_scalar(value: str) -> str:
    """环境变量不存在时保留 ${VAR} 原样，便于启动时报错定位。"""
    return _PATTERN.sub(lambda m: os.environ.get(m.group("name"), m.group(0)), value)


def expand_placeholders(node: Any) -> Any:
    """递归展开**已解析**配置中的 ${VAR}。

    必须先 yaml.safe_load 再展开，而不是先对原始文本做正则替换：
    密码等值里可能含 `:`、`#`、`{`，先替换文本会破坏 YAML 结构。
    """
    if isinstance(node, dict):
        return {k: expand_placeholders(v) for k, v in node.items()}
    if isinstance(node, list):
        return [expand_placeholders(v) for v in node]
    if isinstance(node, str):
        return _expand_scalar(node)
    return node
```

### 2.6 热更新边界

| 类别 | 配置项 | 变更生效方式 |
|---|---|---|
| **可热更新**（监听回调直接生效） | llm 超时/重试、conversation 历史条数/过期时间、reply 长度/温度/tokens | 回调中原子替换运行时配置对象，下一个请求即生效 |
| **仅启动生效**（改后需重启） | database、redis 连接信息与连接池参数 | 回调中标记 `dirty` 并告警日志，提示运维重启；不做连接池重建（复杂度不匹配收益） |

> `server.host` / `server.port` 已移出远程配置（见 §2.3 说明），因此不存在"热更新端口"的问题。

**端口说明**：

- **8848** = Nacos **服务端/SDK 端口**（`NACOS_SERVER_ADDR` 填这个）
- **9848** = gRPC 端口（= 主端口 + 1000），v2 SDK 长连接走这个
- **18080** = Nacos 控制台端口（**本项目当前部署配置**；3.x 默认 8080。浏览器访问用，**SDK 不要填**）

防火墙/安全组需放行 **8848 + 9848**；控制台 18080 只在需要运维访问时开放。

### 6.2 Nacos 控制台准备清单（每环境执行一次）

1. **创建命名空间**：`dev`、`test`（prod 上线时同法）；创建时**手工指定命名空间 ID = 环境名**（默认会生成 UUID，与 bootstrap 配置对不上）
2. **创建配置**：在每个命名空间下创建 Data ID `goodfish-ai-service.yaml`、Group `DEFAULT_GROUP`，内容见 §2.4（数据库/Redis 地址按环境填各环境的实例）
3. **创建 SDK 账号**：每环境独立账号（`dev-svc` / `test-svc`），只授予对应命名空间读写权限（最小权限）
4. **网络放行**：应用部署机 → Nacos 的 **8848（SDK/HTTP）+ 9848（gRPC）**；控制台 **18080**（本项目配置，3.x 默认 8080）仅在运维需要时开放
5. **验证连通性**：用 `python -c "from v2.nacos import ClientConfigBuilder"` 确认 SDK 安装版本为 3.2.0，再启动服务观察是否注册成功
