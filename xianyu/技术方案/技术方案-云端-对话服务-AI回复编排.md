> 来源：[《客户端监听.md》](../客户端监听.md) §3.9 / §3.10 / §3.13、[《云端技术方案.md》](../云端技术方案.md) §5.1（内容重组收录，原文件保留未动）
> 关联：[技术方案-云端-商品服务](技术方案-云端-商品服务.md)、[技术方案-云端-模型服务](技术方案-云端-模型服务.md)、[需求-云端-AI对话回复](../需求/需求-云端-AI对话回复.md)

## 一、功能与职责（总）

### 1.1 功能定位

AI 回复生成是本服务的核心业务流程，采用**三段式**执行链路：

- **主干**：① 查询商品信息（gRPC） → ② 组装提示词（本地） → ③ 发送对话（HTTP，仅大模型 API）
- **协议约定**：除调用大模型 API（OpenAI 兼容 HTTP）外，**所有服务间调用一律 gRPC**
- **调用通道**：客户端**经网关转发**到本服务（不经 BFF）
- **随机延迟在客户端**：客户端在**发起本请求之前**已等待 1-2 秒，本服务不感知该延迟，收到请求即开始处理

《云端技术方案.md》§5.1 三段式执行链路图：

```
┌─── ① 查询商品信息（gRPC）───┐
│  ItemService.GetItemRuntimeConfig(account_id, item_id)
│  → 商品(title/desc/price/stock_status) + 提示词(system/price/tech/default + 3 参数)
└──────────────┬──────────────┘
               ▼
┌─── ② 组装提示词（本地）────┐
│  取/建对话 → 取历史 → 意图识别(仅记日志) → 变量替换 + 三段场景全嵌入
│  → messages = [system(含买家提问回填), ...history, (可选)user(仅图片)]
└──────────────┬──────────────┘
               ▼
┌─── ③ 发送对话 ────────────┐
│  LlmService.GetEnabledModel()（每次直接 RPC，模型服务提供方缓存加速）
│  → 调大模型（HTTP，OpenAI 兼容）
│  → 落库（对话消息 + Token + 回复日志）→ 写幂等 → 返回
└───────────────────────────┘
```

### 1.2 职责边界 / 范围

| 要点 | 说明 |
|---|---|
| **谁存提示词** | 商品服务（`goodfish-item-service`，`goodfish_item_prompt` 表）——提示词属于"商品内容"领域，与商品 1:1 强关联；本服务**不存商品、不存提示词配置、不存模型配置** |
| **谁渲染** | 本服务（对话服务）在本地完成变量替换与场景拼接，**商品服务只提供原始配置，不做任何渲染** |
| **怎么取** | gRPC `ItemService.GetItemRuntimeConfig` **一次拿全**（商品 + 提示词 + 参数），不拆成多次调用 |
| **怎么缓存** | **本服务（调用方）不做任何缓存、不做失效订阅**，每次对话直接 gRPC 获取（调用方无感）；缓存由**服务提供方**负责：**TTL 兜底 + 编辑时主动删除**——商品配置在商品服务（TTL 60s）、启用模型在模型服务（TTL 5min）。**不使用 Nacos 版本键，proto 不再携带任何 version 字段** |
| **内置模板** | **不建表**：内置模板放在商品服务的 **Spring 配置文件**（`goodfish-prompt-templates.yml`），只读；仅用于后台"从模板导入"到商品的 `goodfish_item_prompt`，**运行时链路不读取** |
| **提示词测试** | **本期不做**（`DialogService.TestPrompt` 已移除） |

### 1.3 与其他模块的关系

| 模块 | 关系 |
|---|---|
| 商品服务 | gRPC 下游：`ItemService.GetItemRuntimeConfig` 取商品 + 提示词运行时配置（见 [技术方案-云端-商品服务](技术方案-云端-商品服务.md)） |
| 模型服务 | gRPC 下游：`LlmService.GetEnabledModel` 取启用模型完整配置（见 [技术方案-云端-模型服务](技术方案-云端-模型服务.md)） |
| 大模型厂商 | HTTP 下游（唯一非 gRPC 外部依赖）：OpenAI 兼容 `/v1/chat/completions` |
| 客户端 | 经网关 `POST /api/ai/reply` 发起，请求/响应与幂等约定见 [技术方案-云端-对话服务-接口与幂等](技术方案-云端-对话服务-接口与幂等.md) |
| 图片链路 | 图片由客户端预先上传（`POST /api/ai/image`），本流程只做校验（见 [技术方案-云端-对话服务-接口与幂等](技术方案-云端-对话服务-接口与幂等.md)） |

## 二、逻辑实现（分）

### 2.1 总体设计

服务划分与 gRPC 契约见 [《云端技术方案.md》](../云端技术方案.md)§三、§六。回复编排在 `app/services/reply_service.py`（三段式主干），提示词渲染在 `prompt_service.py` / `prompt_builder.py`，意图识别在 `intent_service.py`，下游客户端在 `item_client.py` / `model_client.py` / `llm_client.py`（见 [技术方案-云端-对话服务-框架与生命周期](技术方案-云端-对话服务-框架与生命周期.md) §2.4 目录结构）。

### 2.2 三段式执行流程（完整链路）

```
1. 客户端 POST /api/ai/reply（REST，经网关路由到本服务实例）
       ↓
2. 参数校验（request_id、goodfish_item_id、buyer_id、message 非空）
   缺失 → 40001
       ↓
3. 幂等检查（Redis：ai:idem:{request_id}）
   ├ 命中结果 → 直接返回缓存响应（不落库、不计 Token），流程结束
   ├ 处理中（占位无结果）→ 返回 50301，客户端退避重试
   └ 未命中 → SET NX 占位（TTL = processing_ttl_seconds，默认 100s），继续
       ↓
───────── ① 查询商品信息 ─────────
4. 【gRPC】ItemService.GetItemRuntimeConfig
      请求：{ account_id, item_id }
      响应：ItemRuntimeConfig
            - 商品：title / description / price / stock_status / image_url
            - 提示词：system_prompt / price_prompt / tech_prompt / default_prompt
            - 参数：max_reply_length（温度 / max_tokens 不在此，随启用模型取）
      （本服务无缓存，每次直接 RPC；商品服务提供方 Redis 缓存：编辑/同步时删除 + TTL 60s 兜底，见 §2.3）
   ├ NOT_FOUND          → 返回 40401（客户端不回复）
   ├ system_prompt 为空  → 返回 40402（商品未配置提示词，不调大模型，客户端不回复）
   ├ DEADLINE_EXCEEDED  → 重试 1 次 → 仍失败返回 50301
   └ UNAVAILABLE        → 返回 50301
       ↓
───────── ② 组装提示词 ─────────
5. 【本地】获取或创建对话（conversation_id = item_id + buyer_id）
6. 【本地】获取对话历史（最近 N 条，默认 20）——上下文全部由本服务维护，客户端不传历史
7. 【本地】意图识别（关键词词表，仅用于日志统计，不参与提示词拼接）
   命中 price / tech / chitchat 关键词 → 记 intent；否则 default
   词表放配置中心（intent.keywords.*），可热更新
8. 【本地】渲染统一系统提示词（三段场景提示词全部嵌入，不做三选一）
   变量替换：{{item_title}} {{item_desc}} {{item_price}} {{max_reply_length}}
   买家提问回填：{{question}} → 本批买家消息，模板末尾以
     「基于上述 回复买家：问题如下{{question}}」形式回填（见 §2.7.3）
   场景提示词 {{price_prompt}} / {{tech_prompt}} / {{default_prompt}} 三段全部嵌入模板，
   由模型按「场景处理指南」自行对号入座；闲聊引导规则见 §2.7
       ↓
───────── ③ 发送对话 ─────────
9. 【本地】图片校验（图片已由客户端预先上传至本服务本地磁盘，此处只做校验）
   对请求中的 image_url（多图时为数组）逐项：
   a. 解析 URL 中的文件名 → 检查 image.storage_dir 下文件存在且未过期
   b. 文件缺失 / 已被清理 → 该图降级为占位文本 "[图片]"，记 WARN，不阻断流程
   （图片的下载与上传均在客户端完成：闲鱼图片 → 客户端转 PNG → POST /api/ai/image → 本地磁盘 → URL）
10.【gRPC】LlmService.GetEnabledModel（每次直接 RPC；模型服务提供方 Redis 缓存：启用/编辑时删除 + TTL 5min 兜底，见 §2.6）
    响应：base_url / model_name / api_key(明文) / temperature / max_tokens
    ├ NOT_FOUND（无启用模型）→ 返回 50002（不调大模型，客户端不回复、不重试）
    └ 超时 / UNAVAILABLE → 50301
11.【本地】温度 / max_tokens 直接取启用模型的配置（模型表），商品提示词不参与
12.【本地】构建 messages（OpenAI 多模态格式）：
    messages = [
      {"role":"system","content":"<渲染后的统一系统提示词，末尾含『基于上述 回复买家：问题如下<本批买家消息>』>"},
      ...history（历史轮次；历史图片消息用已转存的 URL，同一 URL 复用不再转存）
    ]
    ★ 买家提问已回填进 system 提示词，不再单列一条 user 文本消息；
      若本批含图片：追加一条 user 消息只承载图片（文本已在 system 中）
      {"role":"user","content":[{"type":"image_url","image_url":{"url":"<转存后URL>"}}, ...]}
13. 调用大模型（HTTP，OpenAI 兼容 /v1/chat/completions）
    单次超时 30s；按剩余预算决定是否重试，总预算 ≤ 65s；超预算 → 50001
       ↓
14. 落库（同一事务）
    - ai_conversation_message：本条 buyer 消息（文本 / 图片存本服务图片 URL，不存 base64）+ assistant 回复（含 Token / latency）
    - ai_conversation：更新 last_message_at
    - ai_reply_log：渲染后系统提示词 + intent + 模型 + 回复 + 耗时（排障用）
       ↓
15. 写幂等结果（Redis，TTL = idempotency.ttl_seconds）
       ↓
16. 返回 AI 回复内容（reply / conversation_id / model_name / latency_ms）
```

**异常路径**：第 2 步之后任一步失败，**必须 DEL 幂等占位**，否则客户端重试会被"处理中"卡到 TTL 到期。

**gRPC 状态码 → 业务错误码映射**（与 [《云端技术方案.md》](../云端技术方案.md)§6.5 一致）：

| gRPC Status | 业务错误码 | 客户端处理 |
|---|---|---|
| `OK` | 0 | 发送回复 |
| `UNAUTHENTICATED` | 40101 | **删 token + 跳登录页**（A27） |
| `PERMISSION_DENIED` | 40301 | **停止监听 + 冻结应用**（A42） |
| `NOT_FOUND`（商品服务） | 40401 | 不回复（A30） |
| `NOT_FOUND`（模型服务，无启用模型） | 50002 | 不回复、不重试，记日志（云端配置错误，管理端需启用模型） |
| `INVALID_ARGUMENT` | 40001 | 不回复，记日志（属客户端 Bug） |
| `DEADLINE_EXCEEDED` | 50301 | 重试 3 次，仍失败进入"仅监听不回复"（A21） |
| `UNAVAILABLE` | 50301 | 同上 |
| 其他 | 50001 | 不回复（TODO：降级策略） |

**超时预算**：客户端 90s > 网关 75s > 本服务最坏路径 65s，逐层收窄，避免网关先超时而下游仍在跑引发重试风暴。

> **对话历史生命周期**：**长期保留，不做过期清理**——完整对话是排障（与 `ai_reply_log` 对照）及后续分析、导出的基础数据。故不设 `conversation.expire_hours`，也没有"每小时扫 `ai_conversation.last_message_at` 删过期记录"的定时任务。**图片文件同样长期保留**：与对话历史同生命周期，已取消 `image.retention_hours` 与 `tasks/cleanup.py`，保证历史回放时图片 URL 始终可用。

### 2.3 第①段：查询商品信息（gRPC）

- 调用 `ItemService.GetItemRuntimeConfig`（请求 `{account_id, item_id}`），一次拿全商品信息、四段提示词与生成参数（见 §2.2 第 4 步）。
- **缓存策略**：本服务**不缓存**（无 L1/L2，无失效订阅），每次对话直接 gRPC 获取；缓存由商品服务在**提供方侧**承担，**介质为 Redis（共享缓存）**——**编辑/同步变更时主动删除 + TTL 60s 兜底**（多实例共用同一 Redis，删除即全局生效，TTL 仅兜底）。**不使用 Nacos 版本键**。
- **分支**：`NOT_FOUND` → 40401（客户端不回复）；`system_prompt` 为空 → 40402（商品未配置提示词，**不调用大模型**，客户端不回复）；`DEADLINE_EXCEEDED` → 重试 1 次仍失败返回 50301；`UNAVAILABLE` → 50301。

### 2.4 第②段：组装提示词（本地）

按顺序完成四件事（见 §2.2 第 5-8 步）：

1. **获取或创建对话**：`conversation_id = goodfish_item_id + buyer_id`（口径详见 [技术方案-云端-对话服务-存储设计](技术方案-云端-对话服务-存储设计.md)）。
2. **获取对话历史**：最近 `conversation.max_history_messages`（默认 **20**）条；上下文全部由本服务维护，客户端不传历史。
3. **意图识别**：关键词词表（`intent.keywords.price/tech/chitchat`）命中则记 intent，否则 `default`；**仅记日志统计（落 `ai_reply_log.intent`），不参与提示词拼接**；词表放配置中心，可热更新。
4. **渲染统一系统提示词**：变量替换（含 **`{{question}}` 回填本批买家消息**）+ 三段场景提示词全部嵌入模板（详见 §2.7）。

### 2.5 图片处理（第 9 步）

- 图片已由客户端预先下载并上传至本服务本地磁盘（下载 → 转 PNG → `POST /api/ai/image` → 本地磁盘 → URL，链路详见 [技术方案-云端-对话服务-接口与幂等](技术方案-云端-对话服务-接口与幂等.md)）。
- 本流程**只做校验**：对请求中的 `image_url`（多图时为数组）逐项解析 URL 中的文件名 → 检查 `image.storage_dir` 下文件存在且未过期。
- 文件缺失 / 已被清理 → 该图降级为占位文本 `"[图片]"`，记 WARN，**不阻断流程**。
- 构建 messages 时（第 12 步）：历史图片消息用已转存的 URL，**同一 URL 复用不再转存**；对大模型以 OpenAI 多模态格式 `{"type":"image_url","image_url":{"url":...}}` 传递。

### 2.6 第③段：发送对话（与模型服务的交互）

获取启用模型后调用大模型（第 10-13 步）；`temperature` / `max_tokens` **全部取自启用模型（模型表）**，商品提示词不参与模型参数设定。

**与模型服务的 gRPC 交互**：调用地址由 Nacos 服务发现给出——订阅 `goodfish-llm-service-grpc` 的健康实例，装配为 `ipv4:` 多地址 target，由 gRPC 内置 `round_robin` 完成负载均衡（见 [技术方案-云端-gRPC发现库xxs-nacos-grpc-已实现](技术方案-云端-gRPC发现库xxs-nacos-grpc-已实现.md)）。

| 调用场景 | gRPC 方法 | 说明 |
|---|---|---|
| 获取启用模型（主用） | `LlmService.GetEnabledModel` | 返回 `base_url` / `model_name` / `api_key`(明文) / `temperature` / `max_tokens` |
| Token 用量回传（可选） | `LlmService.ReportUsage` | 成本核算用；本期 Token 统计以对话服务本地落库为准 |

**三个要点**：

1. **本服务不缓存，每次对话直接调用**——缓存由模型服务在**提供方侧**承担，**介质为 Redis（共享缓存）**：**启用/编辑时主动删除 + TTL 5min 兜底**（删除即全局生效）。**不使用 Nacos 版本键**；契约已无 `known_version` / `config_version` 参数（`config_version` 仅保留在 `llm_model` 表作排障快照）。
2. **明文 API Key 仅在内网 gRPC 通道传输**；`api_key` 一律**不进日志、不进异常栈**。
3. **契约定义**见 [技术方案-云端-gRPC契约-已实现](技术方案-云端-gRPC契约-已实现.md)。模型服务由 `backend/llm-manage`（Go/Kratos，原生支持 gRPC）承载，需放开其 **gRPC 端口的注册**。

> 服务间获取启用模型**不提供 HTTP 内部接口**，统一走 gRPC。商品服务与模型服务共用同一套发现实现 `GrpcChannelRegistry`：按 `downstream.<alias>.service_name` 分别为两个 `-grpc` 服务名装配 channel，**不按 `metadata.protocol` 过滤**。

**大模型调用**：HTTP、OpenAI 兼容 `/v1/chat/completions`，单次超时 30s；按剩余预算决定是否重试，总预算 ≤ 65s；超预算 → 50001。`llm.timeout_seconds=30` / `max_retries=2` / `retry_delay_seconds=2` 见 [技术方案-云端-对话服务-多环境与配置中心](技术方案-云端-对话服务-多环境与配置中心.md) §2.4。

### 2.7 提示词管理设计

#### 2.7.1 提示词结构（每个商品单独一套）

```
商品提示词配置
├── 系统提示词（全局人设 + 核心原则）
├── 场景提示词
│   ├── 议价场景（用户明确要求降价/优惠/砍价）
│   ├── 技术场景（用户询问产品功能/使用问题）
│   └── 默认场景（其他一般咨询：物流/售后/商品介绍）
└── 最大回复字数（默认 50 字）
```

该结构落地为**商品服务的 `goodfish_item_prompt` 表**（与 `goodfish_item` 一对一），字段定义见 [《云端技术方案.md》](../云端技术方案.md)§7.2；存储/渲染/失效职责划分见 §1.2。

> **本期范围**：商品编辑页只填**系统提示词 + 最大回复字数**；议价 / 技术 / 默认三个场景提示词字段**留空**，页面不提供输入（后续迭代补齐，见《需求-云端-商品管理》第六节）。渲染时留空字段按空串处理，不影响主链路。
>
> **温度 / max_tokens 不在这里**：它们是**大模型配置**，随启用模型（`LlmService.GetEnabledModel`）一起取用，不属于商品提示词（见 [技术方案-云端-模型服务](技术方案-云端-模型服务.md)）。

#### 2.7.2 提示词变量（构建时动态替换）

只保留**有真实数据来源**的变量：`{{buyer_nickname}}`（请求体不含、本服务无买家资料表）、`{{bargain_count}}`（议价功能本期不做）、`{{history}}`（历史经 messages 数组注入，不内联到 system 提示词）均已删除。

| 变量 | 说明 |
|---|---|
| `{{item_title}}` | 商品标题 |
