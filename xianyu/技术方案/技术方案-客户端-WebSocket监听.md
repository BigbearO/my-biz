## 一、功能与职责（总）

### 1.1 功能定位

XianyuLive / websocket_manager（`services/listen_manager.py` + `xianyu/session.py`）负责多账号闲鱼 WebSocket 连接的建立、保活、状态管理与断线重连：**维护多账号连接池，每个监听账号一个独立 WebSocket 连接实例**，收到消息后交给消息处理流水线（见 [技术方案-客户端-消息处理流水线](技术方案-客户端-消息处理流水线.md)）。

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| 每账号一个 `XianyuLive` 实例与独立 WS 连接 | WS 帧的协议编解码（协议层，见 [技术方案-客户端-闲鱼协议层](技术方案-客户端-闲鱼协议层.md)） |
| 连接状态机维护（显式状态迁移，禁止布尔标志堆砌）与状态落库（`listen_state`，渲染层轮询） | 消息的业务处理（去重、窗口合并、AI 请求，见 [技术方案-客户端-消息处理流水线](技术方案-客户端-消息处理流水线.md)） |
| 断线重连（token 失效自愈 + 外层重连计数 5s/10s/15s ×3） | 监听上限配置值的存储（SQLite config 表，见 [技术方案-客户端-本地存储与配置](技术方案-客户端-本地存储与配置.md)） |
| 监听上限统一校验（ListenManager，禁止各调用方自行判断） | Cookie 加密/解密（见 [技术方案-客户端-Cookie管理与加密](技术方案-客户端-Cookie管理与加密.md)） |
| 心跳保活与心跳超时断线判定 | 云端 AI 调用与回复发送（流水线下游环节） |

### 1.3 与其他模块的关系

| 对象 | 方向 | 交互方式 |
|---|---|---|
| 闲鱼协议层（`xianyu/session.py`） | 下游 | WS 长连接、心跳、下行 ACK、token 失效自愈均由复用实现承担 |
| 消息处理流水线 | 下游 | 收到消息回调 → 交给 pipeline 处理 |
| Cookie 管理 | 上游 | 建连/重连取解密后的 Cookie；失效检测回写账号状态 |
| 状态落库 | 下游 | 连接状态变更写 `goodfish_account.listen_state`，渲染层经 `/api/account/list` 轮询（见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md)） |
| 本地 API（start-listen / stop-listen / stop-all） | 上游 | 用户启停入口，经 ListenManager 编排 |

## 二、逻辑实现（分）

### 2.1 总体设计

- **多账号连接**：每个监听账号一个 `XianyuLive` 实例，独立 WebSocket 连接，整体构成连接池；
- **消息回调**：收到消息后交给消息处理流水线（`message_pipeline`）处理；
- **断线重连**：复用实现内置 token 失效自愈重连，其上再补外层重连计数（详见 §2.2）；
- **状态可见**：连接状态显式状态机化，变更写 `listen_state` 落库，渲染层轮询获取。

### 2.2 连接管理方案

| 功能 | 方案 |
|---|---|
| **多账号连接** | 每个监听账号一个 `XianyuLive` 实例，独立 WebSocket 连接 |
| **最大监听数** | 默认 3 个，本地配置项可改（SQLite 配置表）；由 `ListenManager` 统一校验，禁止各调用方自行判断 |
| **★云端监听占用** | 「开始监听」前经 cloud_client 申请云端账号级租约（`acquire`），监听期间每 30s `renew`，停止监听 / 退出应用时 `release`；被其他设备占用（`409`）→ 拒绝启动；**接口不可用 → 降级放行**（记 WARN）。编排统一放 `ListenManager`，见 [技术方案-云端-客户端元数据服务](技术方案-云端-客户端元数据服务.md) §2.4 |
| **连接状态** | 显式状态机（见 §2.3），**禁止用多个布尔标志表达状态**；变更写 `listen_state` 落库，渲染层轮询 |
| **断线重连** | 复用实现已内置**token 失效自愈重连**（`code=400` 触发，连接代次 + 互斥锁做并发去重）；在其之上补一层**外层重连计数**：5s/10s/15s 最多 3 次，3 次失败 → 标记 `disconnected`（对齐需求 A17）。用户可手动"重新开始监听"重置计数 |
| **错误分类** | 网络类（可重连）／凭证类（立即停听 + 标记失效）／风控类（停听 + 长退避 + 告警）——三类走不同分支，不能一律重连 |
| **心跳保活** | 每 **15s** 发送应用层心跳 `{"lwp":"/!"}`（已裁定统一节奏）；断线由 WS 连接异常 / 接收异常触发重连分支，不依赖固定超时判定 |
| **Cookie 失效检测** | 收到闲鱼服务端失效消息 / 请求返回 401 → 停止监听 + 标记失效 + 弹窗提示 |
| **启动失败处理** | Python exe 启动失败由 Electron 重试 2 次（间隔 2s），仍失败弹窗提示"本地服务启动失败，请联系管理员"（详见 [技术方案-客户端-本地服务进程管理](技术方案-客户端-本地服务进程管理.md)） |
| **退出处理** | 先停止所有监听，再退出进程（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.4 优雅关闭） |
| **重启恢复** | 重启后不自动恢复监听，需手动启动（对齐需求 A25） |

> 心跳节奏已统一裁定：**应用层每 15s 发 `{"lwp":"/!"}`**；不依赖 aiohttp 库层心跳，断线以连接异常/接收异常感知（协议层细节见 [技术方案-客户端-闲鱼协议层](技术方案-客户端-闲鱼协议层.md) §2.3）。

### 2.3 账号状态机

状态机在 `core/state.py` 定义，**DB 与 UI 都以此为准**：

| 状态 | 含义 | 可迁移到 |
|---|---|---|
| `idle` | 未监听（DB 默认值；用户停止监听后回到此状态） | `connecting` |
| `connecting` | 建连中 / 鉴权中 | `online` / `invalid` / `backoff` |
| `online` | 已连接，正常收发 | `backoff` / `invalid` / `idle` |
| `backoff` | 断线退避中（记录重试次数） | `connecting` / `disconnected` |
| `invalid` | Cookie 失效（凭证类错误） | `idle` |
| `disconnected` | 重试 3 次仍失败，已停止重连 | `connecting`（用户手动重置）/ `idle` |

> 任意状态在用户点击「停止监听」时直接回到 `idle`；状态只允许通过状态机迁移函数修改，禁止各处直接写 DB 字段。

```
状态迁移图
idle ──开始监听──▶ connecting ──握手成功──▶ online
                        │                     │
                        ├─凭证类错误─▶ invalid └─网络断开─▶ backoff
                        └─网络类错误─▶ backoff          │
                                                       ├─重试成功─▶ connecting
                                                       └─重试≥3次─▶ disconnected
用户停止监听（任意状态）────────────────────────────────▶ idle
```

状态字段落库为 `goodfish_account.listen_state`（见 [技术方案-客户端-本地存储与配置](技术方案-客户端-本地存储与配置.md) §三）。

## 五、异常与容错

| 异常场景 | 处理策略 |
|---|---|
| **WebSocket 断线** | 重连 3 次（5s/10s/15s），仍失败标记"连接断开"（`disconnected`，A17）；用户可手动"重新开始监听"重置计数 |
| **网络类错误** | 可重连，走 backoff → connecting 分支 |
| **凭证类错误** | 立即停听 + 标记 `invalid` + 弹窗提示 |
| **风控类错误** | 停听 + 长退避 + 告警 |
| **token 失效（code=400）** | 复用实现自动重连并换 token（连接代次 + 互斥锁保证并发只重连一次）；外层记一次重连计数 |
| **IM 流控（400600001）** | 复用实现自动退避 `(n+1)*2` 秒、最多 3 次；连续失败则上报状态并延长退避 |
| **Cookie 失效** | 停止监听 + 标记失效 + 弹窗提示，不提供重新输入（见 [技术方案-客户端-Cookie管理与加密](技术方案-客户端-Cookie管理与加密.md)） |
| **重启后** | 不自动恢复监听（A25） |

> 客户端完整异常场景总表见 [技术方案-客户端-云端调用与容错](技术方案-客户端-云端调用与容错.md) §五。
