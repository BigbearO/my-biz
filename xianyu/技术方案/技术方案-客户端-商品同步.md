> 关联：[需求-客户端-商品同步](../需求/需求-客户端-商品同步.md)

## 一、功能与职责（总）

### 1.1 功能定位

ItemSyncer（`services/item_sync_service.py`）负责把用户闲鱼账号下的商品**手动全量同步**到云端：调闲鱼接口全量拉取 → 上报云端，**只增不删**（删除由用户在云端操作）。为云端 AI 回复提供商品上下文（商品不存在时云端返回 40401 不回复）。

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| 手动触发的全量商品拉取（闲鱼协议 `fetch_items`） | 商品数据的云端存储与展示（云端商品服务，见 [技术方案-云端-商品服务](技术方案-云端-商品服务.md)） |
| 商品上报云端（只增不删） | 自动定时同步（TODO，本期不做） |
| 异步执行与同步状态查询接口 | 断点续传（失败即整批重来） |
| 重复触发的防抖（按钮置灰 + 服务端 409） | 商品列表协议签名实现（协议层开放项，见 [技术方案-客户端-闲鱼协议层](技术方案-客户端-闲鱼协议层.md) §2.4） |

### 1.3 与其他模块的关系

| 对象 | 方向 | 交互方式 |
|---|---|---|
| Electron 渲染层（商品同步按钮） | 上游 | 触发 `/api/sync/items/{account_id}`，轮询 `/api/sync/status/{account_id}` 获取进度 |
| 闲鱼协议层 | 下游 | `fetch_items` 全量拉取商品列表（mtop 类 HTTP 接口） |
| 云端客户端（cloud_client） | 下游 | 商品数据上报云端（带 token、走统一重试） |
| 本地 API（sync/status） | 下游 | 同步状态与结果落库，经 `/api/sync/status/{account_id}` 供渲染层轮询 |
| 云端商品服务 | 下游 | 上报落地（新增 X / 更新 X），删除只在云端操作 |

## 二、逻辑实现（分）

### 2.1 总体设计

```
用户点击"同步"按钮（按钮置灰防重复点击）
    ↓
POST /api/sync/items/{account_id}（异步执行，重复触发返回 409）
    ↓
后台调闲鱼接口全量拉取商品列表
    ↓
上报云端（只增不删；删除由用户在云端操作）
    ↓
完成 → toast 提示"同步完成，新增 X 个，更新 X 个"（A33）
       失败 → toast 提示"同步失败，请重试"（A37）
```

### 2.2 同步方案

| 功能 | 方案 |
|---|---|
| **触发方式** | 手动点击"同步"按钮，按钮置灰防重复点击 |
| **同步策略** | 调闲鱼接口全量拉取 → 上报云端，**只增不删**（删除由用户在云端操作） |
| **异步执行** | 后台异步同步不阻塞界面，完成后 toast 提示"同步完成，新增 X 个，更新 X 个"（A33） |
| **失败处理** | toast 提示"同步失败，请重试"，下次点击重新全量拉取，不做断点续传（A37） |
| **自动同步** | TODO，暂时不做（见 §七） |

> 协议依赖：`fetch_items`（mtop 类 HTTP 接口）的签名实现未在复用仓库定位到，开发第 1 步必须确认；不可用则退路为改用会话推送中携带的 `itemId` 增量沉淀商品数据（见 [技术方案-客户端-闲鱼协议层](技术方案-客户端-闲鱼协议层.md) §2.4）。

## 四、接口设计

基础地址：`http://127.0.0.1:{port}/api`（端口协商与 `X-Local-Token` 见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md)）。

| 接口 | 方法 | 说明 |
|------|------|------|
| /api/sync/items/{account_id} | POST | 同步商品（异步） |
| /api/sync/status/{account_id} | GET | 获取同步状态 |

监听方案补充约定：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/sync/items/{account_id}` | POST | 触发全量同步（异步，重复点击返回 409） |
| `/api/sync/status/{account_id}` | GET | 同步状态与结果（新增 X / 更新 X） |

同步进度与结果经 `/api/sync/status/{account_id}` 供渲染层轮询获取（见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md) §2.3）。

## 五、异常与容错

| 异常场景 | 处理策略 |
|---|---|
| **同步失败** | toast 提示"同步失败，请重试"；下次点击重新全量拉取，不做断点续传（A37） |
| **重复触发** | 按钮置灰防重复点击；服务端重复触发返回 409 |
| **商品列表接口不可用** | `fetch_items` 签名实现待核实（协议层开发第 1 步）；退路为会话推送 `itemId` 增量沉淀 |
| **云端上报失败** | 走 cloud_client 统一重试（3 次，2-3s 随机），见 [技术方案-客户端-云端调用与容错](技术方案-客户端-云端调用与容错.md) |
| **云端返回账号不存在（账号未上报成功）** | 同步失败：toast 提示"同步失败"；云端不做部分落库。该账号需先上报云端成功（网络恢复后重新添加账号触发上报）再同步 |
