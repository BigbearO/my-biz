> 来源：《云端技术方案.md》§5.2 管理后台服务 `ruoyi-goodfish-admin`、§8.3.1 经 `ruoyi-goodfish-admin`（跨域聚合）（内容重组收录，原文件保留未动）
> 关联：[技术方案-云端-架构总览](技术方案-云端-架构总览.md)、[技术方案-云端-管理后台前端](技术方案-云端-管理后台前端.md)

## 一、功能与职责（总）

### 1.1 功能定位

管理后台服务 `ruoyi-goodfish-admin` 即原 `ruoyi-goodfish` 模块，**降级为后台 BFF**：为 plus-ui 提供页面接口，数据全部通过 gRPC 从基础服务获取。

### 1.2 职责边界 / 范围

| 项 | 内容 |
|---|---|
| **职责** | 为 plus-ui 提供页面接口，数据全部通过 gRPC 从基础服务获取（跨域聚合读） |
| **拥有表** | **无**（无自有表） |
| **保留** | RuoYi 的登录鉴权、菜单权限、操作日志 |
| **不承担** | 模型/供应商管理的**透传**——plus-ui 直连模型服务（§3.5 裁定，见《技术方案-云端-架构总览》） |

### 1.3 与其他模块的关系

- **下游（gRPC 调用）**：客户端元数据服务（账号数、账号名/昵称、版本发布）、商品服务（商品数、商品列表、提示词复制）。
- **上游（REST 服务对象）**：plus-ui 管理后台前端，仅仪表盘与商品列表两类跨域聚合接口走本服务，其余页面接口直连各基础服务。
- 基础鉴权能力复用 RuoYi 网关统一 token 校验。

## 二、逻辑实现（分）

### 2.1 总体设计

管理后台接口按 §3.5 规则拆分：**跨域聚合读走 admin BFF，单域 CRUD 直连基础服务。**

admin BFF 的编排场景（数据全部通过 gRPC 从基础服务获取）：

| 编排场景 | 数据来源 |
|---|---|
| ① 仪表盘统计 | 账号数（客户端元数据服务）＋ 商品数（商品服务） |
| ② 商品列表 | 商品服务 + 客户端元数据服务（拼账号名、账号昵称） |
| ③ 提示词复制到其他商品 | 商品服务（保持"复制后独立编辑"语义） |
| ④ 版本发布 | 客户端元数据服务（安装包上传存本地磁盘，见《技术方案-云端-文件存储》） |
| ⑤ **删除账号** | 商品服务（`/goodfish/item/count` 按账号统计商品数）→ 客户端元数据服务（删除账号）。**两步非事务、最终一致**：仍有商品 → 拒绝删除；无商品 → 删除账号记录，**不级联删除商品**（见 [技术方案-云端-商品服务](技术方案-云端-商品服务.md)、[技术方案-云端-客户端元数据服务](技术方案-云端-客户端元数据服务.md)） |

### 2.2 为什么不设客户端 BFF

不单独设置面向客户端的 BFF（原方案曾计划 `goodfish-client-bff`，已取消），理由：

| 论点 | 说明 |
|---|---|
| 客户端场景几乎全是单域 | AI 回复、账号上报、商品同步、版本检查、授权校验，每个都只落在一个服务上，**BFF 只能做透传** |
| 透传是净负债 | 多一跳延迟 + 多一个故障点 + 多一套部署，却没有任何聚合收益 |
| 启动初始化不值得 | "授权 + 账号 + 版本"用 3 个并发请求即可，成本远低于维护常驻服务 |
| 客户端只多记几个前缀 | 用统一前缀族解决：`/api/ai/**`、`/goodfish/item/**`、`/goodfish/meta/**`、`/goodfish/llm/**`，封装在客户端一个 `CloudClient` 里，对 UI 无感 |

> 若后续真的出现"客户端需要一次拿到多域聚合数据"的场景，再按 §3.5 规则单独引入 BFF，届时不改动任何基础服务。

## 四、接口设计

经 `ruoyi-goodfish-admin` 的接口仅覆盖**跨域聚合**场景：

| 接口 | 方法 | 聚合来源 |
|------|------|---------|
| `/goodfish/admin/dashboard/stats` | GET | 客户端元数据服务（账号数）＋ 商品服务（商品数） |
| `/goodfish/admin/item/list` | GET | 商品服务 ＋ 客户端元数据服务（拼账号名/昵称） |
| `/goodfish/admin/account/{id}` | DELETE | 商品服务（统计商品数校验）＋ 客户端元数据服务（删除账号）；有商品则拒绝 |

其余管理后台接口（商品、账号、版本、模型）均为前端直连基础服务，不属于本服务；完整接口拆分与前端前缀归属见《[技术方案-云端-管理后台前端](技术方案-云端-管理后台前端.md)》。
