## 一、功能与职责（总）

### 1.1 功能定位

客户端元数据服务 `goodfish-client-meta-service` 是基础微服务，管理闲鱼账号元数据与客户端版本两个领域的数据。

**一个部署单元，两个 gRPC 服务**：契约按领域拆（`AccountService` 账号域、`VersionService` 版本域各自独立 proto 契约），部署按成本合（两个 gRPC 服务合并为一个进程部署）。架构层面的说明见 [技术方案-云端-架构总览](技术方案-云端-架构总览.md)。

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| ① 闲鱼账号信息 upsert（客户端上报） | **绝不存储 Cookie**（A10） |
| ② 账号列表/详情查询、备注修改、最后活跃时间维护 | 不做登录鉴权 |
| ③ 客户端版本发布（版本号、更新说明、强升标记、安装包地址与大小） | 不做授权判定（由 `ruoyi-system` 负责，见 [技术方案-云端-鉴权与授权](技术方案-云端-鉴权与授权.md)） |
| ④ 更新检查 | |

### 1.3 与其他模块的关系

| 对象 | 方向 | 协议/说明 |
|---|---|---|
| 客户端 | 被其调用 | REST 直连（经网关）：账号上报 `/goodfish/meta/account/report`、更新检查 `/goodfish/meta/version/check`、安装包下载（**自定义请求头携带登录 token**，见 2.3）；gRPC `UpsertAccount` / `CheckUpdate` 契约保留 |
| 管理后台（plus-ui） | 被其调用 | REST 直连：`/goodfish/meta/account/**`、`/goodfish/meta/version/**` |
| 商品服务 | 被其调用 | gRPC：`GetAccountByGoodfishId`（商品同步时解析 `account_id`，见 [技术方案-云端-商品服务](技术方案-云端-商品服务.md)） |
| 文件存储 | 提供 | 安装包存服务器本地磁盘，由本服务提供上传/下载（见 [技术方案-云端-文件存储](技术方案-云端-文件存储.md)） |

## 二、逻辑实现（分）

### 2.1 总体设计

一个部署单元承载账号域与版本域两个 gRPC 服务（契约按领域拆、部署按成本合，见 1.1）；北向 REST 面向管理后台与客户端直连。账号域按 `goodfish_id` 维护账号元数据，版本域按版本号维护客户端发布记录。

### 2.2 账号域关键逻辑

- 客户端**添加账号本地验证通过后**经 REST `/goodfish/meta/account/report` 上报：携带 `goodfish_id`、`goodfish_nickname`、`remark`，**不接收 Cookie**（A10）——上报成功是客户端本地入库与后续商品同步（`GetAccountByGoodfishId` 解析）的前置条件；
- 账号按 `goodfish_id` upsert（已有则更新昵称/备注）；
- **★账号只停用、不删除**：`status` = `normal` / `disabled`；停用由管理后台发起，**不校验商品数、不级联删商品**；
- **停用后的效果**：`GetAccountByGoodfishId` 仍正常返回账号（已同步商品与 AI 回复链路不受影响），但**商品同步入口拒绝该账号的同步请求**（商品服务返回 `40404`）；
- **上报不复活停用**：客户端重新上报（upsert）只更新昵称/备注，**不修改 `status`**——停用与否由管理员控制；
- **不维护"是否有效"**：cookie 有效性只在本地维护，云端不记录、不展示；
- 最后活跃时间由本服务维护。

### 2.3 版本域关键逻辑

- 强升版本无「以后再说」（A15）；
- **★「最新版本」判定口径**：按 **发布时间倒序 → 版本号倒序** 排序后取第一条。**不考虑回滚场景**（发布为深思熟虑的操作；若确出现回滚需求再单独设计）；
- **★安装包完整性校验**：上传安装包时由服务端计算 **SHA-512** 并随版本记录（`client_version.sha512`）；检查更新接口一并返回，客户端下载后比对，不一致则拒绝安装（见 [需求-客户端-设置与自动升级](../../需求/需求-客户端-设置与自动升级.md)）；
- 安装包存服务器本地磁盘，由本服务提供上传/下载；
- 安装包下载**需鉴权**：下载接口不加入网关白名单，客户端 electron-updater 经自定义请求头携带登录 token（见 [技术方案-云端-文件存储](技术方案-云端-文件存储.md) §2.3）。

### 2.4 监听占用（跨设备分布式竞态校验）★

**问题**：同一个闲鱼账号可能在本机约束之外被**另一台设备**（或两个客户端实例）同时添加并点「开始监听」，两端都会收到同一条买家消息 → **重复回复**。

**方案**：云端用 Redis 做**账号级监听租约**，客户端「开始监听」前必须先拿到租约。

| 项 | 约定 |
|---|---|
| Redis key | `goodfish:listen:{goodfish_id}` |
| value | 客户端实例标识 `client_instance_id`（建议：机器码 + 本地服务启动 ID，首次启动生成并持久化） |
| 租约 TTL | **90s** |
| acquire | `SET key value NX EX 90`：成功 → 获得占用；已存在且 value 为自己 → 续期成功（重入）；已存在且为他人 → 返回 **409**（业务码 `40901`） |
| renew | 仅当 value 等于自己时重置 TTL（**Lua 保证原子**）；客户端每 **30s** 续期一次 |
| release | 仅当 value 等于自己时删除（Lua）；停止监听 / 退出应用 / 应用冻结时主动调用 |
| 崩溃兜底 | 客户端进程崩溃 → 无法续期 → TTL 90s 后自动释放 |
| Redis 不可用 | **降级放行**（记 WARN），可用性优先；重复监听属低频问题 |

**接口**（客户端经网关调用，需鉴权）：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/goodfish/meta/account/{goodfish_id}/listen/acquire` | POST | 申请监听占用（body 带 `client_instance_id`）；成功返回 `lease_seconds`；已被其他设备占用 → **409 / 40901** |
| `/goodfish/meta/account/{goodfish_id}/listen/renew` | POST | 续期租约（仅持有者可续） |
| `/goodfish/meta/account/{goodfish_id}/listen/release` | DELETE | 释放占用（仅持有者可释放；停止监听 / 退出应用时调用） |

> 客户端侧流程见 [需求-客户端-监听控制](../../需求/需求-客户端-监听控制.md) §2.1；Redis 实例复用现有缓存 Redis。

## 三、数据设计

### 3.1 表：`goodfish_account`（闲鱼账号表）

存储本机上报的闲鱼账号信息，**不存储 Cookie**。

| 字段 | 类型（PG） | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键，自增 |
| goodfish_id | VARCHAR(64) | 闲鱼用户 ID，唯一索引 |
| goodfish_nickname | VARCHAR(128) | 闲鱼昵称 |
| remark | VARCHAR(256) | 备注 |
| status | VARCHAR(16) | 账号状态：`normal` / `disabled`。★**只停用、不删除**（默认 `normal`） |
| last_active_at | TIMESTAMP | 最后活跃时间 |
| create_dept / create_by / create_time / update_by / update_time | — | RuoYi 自带字段 |

### 3.2 表：`client_version`（客户端版本表）

| 字段 | 类型（PG） | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键，自增 |
| version | VARCHAR(32) | 版本号，唯一索引 |
| release_notes | TEXT | 更新说明 |
| force_update | BOOLEAN | 是否强制更新 |
| download_url | VARCHAR(256) | 安装包下载地址 |
| file_size | BIGINT | 安装包大小（字节） |
| sha512 | VARCHAR(128) | 安装包 **SHA-512** 校验值（上传时服务端自动计算；随检查更新接口下发供客户端比对） |
| create_dept / create_by / create_time / update_by / update_time | — | RuoYi 自带字段 |

## 四、接口设计

### 4.1 gRPC

|---|---|---|
| 账号域 | `AccountService` | `UpsertAccount`、`GetAccount`、`GetAccountByGoodfishId`、`ListAccounts` |
| 版本域 | `VersionService` | `CheckUpdate` |

proto 完整定义（`account.proto` / `version.proto`）收录于 [技术方案-云端-gRPC契约](技术方案-云端-gRPC契约.md)，此处不重复复制。

### 4.2 REST（北向，后台 + 客户端直连）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/goodfish/meta/account/list` | GET | 账号列表（分页） |
| `/goodfish/meta/account/{id}` | GET | 账号详情 |
| `/goodfish/meta/account` | PUT | 更新账号备注 |
| `/goodfish/meta/account/{id}/status` | PUT | **启用 / 停用账号**（★账号**只停用、不删除**，不提供 DELETE 接口） |
| `/goodfish/meta/account/report` | POST | **客户端账号上报**（`goodfish_id` / `goodfish_nickname` / `remark`，按 `goodfish_id` upsert，**不接收 Cookie**） |
| `/goodfish/meta/version/list` | GET | 版本列表 |
| `/goodfish/meta/version/check` | GET | **客户端检查更新**（传入当前版本号，返回最新版本信息：版本号、更新说明、是否强升、下载地址、文件大小） |
| `/goodfish/meta/version` | POST | 发布新版本（安装包上传存服务器本地磁盘，见 [技术方案-云端-文件存储](技术方案-云端-文件存储.md)） |
| `/goodfish/meta/ota/download?version=x.y.z` | GET | **安装包下载**（URL 传参，不用路径参数；按 `version` 查询参数定位版本，`client_version.download_url` 即该地址；需鉴权，不加网关白名单，客户端经自定义请求头携带登录 token） |
| `/goodfish/meta/version/force/{id}` | PUT | 设置强制更新 |
| `/goodfish/meta/version/{id}` | DELETE | 删除版本 |
