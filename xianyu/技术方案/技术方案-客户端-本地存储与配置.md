# 技术方案-客户端-本地存储与配置

> 来源：[《客户端监听.md》](../客户端监听.md) §2.10 本地存储 SQLite 表结构、§2.12 配置分层；[《客户端技术方案.md》](../客户端技术方案.md) §四 数据库表结构（内容重组收录，原文件保留未动）
> 关联：[需求-客户端-安全与本地配置](../需求/需求-客户端-安全与本地配置.md)

## 一、功能与职责（总）

### 1.1 功能定位

Python 本地服务的持久化层：本地 SQLite 数据库（账号、配置、消息日志、去重记录四张表）+ 分层配置加载机制。Cookie 字段的加密由 [技术方案-客户端-Cookie管理与加密](技术方案-客户端-Cookie管理与加密.md) 承担，本文件只定义其存储形态。

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| SQLite 表结构定义与 ORM 模型（SQLAlchemy 2.0 async + aiosqlite） | 业务逻辑（由 `services/` 层完成） |
| Alembic 数据库迁移 | Cookie 明文的加解密与密钥管理（见 [技术方案-客户端-Cookie管理与加密](技术方案-客户端-Cookie管理与加密.md)） |
| 配置分层加载（代码默认值 → config.yaml → 环境变量 → SQLite config 表） | 云端配置下发（云端地址打包写死，运行时本地优先） |
| 数据目录约定（`%APPDATA%/goodfish`） | 数据上报云端（本地数据除商品/账号基础信息外不出本机） |

### 1.3 与其他模块的关系

| 对象 | 方向 | 交互方式 |
|---|---|---|
| 账号服务 / 监听调度 | 上游 | 读写 `goodfish_account`（含监听状态机字段 `listen_state`） |
| 消息处理流水线 | 上游 | 写 `message_log`，读写 `dedup_record` 去重持久层 |
| 全部业务模块 | 上游 | 读 `config` 表配置项（配置分层中优先级最高） |
| Cookie 管理与加密 | 平级 | `goodfish_account.cookie` 字段为 AES-256-GCM 密文 |
| 打包方案 | 下游 | 数据目录固定 `%APPDATA%/goodfish`，不写安装目录 |

## 二、逻辑实现（分）

### 2.1 总体设计

- 本地数据库为 **SQLite**，ORM 用 **SQLAlchemy 2.0 (async) + aiosqlite**，迁移用 **Alembic**；
- DB 访问采用**单连接 + 串行化**（本地单机无并发压力，避免连接池复杂度）；
- 所有外部 I/O 必须 `await` 且带 `timeout`，DB 操作同样遵守异步边界（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.3）；
- 数据目录一律 `%APPDATA%/goodfish`（配置/日志/密钥/DB），不写安装目录；
- 表结构见 §三；配置项初始值见 §六。

### 2.2 配置分层

加载优先级（低 → 高，后者覆盖前者）：

| 层级 | 载体 | 说明 |
|---|---|---|
| 1 | 代码默认值 | 常量，兜底 |
| 2 | `config.yaml` | 打包内置的默认配置，随版本走 |
| 3 | 环境变量 | `GOODFISH_*` 前缀，部署/调试覆盖 |
| 4 | SQLite `config` 表 | 用户在 UI 改的值，**优先级最高**，重启保留 |

> 划分原则：**"能被用户改的"落 SQLite**（最大监听数、窗口时长、日志级别、图片限制）；**"部署相关的"走环境变量**（云端地址、端口、日志目录）；**"恒定不变的"进代码常量**。

## 三、数据设计

本地 SQLite 共四张表（与 [《客户端技术方案.md》](../客户端技术方案.md) 第四章对齐，并补齐消息日志与去重持久化两张表）。

**表：`goodfish_account`（闲鱼账号）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| goodfish_id | VARCHAR(64) | 闲鱼用户 ID，**唯一索引**（A11 去重） |
| goodfish_nickname | VARCHAR(128) | 闲鱼昵称 |
| cookie | TEXT | AES-256-GCM 加密后的 Cookie，**永不上云**（A10） |
| remark | VARCHAR(256) | 备注 |
| is_valid | BOOLEAN | Cookie 是否有效 |
| listen_state | VARCHAR(16) | 监听状态（对齐状态机：idle/connecting/online/backoff/invalid/disconnected，见 [技术方案-客户端-WebSocket监听](技术方案-客户端-WebSocket监听.md)） |
| last_check_at | DATETIME | 最后 Cookie 校验时间 |
| created_at / updated_at | DATETIME | 时间戳 |

> 监听状态字段已裁定采用 `listen_state VARCHAR(16)`（对齐账号状态机六态），旧版的 `is_listening BOOLEAN` 作废。

**表：`config`（配置项，key-value）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| key | VARCHAR(64) | 配置键，唯一索引 |
| value | TEXT | 配置值 |
| desc | VARCHAR(256) | 配置说明 |

**表：`message_log`（消息收发日志）** ★新增

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键，自增 |
| account_id | INTEGER | 关联账号 |
| item_id / buyer_id | VARCHAR(64) | 会话标识 |
| direction | VARCHAR(8) | `in`（买家）/ `out`（AI 回复） |
| content | TEXT | 消息内容（图片仅记录 `[图片]` 占位） |
| msg_type | VARCHAR(16) | text / image |
| result | VARCHAR(16) | 发送结果：success / failed / skipped |
| request_id | VARCHAR(64) | 关联云端请求（便于排障） |
| created_at | DATETIME | 时间戳 |

**表：`dedup_record`（去重持久化）** ★新增

| 字段 | 类型 | 说明 |
|---|---|---|
| message_id | VARCHAR(64) | 主键 |
| created_at | DATETIME | 用于定期清理（仅保留最近 2000 条 / 7 天） |

> 迁移用 Alembic；仅 `message_log` 需要保留策略（默认 30 天滚动删除），其余表不清理。

> 本地服务端口**不在配置表**——由端口协商机制（绑定 `127.0.0.1:0` 系统分配 + 握手行）动态确定（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.4），写死在配置里会造成"配置端口与实际监听端口"竞态。

## 五、异常与容错

| 异常场景 | 处理策略 |
|---|---|
| 主密钥解密失败（启动时无法解开已存 Cookie） | 提示"凭证无法解密，请重新录入 Cookie"，**不静默清空**用户数据（解密机制见 [技术方案-客户端-Cookie管理与加密](技术方案-客户端-Cookie管理与加密.md)） |
| 后台清理任务异常 | 日志清理等后台任务由 `TaskGroup` 托管，异常记日志并重启该 Task（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.3） |

## 六、配置项

**初始配置项**（写入 `config` 表）：

| key | 默认值 | 说明 |
|-----|--------|------|
| max_listen_count | 3 | 最大监听数 |
| slide_window_seconds | 5 | 滑动窗口时长（秒） |
| cloud_backend_url | 打包写死 | 云端后台地址 |
| auth_token | 空 | 管理后台登录 token |
| python_port | 随机 | 本地服务端口 |
| img_max_count | 5 | 单次图片张数上限 |
| img_max_total_mb | 5 | 单次图片总体积上限（MB） |
| log_level | INFO | 日志级别 |
| reply_delay_min_ms / reply_delay_max_ms | — | 随机延迟上下限（毫秒，1-2 秒） |

> 已裁定：`python_port` **不落配置表**——本地服务端口由启动端口协商动态确定（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.4），旧版"config 表存 python_port"作废；`img_max_count` / `img_max_total_mb` / `log_level` / `reply_delay_*` 为正式配置项。
