## 一、功能与职责（总）

### 1.1 功能定位

云端 AI 回复的核心服务 `goodfish-ai-service`（Python/FastAPI），核心编排服务、三段式执行链路。负责：

- 接收客户端的 AI 回复请求（经网关）
- 构建统一提示词（商品信息 + 场景提示词 + 对话历史）
- 调用大模型生成回复
- 维护对话历史（商品ID + 买家ID）
- 记录回复决策日志和 Token 消耗

### 1.2 职责边界 / 范围

| 项 | 内容 |
|---|---|
| **职责** | 对话编排、提示词渲染、大模型调用、对话历史维护、Token 统计、幂等 |
| **不负责** | 不存商品、不存提示词配置、不存模型配置 |
| **拥有的表** | `ai_conversation`、`ai_conversation_message`、`ai_reply_log` |
| **REST（北向）** | 业务接口 `POST /api/ai/reply`；**文件接口**：图片上传 `POST /api/ai/image`、图片静态访问 `GET /api/ai/image/view/{filename}`（免鉴权，加网关白名单，仅此路径）——详见 [技术方案-云端-对话服务-接口与幂等](技术方案-云端-对话服务-接口与幂等.md)、[技术方案-云端-文件存储](技术方案-云端-文件存储.md)；原 history / clear 接口已移除 |

服务自身技术形态：北向 REST（FastAPI + uvicorn）对外；东西向 gRPC **仅作调用方**——本期不启动 gRPC 服务端、不注册 gRPC 实例（仅当 Java 侧要调 Python 时才启用）。调用下游时经拦截器把**当前用户信息填入 gRPC metadata**（身份透传）；**服务间不做鉴权、不引入令牌**（靠内网隔离）。

### 1.3 与其他模块的关系

| 模块 | 关系 |
|---|---|
| 网关 | 客户端请求经网关路由 `lb://goodfish-ai-service`（路径透传，不 StripPrefix） |
| Nacos | 配置中心（业务配置）＋ 注册中心（注册 HTTP 实例），连接与封装见 [技术方案-云端-对话服务-多环境与配置中心](技术方案-云端-对话服务-多环境与配置中心.md)、[技术方案-云端-对话服务-Nacos注册-已实现](技术方案-云端-对话服务-Nacos注册-已实现.md) |
| 商品服务 / 模型服务 | 下游 gRPC 消费（`{app}-grpc` 服务名），发现与通道复用库 `xxs-nacos-grpc`，见 [技术方案-云端-gRPC发现库xxs-nacos-grpc-已实现](技术方案-云端-gRPC发现库xxs-nacos-grpc-已实现.md) |
| 大模型厂商 API | 唯一经 HTTP（OpenAI 兼容）访问的外部依赖；服务间调用一律 gRPC |

## 二、逻辑实现（分）

### 2.1 总体设计

技术栈与依赖：

| 依赖 | 版本 | 说明 |
|---|---|---|
| Python | >= 3.10 | 官方 v2 SDK 的最低要求 |
| **nacos-sdk-python** | **== 3.2.0** | 官方 SDK 当前最新版。**必须 ≥ 3.0.3**：3.0.0~3.0.2 已被 PyPI **yanked**（连接断开后不会重新注册的缺陷，装了也不会被解析）；禁止回落到 1.x/2.x 旧同步 API |
| fastapi + uvicorn | 最新稳定 | 北向 REST 框架 + ASGI 服务器 |
| **grpcio** | 最新稳定 | **东西向 gRPC 服务端与客户端**（`grpc.aio` 异步 API，与 uvicorn 共用同一事件循环） |
| **grpcio-tools** | 最新稳定 | 由 `proto/` 生成 Python stub（构建期依赖，不进运行时镜像） |
| **grpcio-health-checking** | 最新稳定 | gRPC 健康检查，供运维探活 |
| protobuf | 由 grpcio-tools 决定 | 协议运行时 |
| pydantic-settings | 最新稳定 | bootstrap 配置（环境变量 / .env） |
| sqlalchemy[asyncio] + asyncpg | 2.x | 异步 PostgreSQL ORM |
| redis[hiredis] | 5.x | 缓存 |
| httpx | 最新稳定 | 异步 HTTP（**仅用于调大模型 API**；服务间调用一律 gRPC） |

### 2.2 Nacos SDK 关键特性（决定接入方式）

- **v2 API 全异步**：所有方法都是 coroutine，与 FastAPI 天然契合
- **导入路径是 `v2.nacos`**：包名 `nacos-sdk-python`，但模块名是 `v2`；与 1.x 的 `import nacos` 完全不同的 API
- **gRPC 长连接**：连接端口 = 主端口 + 1000（如 8848 → 9848），部署时防火墙需放行
- **连接级自动保活**：临时实例（ephemeral）随 gRPC 连接存活，进程崩溃/断连后服务端自动摘除实例，**应用层无需自行心跳**
- **订阅推送**：服务实例变更通过 subscribe 回调推送，无需轮询
- **依赖较重**：3.2.0 会带入 `grpcio` / `protobuf` / `aiohttp` / `a2a-sdk` / `alibabacloud_kms20160120` 等约 11 个运行时依赖，Docker 镜像体积与构建时间需提前评估（基础镜像建议用 `python:3.12-slim` + 分阶段构建）
- **版本边界**：**钉死 3.2.0**（已核实为当前最新）。`3.0.0`/`3.0.1`/`3.0.2` 已被 PyPI **yanked**（"断连后无法重新注册"缺陷）；`3.0.4` 存在 `a2a>=0.44` 依赖冲突（官方 issue #332 的结论就是让用户直接升 3.2.0），**不要回落**

### 2.3 FastAPI 生命周期集成（启动 / 优雅关闭）

两个关键设计决策：

1. **注册时机**——注册放到 lifespan startup 的最后一步。FastAPI 在 lifespan startup 完成前不会接收任何请求，因此"先注册后服务"不会出现未就绪实例接流量。
2. **信号处理**——不做手工 `signal.signal`（会与 uvicorn 自身管理冲突）。uvicorn 收到 SIGTERM/SIGINT 后自动走 lifespan shutdown，一切收尾都在 `finally` 中按序执行。

```python
# app/main.py
import logging
from contextlib import asynccontextmanager

import yaml
from fastapi import FastAPI

from app.bootstrap import load_bootstrap
from app.constants import SERVICE_NAME_AI
from app.db import close_db, init_db
from app.grpc.clients import GrpcClients
from app.grpc.registry import GrpcChannelRegistry
from app.nacos.manager import NacosManager, resolve_register_ip
from app.redis_client import close_redis, init_redis
from app.runtime import RuntimeConfig, on_config_changed, parse_remote_config
from app.utils.env_placeholder import expand_placeholders
from app.version import SERVICE_VERSION

logger = logging.getLogger(__name__)


def create_app() -> FastAPI:
    bootstrap = load_bootstrap()

    @asynccontextmanager
    async def lifespan(app: FastAPI):
        # 1. 建 Nacos gRPC 连接（配置中心 + 注册中心）；重试 3 次仍失败则拒绝启动
        nacos = NacosManager(
            bootstrap,
            service_ip=resolve_register_ip(bootstrap.nacos_register_ip),
        )
        await nacos.start()
        clients = None
        try:
            # 2. 拉远程配置：先 yaml.safe_load，再递归展开 ${VAR}
            raw = await nacos.get_app_config()
            runtime = RuntimeConfig(parse_remote_config(expand_placeholders(yaml.safe_load(raw))))

            # 3. 用远程配置初始化依赖（失败则启动失败，不会注册半个服务）
            await init_db(runtime.database)
            await init_redis(runtime.redis)

            # 4+5. 装配下游 gRPC 通道：订阅 Nacos → 拼 ipv4 多地址 target → 内置 round_robin
            #      实现见《gRPC与Nacos服务发现技术方案.md》§6.3 / §6.4
            registry = GrpcChannelRegistry(
                discovery=runtime.grpc.discovery,
                channel=runtime.grpc.channel,
            )
            await registry.start(nacos)              # 内部完成 subscribe + 首轮 channel 构建
            clients = GrpcClients(registry)

            # 6. 本期**不启动 gRPC 服务端**（Java→Python 链路未启用，见 3.6.1）；
            #    将来启用时： await serve_grpc(clients)，并额外注册 goodfish-ai-service-grpc

            # 7. 注册配置监听（热更新：仅运行参数；连接信息变更只标 dirty + 告警）
            await nacos.watch_app_config(on_config_changed)

            # 8. 注册自身 HTTP 实例 —— lifespan 最后一步，之后 uvicorn 才开始接请求
            #    本期**不注册 gRPC 实例**（Java→Python 链路未启用）；
            #    将来启用时追加一条：register_instance(SERVICE_NAME_AI_GRPC, bootstrap.grpc_port, ...)
            await nacos.register_instance(
                service_name=SERVICE_NAME_AI, port=bootstrap.server_port,
                metadata={"env": bootstrap.app_env, "version": SERVICE_VERSION},
            )

            app.state.bootstrap = bootstrap
            app.state.runtime = runtime
            app.state.nacos = nacos
            app.state.grpc_clients = clients
            yield                                   # ===== 服务运行期 =====
        finally:
            # 优雅关闭（uvicorn 收到 SIGTERM/SIGINT 自动进入）
            await nacos.deregister_all()             # a. 先摘流量（注销 HTTP 实例）
            if clients is not None:
                await clients.close()                # b. 关下游 gRPC 通道
            await close_redis()                      # c. 关运行依赖
            await close_db()
            await nacos.shutdown()                   # d. 断 Nacos SDK 连接
            logger.info("服务已从 Nacos 注销并优雅退出")

    app = FastAPI(title=SERVICE_NAME_AI, lifespan=lifespan)

    @app.get("/health")
    async def health() -> dict[str, str]:
        """北向探针（免鉴权）；gRPC 侧另有 grpc-health-checking 供运维探活。"""
        return {"status": "UP"}

    return app


app = create_app()


if __name__ == "__main__":
    import uvicorn

    _bootstrap = load_bootstrap()
    # REST（uvicorn）与 gRPC（grpc.aio）并行监听，共用同一事件循环，因此 workers 必须为 1
    uvicorn.run(
        "app.main:app",
        host=_bootstrap.server_host,
        port=_bootstrap.server_port,
        workers=1,          # ★ 必须为 1，见下方说明
    )
```

> **为什么 `workers` 必须为 1**：注册参数里的 `ip:port` 是**进程级**的。多 worker 会使用同一端口（SO_REUSEPORT）却各自注册同一个 `ip:port`；任一 worker 退出时执行 `deregister`，会把整个实例从 Nacos 摘掉，而其他 worker 仍在监听 → 网关 503。若确需多进程，必须改造成"每 worker 独立端口 + 独立实例 ID"，本期不做。
>
> **注册端口的确定性**：`server.host` / `server.port` 放在 bootstrap（部署属性），`NacosManager` 与 `uvicorn.run()` 读同一个值，因此"注册端口 == 监听端口"由代码结构保证，不存在"要在注册前先知道远程端口"的时序难题。

**启动/关闭顺序图**：

```
启动                                          关闭（SIGTERM/SIGINT）
────────────────────────────────────         ─────────────────────────
加载 bootstrap（APP_ENV → namespace）          1. deregister（先摘流量）
→ gRPC 连接 Nacos                             2. 关 Redis / DB 连接池
→ 拉配置 + 展开 ${VAR} + 应用                  3. naming/config client.shutdown()
→ 注册配置监听（热更新）                        4. uvicorn 退出进程
→ 初始化 DB / Redis
→ 订阅 llm-manage
→ register（ephemeral）
→ uvicorn 开始接收请求
```
