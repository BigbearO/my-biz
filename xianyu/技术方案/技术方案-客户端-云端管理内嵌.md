## 一、功能与职责（总）

### 1.1 功能定位

Electron 渲染层经内嵌 WebView 加载**云端部署的管理后台（plus-ui）**，用户不离开客户端即可完成商品 / 提示词 / 模型的全部管理配置。本文档定义 **WebView 容器侧**的技术方案：页面加载、登录态注入（`Authorization` 请求头）、401 联动。

**架构边界（本页 vs 客户端本地页）**：

| | 「云端管理」页 | 客户端本地页（账号管理 / 日志 / 设置） |
|---|---|---|
| 页面来源 | 内嵌 WebView 加载 | Electron 渲染层**自研页面** |
| 后端 | **云端的 plus-ui + 云端服务**（plus-ui 为**纯云端应用**，客户端**不内嵌其前端工程**） | **内嵌 Python 本地服务**（`http://127.0.0.1:{port}/api`，SQLite 存储） |
| 登录态 | 复用本地 token，经请求头注入 | 本地 token（config 表） |

> plus-ui 仅作**纯云端**管理后台：客户端不内嵌其前端代码，WebView 只是指向其云端部署地址；客户端本地页面的数据存取全部走内嵌的 Python 本地服务（SQLite）。plus-ui 的登录与 token 存储方式仅作客户端登录实现的**参考**。

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| WebView 创建与加载（后台地址打包写死，不存本地配置） | 后台内部页面与接口实现（plus-ui 与云端服务，归云端文档） |
| 对后台域名请求**统一注入 `Authorization: Bearer <token>` 与 `clientid` 请求头** | 登录 token 的获取（`/api/system/login`，token 落 config 表，见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md) §四/§六） |
| WebView 内 401 监听 → 与主流程同一套 401 处理 | 授权校验时机（启动/每小时，见 [技术方案-云端-鉴权与授权](技术方案-云端-鉴权与授权.md) §2.3） |

### 1.3 与其他模块的关系

| 对象 | 方向 | 交互方式 |
|---|---|---|
| 本地 SQLite config 表 | 读 | token 来源：进入云端管理页时**现读** `auth_token`（Electron 与 Python 共用同一 SQLite） |
| 云端网关 | 下游 | 注入头经网关统一鉴权（`Authorization` + `clientid` 匹配校验，见 [技术方案-云端-鉴权与授权](技术方案-云端-鉴权与授权.md) §2.1） |
| plus-ui（后台前端） | 被其加载 | **最小配合改造**（启动引导探测 / 不覆盖注入头 / 401 交给外层），见 2.3 |
| Electron 渲染层 | 上游 | 401 时通知渲染层跳登录页（与 Python 侧同一套机制） |

## 二、逻辑实现（分）

### 2.1 总体设计

```
渲染层点击「云端管理」菜单
    ↓
主进程获取/创建 WebView（专属 session partition: persist:admin-webview）
    ↓
安装 webRequest 钩子（仅对后台域名生效）：
  - onBeforeSendHeaders：注入 Authorization + clientid
  - onHeadersReceived：监听 401/403
    ↓
从 config 表现读 auth_token → 加载后台首页
    ↓
后台所有 API 请求自动携带 Authorization: Bearer <token>（网关鉴权通过）
    ↓
网关返回 401 → 主进程统一处理（删 token、跳登录页，监听保持运行 A27）
```

### 2.2 请求头注入（核心机制）

- WebView 使用**专属 session partition**（`persist:admin-webview`），不污染默认 session，钩子只影响 WebView 自身；
- `onBeforeSendHeaders` 的 `filter.urls` 限定后台域名（`{cloud_backend_url}/**`），**不把头注入无关域名**；
- `requestHeaders` 做**合并**而非整体替换（保留 `clientid`、`Content-Type` 等原有头）；
- token **每次进入云端管理页时从 config 表现读**，不持有旧引用——重新登录后再次进入即生效，无需额外刷新机制。

```js
// electron/admin-webview.js（主进程）
const ADMIN_PARTITION = 'persist:admin-webview';
const CLIENTID = app.getClientId();            // 打包写死常量，与登录接口共用同一值（见 2.4）

function attachAdminWebView(webContents) {
  const ses = session.fromPartition(ADMIN_PARTITION);
  const filter = { urls: [`${BACKEND_ORIGIN}/*`] };   // 后台域名，打包写死

  ses.webRequest.onBeforeSendHeaders(filter, (details, callback) => {
    const token = readTokenFromConfig();             // 现读 SQLite config 表 auth_token
    callback({
      requestHeaders: {
        ...details.requestHeaders,
        Authorization: `Bearer ${token}`,            // OAuth2 风格，覆盖 plus-ui 自带头
        clientid: CLIENTID,                          // 网关校验 token 与 clientid 绑定（见 2.4）
      },
    });
  });

  ses.webRequest.onHeadersReceived(filter, (details, callback) => {
    if (details.statusCode === 401) handle401();     // 见 2.5
    if (details.statusCode === 403) handle403();     // 见 2.5（A42）
    callback({ cancel: false });
  });
}
```

### 2.3 plus-ui 配合改造（最小三处）

注入头能拦住 HTTP 请求，但**说服不了前端路由守卫**（plus-ui 路由守卫看自身存储的 token，无 token 直接跳它自己的登录页）。后台前端需配合三处小改：

| # | 改造点 | 内容 |
|---|---|---|
| 1 | **启动引导** | 路由守卫放行：应用启动时直接调探测接口（如 `getInfo`，该请求已被注入 `Authorization`）→ 200 视为已登录、记录登录态并放行路由；失败走 401 联动 |
| 2 | **请求层** | request 拦截器**不再从自身 cookie 读 token 覆盖 `Authorization` 头**（避免覆盖外层注入的头） |
| 3 | **401 交外层** | 响应拦截器收到 401 **不再跳自身登录页**（交给 Electron 主进程统一处理） |

### 2.4 clientid 一致性（网关绑定校验，必须满足）

- RuoYi 网关除校验 token 外，还校验 **`clientid` 请求头与 token 是否绑定匹配**（见 [技术方案-云端-鉴权与授权](技术方案-云端-鉴权与授权.md) §2.1）；
- 客户端 `/api/system/login` 登录时使用的 clientid 必须与 WebView 注入的 clientid **相同**，否则注入 token 后的请求会被网关拒绝；
- 措施：clientid 定义为**打包写死常量**，登录接口（`/api/system/login` → 云端 `/auth/login`）与 WebView 请求头注入共用同一值。

### 2.5 401 / 403 联动

| 响应 | 处理（与 Python 侧同一套机制） |
|---|---|
| **401 / 40101** | 删除本地 token（config 表）→ 渲染层跳登录页；监听保持运行（A27）。plus-ui 侧由 2.3-③ 保证不出现"WebView 内嵌登录页" |
| **403 / 40301** | 授权过期：停止所有监听 + 弹窗"授权已过期" + **冻结应用，只允许退出**（A42）——WebView 内触发与主流程行为一致 |

## 三、异常与容错

| 异常场景 | 处理策略 |
|---|---|
| 后台地址不可达 / WebView 加载失败 | WebView 区域显示"云端管理加载失败"提示 + 重试按钮，不影响其他页面功能 |
| token 失效（401） | 见 2.5，统一 401 处理 |
| WebView 内管理操作报业务错误 | 由后台页面自行展示（外层只拦截 401/403，不介入业务语义） |
| 用户未登录点击「云端管理」 | 主界面登录门禁已保证进入主界面必然已登录（token 存在）；token 失效由 2.5 兜底 |

## 四、配置项

| 配置项 | 值 | 说明 |
|---|---|---|
| 云端后台地址 | 打包写死 | WebView 加载地址（不存本地配置，见 [需求-客户端-安全与本地配置](../需求/需求-客户端-安全与本地配置.md)） |
| clientid | 打包写死常量 | 登录接口与 WebView 请求头注入**共用同一值**（见 2.4） |
| session partition | `persist:admin-webview` | WebView 专属会话，隔离注入钩子 |
