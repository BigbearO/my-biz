## 一、功能与职责（总）

### 1.1 功能定位

客户端是 **Electron 壳 + Python 本地服务（FastAPI）** 的双进程桌面应用，是闲鱼自动回复系统的本地执行端：

- **Electron**：桌面壳，负责 UI（Vue3 渲染层）、系统托盘、Python 进程启动与守护、自动升级；
- **Python 本地服务**：监听核心，负责闲鱼协议对接、多账号 WebSocket 监听、消息处理流水线、图片处理、商品同步、本地 SQLite 存储与云端 API 调用；
- **闲鱼协议层（`xianyu/` 包）**：可替换的隔离边界，见 [技术方案-客户端-闲鱼协议层](技术方案-客户端-闲鱼协议层.md)。

系统级整体架构（云端、客户端、闲鱼服务端的关系）见 [技术方案-云端-架构总览](技术方案-云端-架构总览.md)；监听方案整体背景见 [《客户端监听.md》](../客户端监听.md) §一。

**技术栈**：

| 层级 | 技术选型 |
|------|----------|
| 桌面壳 | Electron + Vue3 + Element Plus + Vite |
| 包管理 | npm |
| 本地服务 | Python + FastAPI |
| 数据库 ORM | SQLAlchemy 2.0 (async) |
| 数据库迁移 | Alembic |
| 数据校验 | Pydantic V2 |
| 本地数据库 | SQLite |
| 打包 | PyInstaller（Python）+ electron-builder（Electron） |
| 图片处理 | Pillow |

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| Electron：UI 渲染、系统托盘、Python 进程启动/守护、自动升级 | AI 回复生成（由云端对话服务完成，客户端只携带消息请求 `/api/ai/reply`） |
| Python：闲鱼协议对接、多账号 WS 监听、消息流水线、图片处理、商品同步 | 商品与对话数据的云端存储（客户端只负责全量拉取后上报） |
| Python：本地 SQLite 存储、Cookie 加密存储（永不上云，A10） | Cookie 明文出本机（云端上报只带 `goodfish_id` / `nickname`） |
| Python：云端 API 调用（token 注入、重试、401/403 统一处理） | 云端服务自身的部署与治理（Nacos、网关、LLM 管理） |

### 1.3 与其他模块的关系

| 对象 | 方向 | 交互方式 |
|---|---|---|
| Electron 主进程 → Python 本地服务 | 下游 | child_process 启动/守护；stdout 握手行获取端口（见 [技术方案-客户端-本地服务进程管理](技术方案-客户端-本地服务进程管理.md)） |
| Electron 渲染层 → Python 本地服务 | 下游 | HTTP fetch 轮询（`http://127.0.0.1:{port}/api`，带 `X-Local-Token`，无推送通道，见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md)） |
| Python 本地服务 → 云端 | 下游 | HTTP（cloud_client：token 注入、重试 3 次、401/403 处理），见 [技术方案-客户端-云端调用与容错](技术方案-客户端-云端调用与容错.md) |
| Python 本地服务 → 闲鱼服务端 | 下游 | HTTP 接口 + WebSocket 长连接（协议层），见 [技术方案-客户端-闲鱼协议层](技术方案-客户端-闲鱼协议层.md)、[技术方案-客户端-WebSocket监听](技术方案-客户端-WebSocket监听.md) |
| Python 本地服务 → 本地 SQLite | 下游 | SQLAlchemy async + aiosqlite，见 [技术方案-客户端-本地存储与配置](技术方案-客户端-本地存储与配置.md) |
| Cookie 管理 / 消息流水线 / 商品同步 / 日志 / 打包 | 内部模块 | 划分见 §2.2，各自详见同目录对应功能点文档 |

### 2.3 进程与并发模型

| 项 | 方案 |
|---|---|
| **进程数** | Python 单进程，Uvicorn `workers=1` |
| **事件循环** | 全服务共用一个 asyncio loop：本地 HTTP、N 条闲鱼 WS、消息流水线、定时任务 |
| **异步边界** | 所有外部 I/O（httpx / WS / SQLite）必须 `await` 且带 `timeout`；**严禁在协程内做同步阻塞调用** |
| **阻塞代码处理** | 加密等 CPU/同步任务用 `asyncio.to_thread()` 卸载，避免卡住 WS 心跳 |
| **后台任务** | 心跳任务、每小时 Cookie 巡检、日志清理统一由 `TaskGroup` 托管，进程退出时统一取消 |
| **任务异常** | 每个后台 Task 包 `try/except`，异常必须记日志并重启该 Task，禁止"任务静默死亡" |
| **DB 访问** | SQLAlchemy async + aiosqlite，单连接 + 串行化（本地单机无并发压力，避免连接池复杂度） |

> 为什么必须强调：WS 心跳（应用层每 15s）与 HTTP 服务同 loop，任何一次同步阻塞（如大文件加解密 3s）都会卡住心跳发送 → 连接异常 → 触发无意义重连。

### 2.4 启动流程、端口协商与优雅关闭

**端口协商**：Python 绑定 `127.0.0.1:0` 由系统分配端口，启动完成后把端口**主动告知** Electron，而不是让 Electron 去读可能过期的配置文件（避免"配置端口与实际监听端口"竞态）。

```
Python 启动
  ├─ uvicorn 绑定 127.0.0.1:0（系统分配随机端口）
  ├─ 启动完成后向 stdout 打印单行握手协议：
  │     #GOODFISH_PORT#{"port":53219,"pid":1234,"version":"1.0.0"}#END#
  ├─ 同时原子写 runtime.json（先写 .tmp 再 rename，避免读到半截文件）
  └─ 兜底：Electron 对握手端口做 TCP 连通性探测确认可用（health 探针接口已移除）

Electron
  ├─ spawn python.exe，监听 stdout，正则捕获握手行 → 得到端口
  ├─ 握手超时（默认 15s）→ 读取 runtime.json → 再失败走端口段探测
  └─ 用端口 + X-Local-Token 调用本地 API
```

**启动顺序**：

```
1. 解析命令行/环境变量（X-Local-Token、日志目录）
2. 初始化配置分层（见 技术方案-客户端-本地存储与配置）→ 初始化 loguru
3. 打开 SQLite，执行 Alembic 迁移
4. 解密主密钥，校验能否解开已存 Cookie（失败 → 提示重新录入，不静默）
5. 绑定 127.0.0.1:0，stdout 输出握手行 + 原子写 runtime.json
6. 启动后台任务：Cookie 巡检、日志清理
7. 不自动恢复监听（A25），等待用户点击"开始监听"
```

**优雅关闭**（A38，由 Electron 先调 `/api/account/stop-all` 再发退出信号）：

```
1. 停止接收新的本地 HTTP 请求
2. 取消后台任务（心跳、巡检），等待在途流水线批次完成（超时 5s 后强制取消）
3. 逐个关闭闲鱼 WS 连接
4. flush 日志 / 关闭 SQLite
5. 退出进程
```

进程启动失败重试（2 次/间隔 2s）与崩溃自愈（连续崩溃 3 次阈值）见 [技术方案-客户端-本地服务进程管理](技术方案-客户端-本地服务进程管理.md)。
