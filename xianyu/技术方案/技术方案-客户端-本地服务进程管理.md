## 一、功能与职责（总）

### 1.1 功能定位

Electron 主进程（`electron/python-manager.js`）负责 Python 本地服务 exe 的**启动、探活、崩溃拉起与退出编排**，保证本地服务（FastAPI）在应用生命周期内始终可用。本地服务是闲鱼监听、消息流水线、本地 API 的唯一宿主（Python 单进程，Uvicorn `workers=1`），其进程模型见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.3。

### 1.2 职责边界

| 负责 | 不负责 |
|---|---|
| Electron：spawn Python exe、监听 stdout 握手行获取端口 | Python 服务内部业务（监听、流水线、存储等，见同目录各功能点文档） |
| Electron：启动失败重试（2 次/间隔 2s）、崩溃自动拉起 | 端口协商与优雅关闭的具体协议（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.4） |
| Electron：退出前调 `/api/account/stop-all` 再发退出信号 | 应用自动升级（见 [技术方案-客户端-自动升级](技术方案-客户端-自动升级.md)） |
| Electron：以进程句柄 + 握手端口 TCP 连通性守护探活 | 本地 API 的业务实现（见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md)） |

### 1.3 与其他模块的关系

| 对象 | 方向 | 交互方式 |
|---|---|---|
| Electron 主进程 → Python 本地服务 | 下游 | child_process 启动；stdout 握手协议；HTTP 探活 |
| 总体架构 | 平级 | 进程/并发模型与端口协商细节收录于 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) |
| 本地 API（`/api/account/stop-all`） | 下游 | 优雅关闭的调用通道；探活不走 HTTP（health 接口已移除），见 [技术方案-客户端-本地API](技术方案-客户端-本地API.md) |
| 闲鱼监听 | 下游 | 进程可用是 WS 监听的前提，见 [技术方案-客户端-WebSocket监听](技术方案-客户端-WebSocket监听.md) |

## 二、逻辑实现（分）

### 2.1 总体设计

Electron 主进程通过 `child_process` 启动/守护 Python exe：

```
┌─────────────────────────────────────────┐
│  Electron 主进程（main）                │
│  - 启动/守护 Python exe                 │
└─────────────────────────────────────────┘
              ↓ child_process
┌─────────────────────────────────────────┐
│  Python 本地服务（FastAPI）             │
│  - 监听 127.0.0.1:随机端口              │
└─────────────────────────────────────────┘
```

**启动流程**：

```
1. Electron 启动
2. Electron 主进程启动 Python exe
3. Python exe 启动 FastAPI 服务，绑定 127.0.0.1:随机端口
4. Python 端口写入本地配置，Electron 读取
5. Electron 渲染层加载登录页/主界面
6. 渲染层调本地 API，检查登录态
7. 未登录 → 显示登录页
8. 已登录 → 显示主界面（账号管理页）
```

> 现行端口获取方式为**端口协商**：Python 绑定 `127.0.0.1:0` 由系统分配，启动完成后经 stdout 握手行主动告知 Electron（`#GOODFISH_PORT#{"port":...,"pid":...,"version":"1.0.0"}#END#`），并原子写 `runtime.json` 兜底；不再依赖 Electron 读取可能过期的配置文件。完整握手协议与回退链见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.4。

### 2.2 启动失败重试

- Electron 启动时拉起 Python exe 失败：**自动重试 2 次，间隔 2 秒**；
- 2 次都失败 → 弹窗提示"**本地服务启动失败，请联系管理员**"，弹窗确认后退出应用；
- 端口握手超时（默认 15s 内未捕获握手行）时，Electron 依次回退：读取 `runtime.json` → 端口段探测 → 弹窗"本地服务启动失败"；
- 服务可用性以**进程句柄 + 握手端口 TCP 连通性**探测为准（运行期 Electron 守护探活同此；`/api/system/health` 探针接口已裁定移除）。

### 2.3 进程崩溃自愈

- Python exe 进程**异常退出**时，Electron 主进程自动拉起；
- **连续崩溃超过 3 次** → 不再拉起，弹窗提示用户"**本地服务异常，请重启应用**"（A20）。

### 2.4 退出处理

- 退出应用前**先停止所有监听，再退出进程**（A38）；
- 由 Electron 先调 `/api/account/stop-all`，再发退出信号；
- Python 侧优雅关闭顺序（停止接单 → 取消后台任务并等待在途批次（超时 5s 强制取消）→ 逐个关闭闲鱼 WS → flush 日志/关闭 SQLite → 退出）见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.4。

## 五、异常与容错

| 异常场景 | 处理方案 |
|---|---|
| **本地服务启动失败** | Electron 重试 2 次（间隔 2s），仍失败弹窗"本地服务启动失败，请联系管理员"并退出 |
| **端口握手超时** ★ | Electron 依次回退：`runtime.json` → 端口段探测 → 弹窗"本地服务启动失败" |
| **Python 进程崩溃** | Electron 主进程自动拉起；连续崩溃超过 3 次 → 弹窗"本地服务异常，请重启应用"，不再拉起（A20） |
| **退出应用** | 先停止所有监听，再退出进程（A38） |
| **后台任务异常** | 每个后台 Task 包 `try/except`，异常必须记日志并重启该 Task，禁止"任务静默死亡"（见 [技术方案-客户端-总体架构](技术方案-客户端-总体架构.md) §2.3） |
