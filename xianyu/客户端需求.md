# 闲鱼自动回复系统 客户端需求规格说明书

> 版本：v3.9 ｜ 日期：2026-09-29 ｜ 状态：需求确认
> 关联文档：《技术方案.md》（架构与表结构设计）、《云端需求.md》（云端管理后台）

## 一、项目概述

### 1.1 项目目标

基于大模型实现闲鱼消息智能自动回复，配套商品管理、提示词管理、模型管理能力。采用**「本地监听代理 + 云端管理后台」分离架构**，在保证闲鱼账号凭证安全的前提下，实现 Web 化统一配置管理。

### 1.2 风险提示

- 闲鱼官方禁止第三方逆向工具、自动应答脚本，本方案仅用于技术研究，使用存在账号封禁风险
- 严禁用于商业用途、多账号批量运营
- 开源逆向 SDK 存在协议升级失效的可能，需持续维护适配

### 1.3 核心设计原则

| 原则 | 说明 |
|------|------|
| **敏感凭证本地化** | 闲鱼 Cookie 仅存本地，加密存储，永不离机 |
| **业务配置云端化** | 商品、提示词、模型配置统一云端管理 |
| **风险隔离原则** | 闲鱼交互逻辑与业务管理逻辑彻底分离 |
| **单入口体验** | Electron 统一入口，用户只启动一个应用 |

## 二、整体架构

```
Electron 桌面应用（单入口，唯一用户感知）
├── Vue 渲染层（左侧菜单 + 右侧内容区，标准管理系统布局）
│   ├── 左侧菜单
│   │   ├── 账号管理
│   │   ├── 云端管理（商品/提示词/模型，WebView 内嵌）
│   │   └── 日志
│   └── 右侧内容区（根据菜单切换）
└── 主进程
    └── 守护 Python exe（本地服务，仅绑定 127.0.0.1）
        ├── 本地 SQLite 数据库
        ├── 闲鱼 WebSocket 监听
        └── 消息收发 HTTP 接口
```

## 三、启动流程

```
1. 打开 Electron 应用
2. 调云端后台接口，检查登录态
3. 401（未登录）→ 跳转管理系统登录页（全屏登录，不显示主界面）
4. 登录成功 → 保存登录 token
5. 调授权校验接口，检查账号是否有使用权限
   - 授权有效 → 进入主界面（默认选中「账号管理」菜单）
   - 授权过期/无权限 → 弹窗提示"授权已过期"，应用冻结，只能点退出
   - 云端接口不可用 → 弹窗提示"服务器异常，请联系管理员"，应用冻结
```

> 说明：第一道门槛是**管理后台账号**，第二道门槛是**授权校验**。登录成功后拿到的 token 存储在本机，供 Electron 和 Python 两端共用。
>
> **重启后监听状态**：应用重启后不自动恢复监听，所有账号都是"未监听"状态，需要用户手动点「开始监听」。

## 五、账号管理页（默认首页）

### 5.1 页面布局

- 顶部：「添加账号」按钮
- 主体：表格分页展示
- 表格列：闲鱼 ID、闲鱼昵称、是否有效、监听状态、创建时间、备注、操作

### 5.2 操作列

| 按钮 | 说明 |
|------|------|
| 开始监听 / 停止监听 | 切换监听状态 |

- 如果该账号正在监听，点删除时弹出确认提示：

- 用户确认后 → 先停止监听 → 再删除记录
- 用户取消 → 不做任何操作

### 5.4 状态展示

| 状态字段 | 展示方式 |
|----------|----------|
| 是否有效 | 绿色对勾 = 有效，灰色叉 = 失效 |
| 监听状态 | 绿色"监听中" / 灰色"未监听" |

## 六、添加账号流程

1. 点击「添加账号」按钮
2. 弹出对话框，包含：
   - Cookie 输入框（多行粘贴），一次只输入一个
   - 备注输入框
3. 点击「确认」
4. 本地调闲鱼接口验证 Cookie 有效性
5. 验证通过 → 自动拉取闲鱼 ID、闲鱼昵称
6. 检查该闲鱼 ID 是否已存在
   - 已存在 → 提示"该账号已添加，请勿重复添加"
   - 不存在 → 连同备注一起存入本地数据库
7. 验证失败 → 提示错误信息，不存入

## 七、监听控制

### 7.1 开始监听逻辑

点击某条记录的「开始监听」按钮时：

```
1. 查询当前正在监听的账号数量
2. 判断是否已达最大监听数（配置项，默认 3）
   - 已达上限 → 提示"已达上限，请先停止其他账号"，不执行操作
   - 未达上限 → 继续
3. 启动该账号的 WebSocket 监听
4. 验证 Cookie 有效性，更新是否有效字段
   - 验证通过 → 标记为有效
   - 验证失败 → 标记为失效，提示错误
5. 更新监听状态为"监听中"
```

> 约束：同一个闲鱼账号只能有一条 cookie 记录，因此同一账号只会有一个监听实例，不存在重复监听问题。

### 7.2 停止监听逻辑

点击「停止监听」时：

1. 断开该账号的 WebSocket 连接
2. 更新监听状态为"未监听"

### 7.3 并发限制说明

- 同一时间最多监听 **3 个**闲鱼账号
- 超过时不自动切换、不排队，直接提示用户手动停止其他账号
- 最大监听数为本地配置项，可修改

## 八、消息处理流程

```
买家发送消息
    ↓
本机 WebSocket 收到事件
    ↓
消息去重：按 message_id 去重，重复消息直接丢弃
    ↓
提取字段：
  - 消息 ID（message_id）
  - 商品 ID（item_id）
  - 买家 ID（buyer_id）
  - 会话 ID（session_id）
  - 消息内容（message）
  - 消息类型（text / image）
    ↓
图片消息处理：
  - 本机下载图片
  - 超过 1MB 自动压缩到 800px 宽（使用 Pillow）
  - 转 base64 后随消息一起上报云端
  - 文本消息直接上报
    ↓
滑动窗口合并：
  - 同一买家 + 同一商品，5 秒内的多条消息合并
    ↓
推送到云端管理后台（携带上述全部字段 + 登录 token）
    ↓
云端处理：
  1. 根据商品 ID 匹配商品库
  2. 加载商品上的提示词
  3. 用 item_id + buyer_id 作为对话 ID，调用大模型生成回复（云端维护对话历史）
    ↓
返回回复内容到本机
    ↓
本机等待 1-2 秒随机延迟 → 调用闲鱼接口发送消息
```

> 说明：无人工审核环节，AI 生成后直接下发发送。
>
> **商品不存在处理**：如果云端找不到对应商品，返回错误码，本机不发送、不回复。
>
> **对话历史**：客户端不维护对话历史，由云端用「商品 ID + 买家 ID」作为对话 ID 去维护上下文。

## 九、商品同步

### 9.1 功能说明

- 每个 cookie 详情页有「同步商品」按钮
- 点击后本机调闲鱼接口，**全量拉取**该账号下所有商品
- 拉取到的全部数据推送到云端后台存储
- 云端用于后续消息回复时的商品上下文匹配

### 9.2 同步方式

- 点击「同步商品」后，按钮变灰提示"正在同步..."
- 后台异步执行同步，不阻塞界面
- 同步完成后弹出 toast 提示："同步完成，新增 X 个，更新 X 个"
- 同步过程中重复点击不生效（按钮置灰）
- 同步失败时弹出 toast 提示"同步失败，请重试"，下次点同步重新全量拉取

### 9.3 同步字段

商品 ID、商品标题、商品描述、价格、库存状态（闲鱼接口返回什么就推什么，不做过滤）

## 十三、自动升级

### 13.1 升级触发方式

- **启动时自动检查**：每次打开应用时自动检查是否有新版本
- **手动检查**：设置页点击「检查更新」按钮触发

### 13.2 升级流程

```
1. 检查更新接口返回最新版本信息
2. 对比当前版本：
   - 已是最新 → 提示"当前已是最新版本"
   - 有新版本 → 弹出更新提示弹窗
3. 更新弹窗内容：
   - 新版本号
   - 更新说明
   - 按钮：
     - 强升：只有「立即更新」按钮，无"不升级"选项
     - 非强升：「立即更新」+「以后再说」两个按钮
4. 点击「立即更新」：
   - 停止所有进程（Electron 主进程 + Python exe）
   - 下载新安装包
   - 安装并重启应用
```

### 13.3 升级粒度

- **整体升级**：Electron + Python exe 打包成一个安装包，整体替换
- 升级期间停止原进程，确保文件可替换

### 13.4 技术方案

- 使用 `electron-updater` 实现自动更新
- 安装包由云端后台提供下载地址

## 十四、异常与容错

### 14.1 WebSocket 断连重连

- 监听过程中闲鱼 WebSocket 断开，自动重连
- 重连策略：最多重试 3 次，间隔分别为 5s、10s、15s
- 3 次都失败 → 停止重连，该账号监听状态标记为"连接断开"

### 14.2 Cookie 过期自动检测

- 监听过程中检测到 Cookie 失效（接口返回 401 等）
- 自动停止该账号监听，标记为失效
- 弹窗提示用户"Cookie 已失效"（弹窗只有提示，不提供重新输入入口，用户自行去账号管理页处理）

### 14.3 消息发送失败重试

- 云端下发回复指令，本机调用闲鱼接口发送失败时
- 自动重试 3 次，每次间隔 2-3 秒随机
- 3 次都失败 → 上报发送失败状态到云端，不再重试

### 14.4 Python 进程崩溃自愈

- Python exe 进程异常退出时，Electron 主进程自动拉起
- 连续崩溃超过 3 次 → 弹窗提示用户"本地服务异常，请重启应用"

### 14.5 云端服务不可用处理

- 本机上报消息、调云端接口失败时
- 自动重试 3 次，间隔 2-3 秒随机
- 3 次都失败 → 弹窗提示"云端服务暂不可用，仅监听不回复"
- 云端恢复后自动继续正常流程，不丢消息

### 14.6 登录 token 运行中过期

- 运行过程中调云端接口返回 401（管理后台登录 token 过期）
- 自动跳转登录页，要求重新登录
- 不自动重新登录，需用户手动输入账号密码

### 14.7 Python 进程启动失败

- Electron 启动时拉起 Python exe 失败
- 自动重试 2 次，间隔 2 秒
- 2 次都失败 → 弹窗提示"本地服务启动失败，请联系管理员"
- 弹窗确认后退出应用

### 14.8 授权校验（运行时定时检查）

- 应用运行中，每小时调一次授权校验接口
- 校验结果：
  - 授权有效 → 继续正常运行
  - 授权过期/无权限 → 停止所有监听，弹窗提示"授权已过期"，应用冻结，只能点退出
  - 云端接口不可用 → 停止所有监听，弹窗提示"服务器异常，请联系管理员"，应用冻结

## 十六、消息合并滑动窗口

- 同一买家 + 同一商品，5 秒内的多条消息合并成一条，再提交到云端 AI 对话
- 滑动窗口时长为本地配置项，默认 5 秒，可修改
- 合并规则：按时间顺序拼接消息内容，保留原始消息列表
- 图文合并：同一窗口内的文字和图片消息合并为一条，一起传给多模态模型
- 云端返回回复后，本机等待 1-2 秒随机延迟再发送（模拟真人回复节奏）

---

## 十七、日志轮转

- 本地日志文件自动轮转
- 单文件大小上限：10MB
- 最多保留 5 个历史日志文件
- 超过上限自动删除最旧的日志文件

---

## 十八、本地配置说明

本机 SQLite 存储两类数据：

1. **cookie 列表**：存储已添加的闲鱼账号凭证（Cookie、闲鱼 ID、昵称、备注、是否有效、监听状态、创建时间）
2. **配置项（通用 key-value）**：
   - 最大监听数（默认 3）
   - 登录 token（管理后台登录后的凭证，供 Electron 和 Python 两端共用）
   - 消息合并滑动窗口时长（默认 5 秒）

> 云端后台地址为打包时写死，不存本地配置。

## 十九、安全规范

| 项 | 要求 |
|----|------|
| 闲鱼 Cookie | 仅存本地，加密存储，永不上传云端 |
| 本地 HTTP 服务 | 仅绑定 127.0.0.1，禁止监听 0.0.0.0 |
| 本机与云端通信 | 携带登录 token 鉴权 |
| 消息发送 | 强制间隔限流，模拟真人行为 |

## 二十、验收标准

| 编号 | 验收项 | 判定标准 |
|------|--------|----------|
| A1 | 单入口 | 只安装/启动一个应用即可完成全部操作 |
| A2 | 登录门槛 | 未登录管理后台时，无法进入主界面 |
| A3 | 管理系统布局 | 左侧菜单 + 右侧内容区，四个菜单项可正常切换 |
| A4 | 多账号管理 | 支持添加、删除、查看多个闲鱼账号 cookie |
| A5 | Cookie 脱敏 | 列表不显示完整 cookie，点详情才看完整 |
| A6 | 监听并发控制 | 最多同时监听 3 个账号，超限提示 |
| A7 | Cookie 有效性 | 点开始监听时自动验证 cookie，失败则更新状态 |
| A8 | 商品同步 | 手动触发全量同步商品到云端 |
| A9 | 消息路由 | 消息上报时携带商品 ID 和买家 ID，云端正确匹配 |
| A10 | Cookie 安全 | 闲鱼 Cookie 不出本机，云端零接触 |
| A11 | 账号去重 | 同一闲鱼账号不能重复添加 |
| A12 | 云端管理页 | 内嵌 WebView 可正常访问云端管理后台 |
| A13 | 日志页 | 可查看本地运行日志，支持筛选和导出 |
| A14 | 自动升级 | 启动时自动检查更新，设置页可手动检查 |
| A15 | 强升策略 | 强升版本无"以后再说"按钮，必须更新 |
| A16 | 整体升级 | 升级期间停止原进程，整体替换安装包 |
| A17 | WS 断连重连 | 监听中断线自动重连 3 次（5s/10s/15s），失败后标记状态 |
| A18 | Cookie 过期提示 | 监听中 cookie 失效自动停止监听并弹窗提示 |
| A19 | 发送失败重试 | 消息发送失败自动重试 3 次（2-3s 随机间隔） |
| A20 | 进程崩溃自愈 | Python 进程崩溃后自动拉起，连续 3 次崩溃提示用户 |
| A21 | 云端不可用处理 | 云端接口连续失败 3 次后弹窗提示，仅监听不回复 |
| A22 | 系统托盘 | 关闭窗口最小化到托盘，右键菜单可打开/退出 |
| A23 | 消息合并滑动窗口 | 同一买家同一商品 5s 内消息合并后再提交云端 |
