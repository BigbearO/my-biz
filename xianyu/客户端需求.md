# 闲鱼自动回复系统 客户端需求规格说明书

> 版本：v3.2 ｜ 日期：2026-09-21 ｜ 状态：需求确认
> 关联文档：《技术方案.md》（架构与表结构设计）、《云端需求.md》（云端管理后台）

---

## 一、项目概述

### 1.1 项目目标

基于大模型实现闲鱼消息智能自动回复，配套商品管理、提示词管理、模型管理能力。采用**「本地监听代理 + 云端管理后台」分离架构**，在保证闲鱼账号凭证安全的前提下，实现 Web 化统一配置管理。

### 1.2 风险提示

- 闲鱼官方禁止第三方逆向工具、自动应答脚本，本方案仅用于技术研究，使用存在账号封禁风险
- 严禁用于商业用途、多账号批量运营
- 开源逆向 SDK 存在协议升级失效的可能，需持续维护适配

### 1.3 核心设计原则

| 原则 | 说明 |
|------|------|
| **敏感凭证本地化** | 闲鱼 Cookie 仅存本地，加密存储，永不离机 |
| **业务配置云端化** | 商品、提示词、模型配置统一云端管理 |
| **风险隔离原则** | 闲鱼交互逻辑与业务管理逻辑彻底分离 |
| **单入口体验** | Electron 统一入口，用户只启动一个应用 |

## 二、整体架构

```
Electron 桌面应用（单入口，唯一用户感知）
├── Vue 渲染层
│   ├── Tab1: 管理后台登录 → cookie 列表页
│   ├── Tab2: 商品/提示词/模型管理（云端 WebView 内嵌）
│   └── Tab3: 日志
└── 主进程
    └── 守护 Python exe（本地服务，仅绑定 127.0.0.1）
        ├── 本地 SQLite 数据库
        ├── 闲鱼 WebSocket 监听
        └── 消息收发 HTTP 接口
```

---

## 三、启动流程

```
1. 打开 Electron 应用
2. 调云端后台接口，检查登录态
3. 401（未登录）→ 跳转管理系统登录页
4. 登录成功 → 保存登录 token → 进入 cookie 列表页
```

> 说明：第一道门槛是**管理后台账号**，不是闲鱼 Cookie。登录成功后拿到的 token 存储在本机，供 Electron 和 Python 两端共用。

## 四、cookie 列表页

### 4.1 页面布局

- 顶部：「添加账号」按钮
- 主体：表格分页展示
- 表格列：闲鱼 ID、闲鱼昵称、是否有效、监听状态、创建时间、备注、操作
- Cookie 本身不在列表列显示

### 4.2 操作列

| 按钮 | 说明 |
|------|------|
| 开始监听 / 停止监听 | 切换监听状态 |
| 详情 | 弹窗查看完整 cookie（默认脱敏 `***`，点击显示完整） |
| 删除 | 删除该条 cookie 记录 |

### 4.3 状态展示

| 状态字段 | 展示方式 |
|----------|----------|
| 是否有效 | 绿色对勾 = 有效，灰色叉 = 失效 |
| 监听状态 | 绿色"监听中" / 灰色"未监听" |

## 五、添加账号流程

1. 点击「添加账号」按钮
2. 弹出对话框，包含：
   - Cookie 输入框（多行粘贴），一次只输入一个
   - 备注输入框
3. 点击「确认」
4. 本地调闲鱼接口验证 Cookie 有效性
5. 验证通过 → 自动拉取闲鱼 ID、闲鱼昵称
6. 检查该闲鱼 ID 是否已存在
   - 已存在 → 提示"该账号已添加，请勿重复添加"
   - 不存在 → 连同备注一起存入本地数据库
7. 验证失败 → 提示错误信息，不存入

## 六、监听控制

### 6.1 开始监听逻辑

点击某条记录的「开始监听」按钮时：

```
1. 查询当前正在监听的账号数量
2. 判断是否已达最大监听数（配置项，默认 3）
   - 已达上限 → 提示"已达上限，请先停止其他账号"，不执行操作
   - 未达上限 → 继续
3. 启动该账号的 WebSocket 监听
4. 验证 Cookie 有效性，更新是否有效字段
   - 验证通过 → 标记为有效
   - 验证失败 → 标记为失效，提示错误
5. 更新监听状态为"监听中"
```

> 约束：同一个闲鱼账号只能有一条 cookie 记录，因此同一账号只会有一个监听实例，不存在重复监听问题。

### 6.2 停止监听逻辑

点击「停止监听」时：

1. 断开该账号的 WebSocket 连接
2. 更新监听状态为"未监听"

### 6.3 并发限制说明

- 同一时间最多监听 **3 个**闲鱼账号
- 超过时不自动切换、不排队，直接提示用户手动停止其他账号
- 最大监听数为本地配置项，可修改

## 七、消息处理流程

```
买家发送消息
    ↓
本机 WebSocket 收到事件
    ↓
提取字段：
  - 商品 ID（item_id）
  - 买家 ID（buyer_id）
  - 会话 ID（session_id）
  - 消息内容（message）
    ↓
推送到云端管理后台（携带上述全部字段 + 登录 token）
    ↓
云端：
  1. 根据商品 ID 匹配商品库
  2. 加载商品上的提示词
  3. 调用大模型生成回复
    ↓
下发回复指令到本机
    ↓
本机调用闲鱼接口发送消息
```

> 说明：无人工审核环节，AI 生成后直接下发发送。

## 八、商品同步

### 8.1 功能说明

- 每个 cookie 详情页有「同步商品」按钮
- 点击后本机调闲鱼接口，**全量拉取**该账号下所有商品
- 拉取到的全部数据推送到云端后台存储
- 云端用于后续消息回复时的商品上下文匹配

### 8.2 同步字段

商品 ID、商品标题、商品描述、价格、库存状态（闲鱼接口返回什么就推什么，不做过滤）

## 九、本地配置说明

本机 SQLite 存储两类数据：

1. **cookie 列表**：存储已添加的闲鱼账号凭证（Cookie、闲鱼 ID、昵称、备注、是否有效、监听状态、创建时间）
2. **配置项（通用 key-value）**：
   - 最大监听数（默认 3）
   - 登录 token（管理后台登录后的凭证，供 Electron 和 Python 两端共用）

> 云端后台地址为打包时写死，不存本地配置。

## 十、安全规范

| 项 | 要求 |
|----|------|
| 闲鱼 Cookie | 仅存本地，加密存储，永不上传云端 |
| 本地 HTTP 服务 | 仅绑定 127.0.0.1，禁止监听 0.0.0.0 |
| 本机与云端通信 | 携带登录 token 鉴权 |
| 消息发送 | 强制间隔限流，模拟真人行为 |

---

## 十一、验收标准

| 编号 | 验收项 | 判定标准 |
|------|--------|----------|
| A1 | 单入口 | 只安装/启动一个应用即可完成全部操作 |
| A2 | 登录门槛 | 未登录管理后台时，无法访问 cookie 列表 |
| A3 | 多账号管理 | 支持添加、删除、查看多个闲鱼账号 cookie |
| A4 | Cookie 脱敏 | 列表不显示完整 cookie，点详情才看完整 |
| A5 | 监听并发控制 | 最多同时监听 3 个账号，超限提示 |
| A6 | Cookie 有效性 | 点开始监听时自动验证 cookie，失败则更新状态 |
| A7 | 商品同步 | 手动触发全量同步商品到云端 |
| A8 | 消息路由 | 消息上报时携带商品 ID 和买家 ID，云端正确匹配 |
| A9 | Cookie 安全 | 闲鱼 Cookie 不出本机，云端零接触 |
| A10 | 账号去重 | 同一闲鱼账号不能重复添加 |
