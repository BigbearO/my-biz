# 闲鱼自动回复系统 技术方案

> 版本：v1.0 ｜ 日期：2026-09-20 ｜ 状态：方案设计

---

## 一、项目概述

### 1.1 项目目标

基于大模型实现闲鱼消息智能自动回复，配套**商品管理、提示词管理、模型管理**三大管理能力。采用**「本地监听代理 + 云端管理后台」分离架构**，在保证闲鱼账号凭证安全的前提下，实现 Web 化统一配置管理。

### 1.2 风险提示

- 闲鱼官方禁止第三方逆向工具、自动应答脚本，本方案仅用于技术研究，使用存在账号封禁风险
- 严禁用于商业用途、多账号批量运营
- 开源逆向 SDK 存在协议升级失效的可能，需持续维护适配

### 1.3 核心设计原则

| 原则 | 说明 |
|------|------|
| **敏感凭证本地化** | 闲鱼登录凭证仅存本地，永不离机 |
| **业务配置云端化** | 商品、提示词、模型配置统一云端管理 |
| **风险隔离原则** | 闲鱼交互逻辑与业务管理逻辑彻底分离 |
| **最小权限原则** | 服务端不持有任何闲鱼账号操作能力 |

---

## 二、整体架构设计

采用双层分离架构，将高风险的闲鱼平台交互全部锁定在本地，云端仅负责业务管理与大模型调度。

### 2.1 架构分层

**1. 本地监听代理层（本机运行）**

- 负责闲鱼侧所有 IO：消息监听、消息发送、登录态维护
- 唯一持有闲鱼登录凭证，不存储业务配置数据
- 仅提供本机环回 HTTP 接口，不暴露公网

**2. Web 管理服务层（云端部署）**

- 负责业务管理：商品、提示词、模型、对话记录、大模型调度
- 不持有任何闲鱼登录凭证，仅管理系统自身鉴权体系
- 提供 Web 管理后台，支持多终端浏览器访问

### 2.2 通信机制

- 双向 HTTP 通信，携带系统级 API Key 鉴权
- 本地 Agent 主动上报消息事件与心跳状态
- Web 服务端下发回复指令与配置更新
- 网络异常时本地内置重试队列，保证消息不丢失

## 三、本地监听代理模块（xianyu-local-agent）

### 3.1 模块定位

独立运行在用户本机的后台进程，是闲鱼平台与管理系统之间的唯一隔离层。所有闲鱼平台交互均在此模块完成，云端服务不直接接触闲鱼协议。

### 3.2 职责边界

✅ **负责**

- 闲鱼 Token 手动输入、验证、加密存储与登录态维护
- WebSocket 实时监听闲鱼 IM 消息
- 解析消息关联的商品 ID、会话信息
- 向 Web 后台推送消息事件与运行状态
- 接收 Web 后台指令，调用 SDK 发送闲鱼消息
- 本地心跳保活、断线重连、异常告警

❌ **不负责**

- 不存储商品库、提示词模板、模型密钥等业务配置
- 不直接调用大模型生成回复
- 不提供公网访问接口
- 不持久化对话记录

### 3.3 功能清单

#### 3.3.1 登录凭证管理

- 提供本地页面 Token 多行输入框，支持手动粘贴闲鱼 Cookie/Token（不做扫码）
- 调用闲鱼用户信息接口验证 Token 有效性
- 基于机器标识的对称加密，磁盘仅存储密文
- 定时校验登录态，失效触发告警上报，不上传凭证本身
- 支持一键清空本地凭证

#### 3.3.2 消息监听

- 基于开源 Python 逆向 SDK 建立 WebSocket 长连接
- 监听文本消息、图片消息、会话系统事件
- 提取会话 ID、买家 ID、商品 ID、消息内容、时间戳
- 消息去重、防抖处理，避免重复上报

#### 3.3.3 消息发送

- 暴露本机环回 HTTP 接口接收发送指令
- 调用逆向 SDK 执行消息发送
- 发送频率限流 + 随机延迟，模拟真人行为
- 返回发送成功 / 失败状态

#### 3.3.4 状态与心跳

- 定时向 Web 后台上报心跳：在线状态、登录状态、WebSocket 连接状态
- 异常事件主动上报：登录失效、连接断开、SDK 错误

#### 3.3.5 本地管理页面

- 本机访问地址：`http://127.0.0.1:8000`
- Token 输入与验证、登录状态实时展示
- Web 后台地址、Agent 凭证配置
- 运行日志查看、手动重连控制

### 3.4 技术栈

| 类别 | 选型 | 说明 |
|------|------|------|
| 运行环境 | Python 3.11+ | 兼容主流开源逆向 SDK |
| Web 框架 | FastAPI | 异步高性能，提供本机 HTTP 接口 |
| 异步框架 | asyncio | 适配 WebSocket 异步事件模型 |
| 闲鱼交互 | 开源 Python 逆向 SDK | 封装闲鱼协议与消息收发 |
| 本地存储 | JSON 文件 | 仅存加密凭证与本地配置 |
| 加密 | cryptography | 对称加密存储闲鱼 Token |
| HTTP 客户端 | httpx（异步） | 向 Web 后台推送事件 |
| 日志 | loguru | 本地日志输出与轮转 |
| 进程守护 | NSSM（Windows） | 后台常驻与崩溃自动重启 |

## 四、Web 管理后台模块

### 4.1 模块定位

业务管理中枢，统一维护所有业务配置与数据，调度大模型生成回复。完全不接触任何闲鱼登录凭证，仅管理系统内部设备与业务数据。

### 4.2 职责边界

✅ **负责**

- Agent 设备管理与鉴权
- 商品信息 CRUD 与分类管理
- 提示词模板管理、变量渲染
- 大模型配置管理与调用调度
- 对话记录存储与查询
- 人工审核回复队列
- 运行状态监控与统计

❌ **不负责**

- 不存储、不接触闲鱼登录凭证
- 不直接与闲鱼平台交互

### 4.3 功能清单

#### 4.3.1 Agent 管理

- Agent 实例创建、删除、禁用
- 自动生成 Agent ID 与 API Key
- Agent 在线状态、登录状态实时展示
- 按 Agent 分配商品库与配置权限

#### 4.3.2 商品管理

- 商品信息录入：标题、描述、价格、闲鱼商品 ID
- 商品与提示词模板绑定
- 按 Agent 分配商品可见范围

#### 4.3.3 提示词管理

- 提示词模板增删改查
- 变量占位符支持：`{{商品标题}}`、`{{商品描述}}`、`{{买家提问}}`
- 模板版本管理与一键切换

#### 4.3.4 模型管理

- 多模型配置：支持所有兼容 OpenAI 接口的模型
- API 密钥、接口地址、参数配置（温度、最大 Token）
- 模型路由与降级策略

#### 4.3.5 对话与审核

- 全量对话记录存储与检索
- AI 生成回复人工审核队列
- 支持人工修改回复后下发
- 发送状态全链路追踪

#### 4.3.6 统计与监控

- 消息量、回复率统计
- Agent 运行状态监控告警
- Token 消耗统计

## 五、双凭证体系与存储边界（核心设计）

### 5.1 两套独立凭证体系

彻底分离两类凭证，从根源上解决安全与管理的平衡问题。

| 凭证类型 | 作用 | 持有方 | 敏感等级 | 泄露后果 |
|----------|------|--------|----------|----------|
| 闲鱼凭证（Token/Cookie） | 登录闲鱼账号、收发消息 | 仅本地 Agent | 极高 | 账号被盗、恶意操作、封禁 |
| 系统鉴权凭证（Agent ID + API Key） | 标识 Agent 设备、校验内部通信合法性 | 本地 Agent + Web 后台 | 中 | 仅影响系统内部通信，不波及闲鱼账号 |

> 核心结论：Web 管理后台**不需要也不应该存储闲鱼 Token**。后台管理的是「Agent 设备实例」而非「闲鱼账号」，通过 Agent 注册制（agent_id + api_key）实现全部管理能力。

### 5.2 数据存储边界

严格划分本地与服务端的存储范围，敏感数据绝不越界。

| 数据类别 | 存储位置 | 说明 |
|----------|----------|------|
| 闲鱼登录凭证 | 仅本地 | 加密存储，绝对不上传服务端 |
| Agent ID + API Key | 本地 + 服务端 | 系统内部身份标识，可安全存储 |
| 商品库、提示词模板 | 仅服务端 | 统一管理，本地启动后拉取缓存 |
| 模型配置、大模型 API 密钥 | 仅服务端 | 密钥统一托管，本地不可见 |
| 对话记录、消息日志 | 仅服务端 | 本地上报，云端持久化 |
| Agent 运行参数（端口、日志级别） | 仅本地 | 本机运行配置 |

### 5.3 Token 本地加密方案

1. **密钥生成**：基于本机硬件标识 + 用户自定义主密钥派生加密密钥
2. **存储方式**：磁盘仅保存加密后的密文，启动时解密加载到内存
3. **使用原则**：仅内存中明文使用，进程退出自动释放
4. **验证逻辑**：输入 Token 后本地调用闲鱼接口验证，验证通过才加密存储

### 5.4 Agent 注册机制（服务端零凭证管理）

1. 在 Web 后台手动创建 Agent 实例，生成唯一 `agent_id` 和对应 `api_key`
2. 将两者填入本地 Agent 配置文件
3. 此后所有双向通信携带 `api_key` 鉴权，服务端通过 `agent_id` 识别实例
4. 多账号扩展：每个闲鱼账号 = 一个本地 Agent 进程 = 一个 `agent_id`，Token 全部散落在各本地机器，服务端零凭证风险

## 六、完整业务数据流

### 6.1 启动初始化流程

```
1. 本地Agent启动
2. 读取本地加密文件，解密得到闲鱼Token
3. 建立闲鱼WebSocket连接，验证登录态
4. 使用Agent ID + API Key向Web后台鉴权
5. 拉取对应商品库、提示词、模型配置到本地缓存
6. 开始监听消息，定时上报心跳
```

### 6.2 消息接收上报流程

```
1. 买家发送消息 → 闲鱼WebSocket推送
2. 本地Agent解析消息，提取商品ID、会话信息
3. 组装标准消息事件结构体
4. 携带API Key鉴权，上报至Web后台
5. Web后台落库对话记录
```

### 6.3 AI 回复生成与下发流程

```
1. Web后台根据商品ID匹配商品信息
2. 加载绑定的提示词模板，变量渲染生成完整Prompt
3. 调用配置的大模型生成回复内容
4. 进入人工审核队列（可选）
5. 审核通过后，调用对应Agent的本机HTTP接口
6. 携带API Key鉴权，下发回复指令
7. 本地Agent收到指令，调用闲鱼SDK发送消息
8. 返回发送结果，更新对话状态
```

## 八、安全与风控规范

### 8.1 系统安全

- 本地 Agent 接口仅绑定 `127.0.0.1`，禁止监听 `0.0.0.0`
- 所有双向通信必须携带 API Key 鉴权，防止伪造请求
- 大模型密钥仅存服务端，统一管理调用
- 定期轮换系统 API Key

### 8.2 账号安全

- 闲鱼 Token 永不离机，服务端零接触
- 本地磁盘加密存储，防止文件泄露
- 登录失效仅上报状态，不上传凭证内容
- 支持一键清空本地凭证

### 8.3 平台风控

- 消息发送强制间隔限流，禁止秒回
- 默认人工审核模式，不开启全自动发送
- 模拟真人回复时长随机延迟
- 异常流量自动熔断暂停发送
