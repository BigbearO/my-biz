# 需求-客户端-监听控制

## 一、功能概述（总）

### 1.1 功能定位

监听控制负责单个闲鱼账号 WebSocket 监听的启动与停止，并通过最大监听数约束并发规模，是账号产生消息事件的总开关，解决"多账号监听并发可控"的问题。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | 开始监听 | 校验并发上限 → 启动 WebSocket 监听 → 验证 Cookie 有效性 → 更新监听状态 |
| F2 | 停止监听 | 断开该账号的 WebSocket 连接，更新监听状态 |
| F3 | 并发限制 | 同一时间最多监听 3 个账号（本地配置项），超限直接提示 |
| F4 | 分布式监听占用 ★ | 同一闲鱼账号**同一时刻只允许一台设备监听**：开始监听前向云端申请账号级占用租约（Redis），已被其他设备占用则拒绝启动 |

### 1.3 功能边界

- 监听运行中的异常（WebSocket 断连重连、Cookie 过期自动检测）归 [需求-客户端-异常与容错](需求-客户端-异常与容错.md)
- 监听状态、是否有效字段在账号管理列表的展示归 [需求-客户端-账号管理](需求-客户端-账号管理.md)
- 最大监听数、滑动窗口时长等配置的本地存储归 [需求-客户端-安全与本地配置](需求-客户端-安全与本地配置.md)
- 重启后不自动恢复监听的规则归 [需求-客户端-应用框架与启动登录](需求-客户端-应用框架与启动登录.md)

## 二、功能详述（分）

### 2.1 开始监听逻辑

点击某条记录的「开始监听」按钮时：

```
1. 查询当前正在监听的账号数量
2. 判断是否已达最大监听数（配置项，默认 3）
   - 已达上限 → 提示"已达上限，请先停止其他账号"，不执行操作
   - 未达上限 → 继续
3. ★向云端申请账号级**监听占用**（Redis 分布式租约，见 [需求-云端-账号管理](需求-云端-账号管理.md) §2.4）
   - 申请成功 → 继续（监听期间每 30s 续期一次）
   - 已被其他设备占用 → 提示"该账号已在其他设备监听，请先在原设备停止监听"，**不启动**
   - 云端接口不可用 → **降级放行**（记 WARN），不阻断监听
4. 启动该账号的 WebSocket 监听
5. 验证 Cookie 有效性，更新是否有效字段
   - 验证通过 → 标记为有效
   - 验证失败 → 标记为失效，提示错误，并**释放云端监听占用**
6. 更新监听状态为"监听中"
```

> 约束：同一个闲鱼账号只能有一条 cookie 记录，因此同一账号只会有一个监听实例，不存在重复监听问题。

### 2.2 停止监听逻辑

点击「停止监听」时：

1. 断开该账号的 WebSocket 连接
2. ★释放云端监听占用（`release`），并停止续期
3. 更新监听状态为"未监听"

### 2.3 并发限制说明

- 同一时间最多监听 **3 个**闲鱼账号
- 超过时不自动切换、不排队，直接提示用户手动停止其他账号
- 最大监听数为本地配置项，可修改

## 三、业务规则与约束

- 同一时间最多监听 **3 个**闲鱼账号；最大监听数为本地配置项，默认 3，可修改
- 超过上限时不自动切换、不排队，直接提示用户手动停止其他账号
- 开始监听时自动验证 Cookie 有效性并回写"是否有效"字段：验证通过标记为有效，验证失败标记为失效并提示错误
- 同一个闲鱼账号在本机只能有一条 cookie 记录，因此本机不会出现重复监听实例
- ★**跨设备去重复监听**：同一闲鱼账号**同一时刻只允许一台设备监听**——开始监听前必须向云端申请账号级占用租约（Redis，租约 90s），监听期间每 30s 续期，停止监听 / 退出应用时释放；进程崩溃由 TTL 兜底（90s 后自动释放）；**云端接口不可用时降级放行**，不阻断监听（见 [需求-云端-账号管理](需求-云端-账号管理.md) §2.4）

## 四、异常与边界场景

| 场景 | 处理要求 |
|------|----------|
| 已达最大监听数时点开始监听 | 提示"已达上限，请先停止其他账号"，不执行操作 |
| 该账号已在其他设备监听（云端占用申请返回 409） | 提示"该账号已在其他设备监听，请先在原设备停止监听"，**不启动** |
| 云端监听占用接口不可用 | **降级放行**（记 WARN），正常启动监听，不阻断用户 |
| 开始监听时 Cookie 验证失败 | 标记为失效，提示错误 |
| 监听过程中 WebSocket 断连或 Cookie 失效 | 不在本文件处理，归 [需求-客户端-异常与容错](需求-客户端-异常与容错.md) |

## 五、验收标准

| 编号 | 验收项 | 判定标准 |
|------|--------|----------|
| A6 | 监听并发控制 | 最多同时监听 3 个账号，超限提示；同一账号不允许在两台设备上同时监听（云端 Redis 占用校验） |
| A7 | Cookie 有效性 | 点开始监听时自动验证 cookie，失败则更新状态 |
