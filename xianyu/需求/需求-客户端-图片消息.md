> 关联：[技术方案-客户端-图片处理](../技术方案/技术方案-客户端-图片处理.md)

## 一、功能概述（总）

### 1.1 功能定位

图片消息处理负责把买家发来的图片消息接入自动回复链路：本机下载图片并统一转为 PNG，先上传云端换取图片访问 URL，再随消息上报该 URL（不传 base64），使云端多模态模型可以基于图片内容生成回复。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | 图片下载与格式统一 | 本机用闲鱼 Cookie 下载图片，统一转为 PNG |
| F2 | 上传云端换取 URL | 先上传云端（POST /api/ai/image）获取图片访问 URL |
| F3 | 随消息上报 URL | 随消息一起上报该 URL，不传 base64 |
| F4 | 图文合并 | 同一滑动窗口内的文字和图片消息合并为一条，一起传给多模态模型 |

### 1.3 功能边界

- 图片消息在整体消息流程中的位置（去重、滑动窗口合并、随机延迟时机）归 [需求-客户端-消息自动回复](需求-客户端-消息自动回复.md)
- 图片在云端的存储（服务器本地磁盘）与图片访问能力由云端提供
- 图片体积校验在云端上传接口实现，上限走云端配置，客户端不做体积校验

## 二、功能详述（分）

### 2.1 图片消息处理步骤

源文档 §八 消息处理流程中的图片消息处理步骤（逐字收录）：

```
图片消息处理：
  - 本机用闲鱼 Cookie 下载图片，转为 PNG
  - 先上传云端（POST /api/ai/image）获取图片访问 URL
  - 随消息一起上报该 URL（不传 base64）；云端存服务器本地磁盘并提供图片访问
  - 文本消息直接上报
```

### 2.2 图文合并

同一窗口内的文字和图片消息合并为一条，一起传给多模态模型。滑动窗口机制（同一买家 + 同一商品，默认 5 秒）见 [需求-客户端-消息自动回复](需求-客户端-消息自动回复.md)。

## 三、业务规则与约束

- 下载图片使用本机保存的闲鱼 Cookie
- 本机统一转 PNG 后上传，格式统一在客户端完成
- 上传接口：POST /api/ai/image，上传后获取图片访问 URL
- 上报消息时携带图片访问 URL，不传 base64
- 图片体积上限不在客户端校验，体积校验在云端上传接口，上限走云端配置（参见《客户端监听.md》§3.8.1：[../客户端监听.md](../客户端监听.md)）
- 文本消息不经过图片处理步骤，直接上报
- 图文合并后一起传给多模态模型

## 四、异常与边界场景

| 场景 | 处理要求 |
|------|----------|
| 消息类型为 text | 不走图片处理，直接上报 |
| 消息类型为 image | 下载转 PNG → 上传云端（POST /api/ai/image）拿 URL → 随消息上报该 URL |
| 图片体积超限 | 由云端上传接口校验拦截，上限走云端配置（见《客户端监听.md》§3.8.1） |
| 同一窗口内图文混合 | 合并为一条，一起传给多模态模型 |

## 五、验收标准

| 编号 | 验收项 | 判定标准 |

| A28 | 图片消息处理 | 本机下载闲鱼图片转 PNG，先上传云端（POST /api/ai/image）拿 URL，再随消息上报该 URL（不传 base64） |
| A32 | 图片格式统一 | 本机统一转 PNG 后上传；体积校验在云端上传接口（上限走云端配置，见《客户端监听.md》§3.8.1） |
| A36 | 图文合并 | 同一窗口内图文消息合并后一起传给多模态模型 |
