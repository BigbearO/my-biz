## 一、功能概述（总）

### 1.1 功能定位

异常与容错定义客户端运行期遇到各类故障时的自愈与降级行为，覆盖 WebSocket 断连、Cookie 过期、消息发送失败、Python 进程崩溃、云端服务不可用、登录 token 过期、Python 进程启动失败、授权运行时校验八类场景，保证故障下行为可预期、可恢复、可感知。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | WebSocket 断连重连 | 自动重连最多 3 次（5s/10s/15s），失败后标记"连接断开" |
| F2 | Cookie 过期自动检测 | 自动停止该账号监听、标记失效并弹窗提示 |
| F3 | 消息发送失败重试 | 自动重试 3 次（2-3 秒随机间隔），失败仅记录本地日志 |
| F4 | Python 进程崩溃自愈 | Electron 主进程自动拉起，连续崩溃超过 3 次提示用户 |
| F5 | 云端服务不可用处理 | 重试 3 次后提示"仅监听不回复"，云端恢复后自动继续且不丢消息 |
| F6 | 登录 token 运行中过期 | 401 时自动跳转登录页，不自动重新登录 |
| F7 | Python 进程启动失败 | 自动重试 2 次（间隔 2 秒），失败弹窗提示并退出应用 |
| F8 | 授权校验（运行时定时检查） | 每小时校验一次，授权过期 → 冻结；接口非 200 时重试 3 次，3 次后仍非 200 判定"不可用" → 冻结 |

### 1.3 功能边界

- 启动阶段的登录态检查与授权校验（第一道门槛）归 [需求-客户端-应用框架与启动登录](需求-客户端-应用框架与启动登录.md)；本文件覆盖运行中的 401 跳转与每小时授权定时检查
- 正常消息处理流程归 [需求-客户端-消息自动回复](需求-客户端-消息自动回复.md)，本文件只定义其失败重试与降级
- 监听启停的正常操作归 [需求-客户端-监听控制](需求-客户端-监听控制.md)
- 授权体系本身的设计归云端与 [需求-客户端-安全与本地配置](需求-客户端-安全与本地配置.md)

## 二、功能详述（分）

### 2.1 WebSocket 断连重连

- 监听过程中闲鱼 WebSocket 断开，自动重连
- 重连策略：最多重试 3 次，间隔分别为 5s、10s、15s
- 3 次都失败 → 停止重连，该账号监听状态标记为"连接断开"

### 2.2 Cookie 过期自动检测

- 监听过程中检测到 Cookie 失效（接口返回 401 等）
- 自动停止该账号监听，标记为失效
- 弹窗提示用户"Cookie 已失效"（弹窗只有提示，不提供重新输入入口，用户自行去账号管理页处理）

### 2.3 消息发送失败重试

- 云端下发回复指令，本机调用闲鱼接口发送失败时
- 自动重试 3 次，每次间隔 2-3 秒随机
- 3 次都失败 → **仅记录本地日志，不再重试（不上报云端）**

### 2.4 Python 进程崩溃自愈

- Python exe 进程异常退出时，Electron 主进程自动拉起
- 连续崩溃超过 3 次 → 弹窗提示用户"本地服务异常，请重启应用"

### 2.5 云端服务不可用处理

- 本机上报消息、调云端接口**确定性失败**（HTTP 4xx/5xx、业务码明确失败）时
- 自动重试 3 次，间隔 2-3 秒随机
- 3 次都失败 → 弹窗提示"云端服务暂不可用，仅监听不回复"
- **超时 / 连接中断不重试**（属"不确定失败"：服务端可能仍在处理，重试会撞上幂等"处理中"，本轮必然拿不到结果）→ 仅记日志，不进"云端不可用"状态，等下一批消息自然重新请求
- 云端恢复后自动继续正常流程，不丢消息

### 2.6 登录 token 运行中过期

- 运行过程中调云端接口返回 401（管理后台登录 token 过期）
- 自动跳转登录页，要求重新登录
- 不自动重新登录，需用户手动输入账号密码

### 2.7 Python 进程启动失败

- Electron 启动时拉起 Python exe 失败
- 自动重试 2 次，间隔 2 秒
- 2 次都失败 → 弹窗提示"本地服务启动失败，请联系管理员"
- 弹窗确认后退出应用

### 2.8 授权校验（运行时定时检查）

- 应用运行中，每小时调一次授权校验接口
- 校验结果：
  - 授权有效 → 继续正常运行
  - 授权过期/无权限 → 停止所有监听，弹窗提示"授权已过期"，应用冻结，只能点退出
  - 云端接口不可用 → 停止所有监听，弹窗提示"服务器异常，请联系管理员"，应用冻结
- **"接口不可用"的判定**：接口返回非 200（4xx / 5xx / 网络异常 / 超时）时，**先重试 3 次（间隔 2-3 秒随机）**，3 次后仍非 200 才判定为不可用并冻结应用；任一次返回 200 即按正常结果解析。401 不重试，走"跳登录页"分支。
  - 目的：避免一次网络抖动就把应用冻死（每小时一次的校验过于敏感）

## 三、业务规则与约束

重试与阈值参数汇总：

| 场景 | 重试次数 | 重试间隔 | 失败终态 |
|------|----------|----------|----------|
| WebSocket 断连重连 | 最多 3 次 | 5s、10s、15s | 停止重连，监听状态标记为"连接断开" |
| 消息发送失败 | 自动重试 3 次 | 每次 2-3 秒随机 | 仅记录本地日志，不再重试，不上报云端 |
| 云端接口调用失败（确定性 4xx/5xx、业务码失败） | 自动重试 3 次 | 2-3 秒随机 | 弹窗提示，仅监听不回复 |
| 云端接口超时 / 连接中断（不确定失败） | **不重试** | — | 仅记日志，本轮不回复，等下一批消息重新请求 |
| Python 进程崩溃 | — | — | Electron 自动拉起；连续崩溃超过 3 次弹窗提示 |
| Python 进程启动失败 | 自动重试 2 次 | 间隔 2 秒 | 弹窗提示，确认后退出应用 |
| 授权运行时校验 | 每小时 1 次 | 非 200 时重试 3 次（2-3 秒随机） | `data=false`（授权过期）→ 冻结；**重试 3 次仍非 200**（接口不可用）→ 冻结 |

其他约束：

- 消息发送重试失败后不上报云端，只记本地日志
- Cookie 失效弹窗只有提示，不提供重新输入入口，用户自行去账号管理页处理
- token 过期不自动重新登录，需用户手动输入账号密码
- 云端恢复后自动继续正常流程，不丢消息
