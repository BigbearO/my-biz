# 需求-云端-登录与授权校验

> 来源：《云端需求.md》§4.4 授权校验接口；《云端技术方案.md》§3.9 鉴权与授权（需求侧要点）（内容重组收录，原文件保留未动）
> 关联：[技术方案-云端-鉴权与授权](../技术方案/技术方案-云端-鉴权与授权.md)

## 一、功能概述（总）

### 1.1 功能定位

登录与授权校验负责判断登录账号是否有权限继续使用系统：**鉴权**（token 是否有效）由网关统一校验，失败返回 401；**授权**（该用户是否有使用权限、是否在授权期内）由客户端主动调用云端授权校验接口判断。授权校验接口在客户端启动时和运行中定时调用。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|---|---|---|
| 1 | 鉴权（登录态校验） | 除白名单外所有接口必须带 token，网关统一校验，失败返回 HTTP 401 |
| 2 | 授权校验接口 | 客户端主动调用，校验用户授权状态，无效返回 HTTP 403 + 业务码 `40301` |
| 3 | 授权失效处理 | 客户端停止所有监听、弹窗、冻结应用，只允许退出 |

### 1.3 功能边界

- **网关不做业务授权判定**（不引入授权状态查询、不加兜底 filter）；授权是业务语义，由客户端主动调用授权校验接口兜住（启动时 + 运行中每小时）。
- **已签发 token 不做主动失效处理**：不引入服务端 token 黑名单 / 强制下线机制，依赖客户端下一次授权校验兜住。
- 登录、用户管理等基础能力复用 RuoYi 已有功能。
- 客户端侧的鉴权 / 授权处理细节（401 跳登录页、403 冻结应用等）由客户端需求定义，见[客户端需求.md](../客户端需求.md)。

## 二、功能详述（分）

### 2.1 鉴权与授权的区分

| 层次 | 判定对象 | 谁来做 | 失败响应 | 客户端处理 |
|---|---|---|---|---|
| **鉴权**（Authentication） | token 是否有效 / 是否过期 | **网关统一校验**（RuoYi 自带） | HTTP **401** | **删除本地 token + 跳转登录页**，不自动重登 |
| **授权**（Authorization） | 该用户是否有使用权限（是否在授权期内） | **客户端主动调用** | HTTP **403** + 业务码 `40301` | **停止所有监听 + 弹窗 + 冻结应用**，只允许退出 |

> **为什么必须区分**：401 是"没登录 / 登录过期"，**重新登录可解决**；403 是"登录了但没权限"，**重新登录解决不了**，必须联系管理员。两者若混用同一错误码，客户端会出现"跳到登录页—重登—又被拒"的死循环。

### 2.2 授权校验接口

**接口说明**：客户端启动时和运行中定时调用，判断当前登录账号是否有使用权限。

```
客户端调授权校验接口
    携带：登录 token
    ↓
云端：根据 token 找到当前用户
    ↓
校验该用户的授权状态：
  - 有效（在授权期内）→ 返回 success
  - 无效（过期/未授权）→ 返回错误码，客户端冻结应用
```

**接口定义**：

| 接口 | 方法 | 提供方 | 返回 |
|---|---|---|---|
| `/system/auth/access` | GET | `ruoyi-system` | 授权状态：有效 / 过期 / 未授权 |

**客户端调用时机**：

```
1. 应用启动时调用一次
2. 运行中每小时调用一次
```

### 2.3 授权失效的处理时序

```
客户端收到 403 / 40301（授权过期或未授权）
  ├─ 删除本地 token（无权限，留着无意义）
  ├─ 调本地 POST /api/account/stop-all  → 停止所有监听
  ├─ 弹窗"授权已过期"（不提供重新登录入口）
  ├─ 应用冻结，只允许退出
  └─ 不再发起任何云端调用
```

### 2.4 授权校验接口不可用（云端异常）

接口不可用（云端异常）时：停止所有监听 + 弹窗"服务器异常，请联系管理员" + 冻结应用。**用与 403 不同的错误码**（503 类），避免与"授权过期"混淆。

### 2.5 已签发 token 的处理

**决策：用户被禁用 / 授权过期后，已签发的 token 不做主动失效处理。**

| 场景 | 处理 |
|---|---|
| 用户被禁用 / 授权过期 | 客户端在**下一次授权校验**（启动时或每小时）得到无权限 → **删除本地 token** + 停止监听 + 冻结应用 |
| 已签发但仍有效的 token | **不主动失效**，不做特殊处理 |
| 后续若因此出现问题 | 届时再处理（本期不做） |

## 三、业务规则与约束

1. 授权状态直接复用 RuoYi 用户表，后续可扩展为独立的授权管理（到期时间、授权类型等）。
2. 网关只做"认证 + 路由 + 限流"；"授权到期"由客户端每小时主动校验覆盖。
3. 401 与 403 语义必须区分使用：401 重新登录可解决；403 必须联系管理员，两者不得混用同一错误码。

## 四、异常与边界场景

| 场景 | 处理要求 |
|---|---|
| token 无效 / 登录过期（401） | 客户端删除本地 token + 跳转登录页，不自动重登 |
| 授权过期 / 未授权（403 / 40301） | 删除本地 token、停止所有监听、弹窗"授权已过期"（不提供重新登录入口）、应用冻结只允许退出、不再发起任何云端调用 |
| 授权校验接口不可用（云端异常） | 停止所有监听 + 弹窗"服务器异常，请联系管理员" + 冻结应用；使用与 403 不同的错误码（503 类） |
