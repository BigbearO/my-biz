# 需求-云端-登录与授权校验

> 来源：《云端需求.md》§4.4 授权校验接口；《云端技术方案.md》§3.9 鉴权与授权（需求侧要点）（内容重组收录，原文件保留未动）
> 关联：[技术方案-云端-鉴权与授权](../技术方案/技术方案-云端-鉴权与授权.md)

## 一、功能概述（总）

### 1.1 功能定位

登录与授权校验负责判断登录账号是否有权限继续使用系统：**鉴权**（token 是否有效）由网关统一校验，失败返回 401；**授权**（该用户是否有使用权限、是否在授权期内）由客户端主动调用云端授权校验接口判断。授权校验接口在客户端启动时和运行中定时调用。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|---|---|---|
| 1 | 鉴权（登录态校验） | 除白名单外所有接口必须带 token，网关统一校验，失败返回 HTTP 401 |
| 2 | 授权校验接口 | 客户端主动调用，校验用户授权状态，无效返回 HTTP 403 + 业务码 `40301` |
| 3 | 授权失效处理 | 客户端停止所有监听、弹窗、冻结应用，只允许退出 |

### 1.3 功能边界

- **网关不做业务授权判定**（不引入授权状态查询、不加兜底 filter）；授权是业务语义，由客户端主动调用授权校验接口兜住（启动时 + 运行中每小时）。
- **已签发 token 不做主动失效处理**：不引入服务端 token 黑名单 / 强制下线机制，依赖客户端下一次授权校验兜住。
- 登录、用户管理等基础能力复用 RuoYi 已有功能。
- 客户端侧的鉴权 / 授权处理细节（401 跳登录页、403 冻结应用等）由客户端需求定义，见[客户端需求.md](../客户端需求.md)。

## 二、功能详述（分）

### 2.1 鉴权与授权的区分

| 层次 | 判定对象 | 谁来做 | 失败响应 | 客户端处理 |
|---|---|---|---|---|
| **鉴权**（Authentication） | token 是否有效 / 是否过期 | **网关统一校验**（RuoYi 自带） | HTTP **401** | **删除本地 token + 跳转登录页**，不自动重登 |
| **授权**（Authorization） | 该用户是否有使用权限（是否在授权期内） | **客户端主动调用** | HTTP **403** + 业务码 `40301` | **停止所有监听 + 弹窗 + 冻结应用**，只允许退出 |

> **为什么必须区分**：401 是"没登录 / 登录过期"，**重新登录可解决**；403 是"登录了但没权限"，**重新登录解决不了**，必须联系管理员。两者若混用同一错误码，客户端会出现"跳到登录页—重登—又被拒"的死循环。

### 2.2 授权校验接口

**接口说明**：客户端启动时和运行中定时调用，判断当前登录账号是否有使用权限。

```
客户端调授权校验接口
    携带：登录 token
    ↓
云端：根据 token 找到当前用户
    ↓
校验该用户的授权状态：
  - 有效（在授权期内）→ 返回 R<Boolean> data=true
  - 无效（过期/未授权）→ 返回 R<Boolean> data=false，客户端冻结应用
```

**接口定义**：

| 接口 | 方法 | 提供方 | 返回 |
|---|---|---|---|
| `/system/auth/access` | GET | **Java 新业务服务 `ruoyi-goodfish-admin`** ★ | **RuoYi-Cloud-Plus 通用响应体 `R<Boolean>`**：`data=true` 表示有权限（在授权期内），`data=false` 表示无权限（过期 / 未授权） |

> ★**本期实现**：该接口在本版本**恒定返回 `data=true`**（不做真实授权判定），目的是打通客户端「启动时 + 运行中每小时」的校验链路。后续接入真实授权数据（授权到期时间 / 授权类型等）时**接口契约不变**，只替换实现。
>
> 提供方由原 `ruoyi-system` 调整为 Java 业务服务：`ruoyi-system` 只提供通用用户/权限能力，授权到期属本业务语义，后续需自有授权数据，不宜塞进通用系统服务。

返回示例：

```json
// POST 成功（有权限）
{ "code": 200, "msg": "操作成功", "data": true }
// 无权限
{ "code": 200, "msg": "操作成功", "data": false }
```

> 客户端解析通用响应体中的 `data` 布尔值：`false` → 按授权失效处理（见 2.3）。该接口自身不做 401/403 语义，`401`（未登录 / 登录过期）仍由网关统一鉴权返回。

**客户端调用时机**：

```
1. 应用启动时调用一次
2. 运行中每小时调用一次
```

### 2.3 授权失效的处理时序

```
授权校验接口返回 data=false（授权过期或未授权），或业务接口返回 403 / 40301
  ├─ 删除本地 token（无权限，留着无意义）
  ├─ 调本地 POST /api/account/stop-all  → 停止所有监听
  ├─ 弹窗"授权已过期"（不提供重新登录入口）
  ├─ 应用冻结，只允许退出
  └─ 不再发起任何云端调用
```

### 2.4 授权校验接口不可用（云端异常）★判定口径

**"接口不可用"必须重试后才判定，禁止一次网络抖动就冻死应用**：

```
客户端调 /system/auth/access
  ├─ HTTP 200  → 解析 data：true 继续运行；false → 按授权失效处理（见 §2.3 时序）
  ├─ HTTP 401  → 按鉴权处理：删本地 token + 跳登录页（不重试、不冻结）
  └─ 其他非 200（4xx / 5xx / 网络异常 / 超时）→ 重试 3 次，间隔 2-3 秒随机
        ├─ 任一次返回 200 → 正常解析，结束
        └─ 3 次后仍非 200 → 判定"接口不可用"：
               停止所有监听 + 弹窗"服务器异常，请联系管理员" + 冻结应用
```

> **与"授权过期"必须用不同信号区分**：授权过期 = HTTP 200 且 `data=false`；接口不可用 = 重试 3 次后仍非 200（5xx 类）。
>
> 该重试独立于消息流水线的重试策略——流水线对"超时 / 连接中断"不重试，但**授权校验必须重试 3 次**，否则一次抖动就冻结应用（A43 会过于激进）。

### 2.5 已签发 token 的处理

**决策：用户被禁用 / 授权过期后，已签发的 token 不做主动失效处理。**

| 场景 | 处理 |
|---|---|
| 用户被禁用 / 授权过期 | 客户端在**下一次授权校验**（启动时或每小时）得到无权限 → **删除本地 token** + 停止监听 + 冻结应用 |
| 已签发但仍有效的 token | **不主动失效**，不做特殊处理 |
| 后续若因此出现问题 | 届时再处理（本期不做） |

## 三、业务规则与约束

1. **本期 `/system/auth/access` 恒定返回 `data=true`**（不做真实授权判定，由 Java 业务服务 `ruoyi-goodfish-admin` 提供）；授权状态后续扩展为独立的授权管理（到期时间、授权类型等）时**接口契约不变**，只替换实现。
2. 网关只做"认证 + 路由 + 限流"；"授权到期"由客户端每小时主动校验覆盖。
3. 401 与 403 语义必须区分使用：401 重新登录可解决；403 必须联系管理员，两者不得混用同一错误码。

## 四、异常与边界场景

| 场景 | 处理要求 |
|---|---|
| token 无效 / 登录过期（401） | 客户端删除本地 token + 跳转登录页，不自动重登 |
| 授权过期 / 未授权 | 授权校验接口返回 `data=false`（或业务接口返回 403 / 40301）：删除本地 token、停止所有监听、弹窗"授权已过期"（不提供重新登录入口）、应用冻结只允许退出、不再发起任何云端调用 |
| 授权校验接口不可用（云端异常） | 非 200 时**先重试 3 次（间隔 2-3 秒随机）**，3 次后仍非 200 才判定不可用 → 停止所有监听 + 弹窗"服务器异常，请联系管理员" + 冻结应用；与"无权限"用不同的信号区分（重试后仍非 200，而非 `data=false`） |
