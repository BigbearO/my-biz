## 一、功能概述（总）

### 1.1 功能定位

本文件约束客户端的两条底线：一是**本地存什么**——SQLite 存储的数据范围与通用配置项；二是**安全红线**——闲鱼凭证永不出本机、本地服务仅绑定回环地址、通信鉴权与消息发送限流，并收录凭证体系（★**单凭证**：系统侧统一使用管理后台登录 token，Agent ID + API Key 方案已作废）与存储边界的总体设计，解决"凭证安全与配置管理"问题。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | 本地数据存储 | 本机 SQLite 存储两类数据：cookie 列表、通用 key-value 配置项 |
| F2 | 本地配置项 | 最大监听数（默认 3）、登录 token、消息合并滑动窗口时长（默认 5 秒） |
| F3 | 安全规范 | Cookie 仅存本地加密存储、本地 HTTP 仅绑定 127.0.0.1、通信携带 token 鉴权、发送强制间隔限流 |
| F4 | 单凭证体系 | 闲鱼凭证（Cookie）仅本地持有；系统侧鉴权统一使用**管理后台登录 token**，不再引入独立的 Agent ID + API Key |
| F5 | 存储边界 | 本地与服务端的存储范围严格划分，敏感数据绝不越界 |
| F6 | 凭证本地加密 | 硬件标识派生密钥，磁盘只存密文，仅内存明文使用 |

### 1.3 功能边界

- 最大监听数的业务使用规则归 [需求-客户端-监听控制](需求-客户端-监听控制.md)，滑动窗口时长的业务使用规则归 [需求-客户端-消息自动回复](需求-客户端-消息自动回复.md)，本文件只定义其配置存储

- 云端侧存储（商品库、提示词模板、模型配置与大模型密钥、对话记录）归云端技术方案
- Agent 注册的后台操作（Web 后台创建 Agent 实例）归云端管理后台

## 二、功能详述（分）

### 2.1 本地数据存储（SQLite）

本机 SQLite 存储两类数据：

1. **cookie 列表**：存储已添加的闲鱼账号凭证（Cookie、闲鱼 ID、昵称、备注、是否有效、监听状态、创建时间）
2. **配置项（通用 key-value）**：
   - 最大监听数（默认 3）
   - 登录 token（管理后台登录后由 Electron 交给**内嵌 Python 服务**保存；**Python 为唯一持有者**，其他方经本地 API 获取）
   - **clientid**（与登录 token 同源写入、必须成对携带；网关校验二者是否匹配）
   - 消息合并滑动窗口时长（默认 5 秒）
   - 单批消息最长等待时长（默认 15 秒）

> 云端后台地址为打包时写死，不存本地配置。

### 2.2 安全规范（客户端需求 §十九）

| 项 | 要求 |
|----|------|
| 闲鱼 Cookie | 仅存本地，加密存储，永不上传云端 |
| 本地 HTTP 服务 | 仅绑定 127.0.0.1，禁止监听 0.0.0.0 |
| 本机与云端通信 | 携带登录 token 鉴权 |
| 消息发送 | 强制间隔限流，模拟真人行为 |

### 2.3 凭证体系（★已裁定：单凭证；原双凭证 / Agent 注册制作废）

#### 2.3.1 两类凭证的归属

| 凭证类型 | 作用 | 持有方 | 敏感等级 | 泄露后果 |
|----------|------|--------|----------|----------|
| 闲鱼凭证（Cookie） | 登录闲鱼账号、收发消息、拉取商品 | **仅本地**（AES-256-GCM 加密存 SQLite） | 极高 | 账号被盗、恶意操作、封禁 |
| 系统鉴权凭证（**管理后台登录 token**） | 校验客户端对云端的调用合法性 | 本地（内嵌 Python 服务持有）+ 云端网关校验 | 中 | 仅影响系统内部通信，不波及闲鱼账号 |

> 核心结论：
> 1. 云端（含管理后台）**不需要也不应该存储闲鱼 Cookie**；
> 2. 系统侧鉴权**统一使用管理后台登录 token**（`Authorization: Bearer <token>` + `clientid` 请求头，由网关统一校验），**不再引入独立的 Agent ID + API Key 体系**——原《技术方案.md》§五「双凭证体系 + Agent 注册制」**已作废**；
> 3. 云端不感知「设备 / Agent 实例」，只感知登录用户；闲鱼账号数据以 `goodfish_id` 维度维护。

#### 2.3.2 数据存储边界

严格划分本地与服务端的存储范围，敏感数据绝不越界。

| 数据类别 | 存储位置 | 说明 |
|----------|----------|------|
| 闲鱼登录凭证（Cookie） | 仅本地 | 加密存储，绝对不上传服务端 |
| 管理后台登录 token + clientid | 仅本地 | 由内嵌 Python 服务持有（SQLite config 表），随请求头带出；云端只校验、不存储 |
| 商品库、提示词模板 | 仅服务端 | 统一管理，本地启动后拉取缓存 |
| 模型配置、大模型 API 密钥 | 仅服务端 | 密钥统一托管，本地不可见 |
| 对话记录、消息日志 | 仅服务端 | 本地上报，云端持久化 |
| Agent 运行参数（端口、日志级别） | 仅本地 | 本机运行配置 |

#### 2.3.3 Token 本地加密方案

1. **密钥生成**：基于本机硬件标识 + 用户自定义主密钥派生加密密钥
2. **存储方式**：磁盘仅保存加密后的密文，启动时解密加载到内存
3. **使用原则**：仅内存中明文使用，进程退出自动释放
4. **验证逻辑**：输入 Token 后本地调用闲鱼接口验证，验证通过才加密存储

#### 2.3.4 进程与实例模型 ★（含一处待确认）

**现行方案**：Python **单进程**运行，进程内**每个监听账号一个独立 WebSocket 连接实例**（`XianyuLive`），共用同一个 asyncio 事件循环（见 [技术方案-客户端-总体架构](../技术方案/技术方案-客户端-总体架构.md) §2.3）。闲鱼 Cookie 全部留在本机，服务端零凭证风险。

> **★待确认**：是否需要改为「每个闲鱼账号 = 一个独立 Python 进程」。若改，启动端口协商、本地 API、进程守护与崩溃自愈、SQLite「单连接 + 串行化」等机制都要重新设计，**影响面大**；需单独裁定后再动，本文件不展开。

### 2.4 安全与风控规范（技术方案 §八）

#### 2.4.1 系统安全

- 本地服务接口仅绑定 `127.0.0.1`，禁止监听 `0.0.0.0`
- 本机 → 云端的所有通信必须携带管理后台登录 token（`Authorization: Bearer <token>`）**与 `clientid` 请求头**，由网关统一校验，防止伪造请求
- Electron ↔ Python 的本地接口统一校验 `X-Local-Token`（Electron 启动时生成、经环境变量传给 Python）
- 大模型密钥仅存服务端，统一管理调用，本地不可见

#### 2.4.2 账号安全

- 闲鱼 Token 永不离机，服务端零接触
- 本地磁盘加密存储，防止文件泄露
- 登录失效仅上报状态，不上传凭证内容
- 支持一键清空本地凭证

#### 2.4.3 平台风控

- 消息发送强制间隔限流，禁止秒回
- **无人工审核环节**：AI 生成后直接下发发送（已裁定，与《需求-客户端-消息自动回复》口径一致；早期文档的"默认人工审核模式"作废）
- 模拟真人回复时长随机延迟
- 异常流量自动熔断暂停发送

## 三、业务规则与约束

- 云端后台地址为打包时写死，不存本地配置
- 配置项默认值：最大监听数 3；消息合并滑动窗口时长 5 秒；登录 token 由内嵌 Python 服务统一持有（Electron 登录成功后交入）
- 闲鱼 Cookie/Token 仅存本地、加密存储，永不上传云端、永不离机，服务端零接触
- 本地 HTTP 服务仅绑定 127.0.0.1，禁止监听 0.0.0.0
- 本机与云端通信携带**登录 token + `clientid`** 鉴权，由网关统一校验（★二者必须同源成对）；Electron 与 Python 之间的本地接口统一校验 `X-Local-Token`
- Token 加密：磁盘仅存密文，启动时解密加载到内存，仅内存中明文使用，进程退出自动释放
- Token 入库前必须先本地调用闲鱼接口验证，验证通过才加密存储
- 消息发送强制间隔限流，模拟真人行为（随机延迟），禁止秒回
- 大模型密钥仅存服务端，本地不可见

## 四、异常与边界场景

| 场景 | 处理要求 |
|------|----------|
| Token 输入无效 | 本地调用闲鱼接口验证不通过，不加密存储 |
| 进程退出 | 内存中明文 Token 自动释放，磁盘始终只有密文 |
| 闲鱼登录失效 | 仅上报状态，不上传凭证内容 |
| 本地文件泄露风险 | 本地磁盘加密存储防护；支持一键清空本地凭证 |
| 异常流量 | 自动熔断暂停发送 |
| 多账号扩展 | 每个闲鱼账号 = 一个独立 WebSocket 连接实例（同一 Python 进程内，见 §2.3.4 待确认）；Cookie 全部留在本机，服务端零凭证风险 |
