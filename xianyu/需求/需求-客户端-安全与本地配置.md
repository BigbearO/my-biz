## 一、功能概述（总）

### 1.1 功能定位

本文件约束客户端的两条底线：一是**本地存什么**——SQLite 存储的数据范围与通用配置项；二是**安全红线**——闲鱼凭证永不出本机、本地服务仅绑定回环地址、通信鉴权与消息发送限流，并收录双凭证体系与存储边界的总体设计，解决"凭证安全与配置管理"问题。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | 本地数据存储 | 本机 SQLite 存储两类数据：cookie 列表、通用 key-value 配置项 |
| F2 | 本地配置项 | 最大监听数（默认 3）、登录 token、消息合并滑动窗口时长（默认 5 秒） |
| F3 | 安全规范 | Cookie 仅存本地加密存储、本地 HTTP 仅绑定 127.0.0.1、通信携带 token 鉴权、发送强制间隔限流 |
| F4 | 双凭证体系 | 闲鱼凭证与系统鉴权凭证（Agent ID + API Key）彻底分离 |
| F5 | 存储边界 | 本地与服务端的存储范围严格划分，敏感数据绝不越界 |
| F6 | Token 本地加密 | 硬件标识派生密钥，磁盘只存密文，仅内存明文使用 |

### 1.3 功能边界

- 最大监听数的业务使用规则归 [需求-客户端-监听控制](需求-客户端-监听控制.md)，滑动窗口时长的业务使用规则归 [需求-客户端-消息自动回复](需求-客户端-消息自动回复.md)，本文件只定义其配置存储

## 二、功能详述（分）

### 2.1 本地数据存储（SQLite）

本机 SQLite 存储两类数据：

1. **cookie 列表**：存储已添加的闲鱼账号凭证（Cookie、闲鱼 ID、昵称、备注、是否有效、监听状态、创建时间）
2. **配置项（通用 key-value）**：
   - 最大监听数（默认 3）
   - 登录 token（管理后台登录后的凭证，供 Electron 和 Python 两端共用）
   - 消息合并滑动窗口时长（默认 5 秒）

> 云端后台地址为打包时写死，不存本地配置。

### 2.2 安全规范（客户端需求 §十九）

| 项 | 要求 |
|----|------|
| 闲鱼 Cookie | 仅存本地，加密存储，永不上传云端 |
| 本地 HTTP 服务 | 仅绑定 127.0.0.1，禁止监听 0.0.0.0 |
| 本机与云端通信 | 携带登录 token 鉴权 |
| 消息发送 | 强制间隔限流，模拟真人行为 |

### 2.3 双凭证体系（技术方案 §五）

#### 2.3.1 两套独立凭证体系

彻底分离两类凭证，从根源上解决安全与管理的平衡问题。

| 凭证类型 | 作用 | 持有方 | 敏感等级 | 泄露后果 |
|----------|------|--------|----------|----------|
| 闲鱼凭证（Token/Cookie） | 登录闲鱼账号、收发消息 | 仅本地 Agent | 极高 | 账号被盗、恶意操作、封禁 |
| 系统鉴权凭证（Agent ID + API Key） | 标识 Agent 设备、校验内部通信合法性 | 本地 Agent + Web 后台 | 中 | 仅影响系统内部通信，不波及闲鱼账号 |

> 核心结论：Web 管理后台**不需要也不应该存储闲鱼 Token**。后台管理的是「Agent 设备实例」而非「闲鱼账号」，通过 Agent 注册制（agent_id + api_key）实现全部管理能力。

#### 2.3.2 数据存储边界

严格划分本地与服务端的存储范围，敏感数据绝不越界。

| 数据类别 | 存储位置 | 说明 |
|----------|----------|------|
| 闲鱼登录凭证 | 仅本地 | 加密存储，绝对不上传服务端 |
| Agent ID + API Key | 本地 + 服务端 | 系统内部身份标识，可安全存储 |
| 商品库、提示词模板 | 仅服务端 | 统一管理，本地启动后拉取缓存 |
| 模型配置、大模型 API 密钥 | 仅服务端 | 密钥统一托管，本地不可见 |
| 对话记录、消息日志 | 仅服务端 | 本地上报，云端持久化 |
| Agent 运行参数（端口、日志级别） | 仅本地 | 本机运行配置 |

#### 2.3.3 Token 本地加密方案

1. **密钥生成**：基于本机硬件标识 + 用户自定义主密钥派生加密密钥
2. **存储方式**：磁盘仅保存加密后的密文，启动时解密加载到内存
3. **使用原则**：仅内存中明文使用，进程退出自动释放
4. **验证逻辑**：输入 Token 后本地调用闲鱼接口验证，验证通过才加密存储

#### 2.3.4 Agent 注册机制（服务端零凭证管理）

1. 在 Web 后台手动创建 Agent 实例，生成唯一 `agent_id` 和对应 `api_key`
2. 将两者填入本地 Agent 配置文件
3. 此后所有双向通信携带 `api_key` 鉴权，服务端通过 `agent_id` 识别实例
4. 多账号扩展：每个闲鱼账号 = 一个本地 Agent 进程 = 一个 `agent_id`，Token 全部散落在各本地机器，服务端零凭证风险

### 2.4 安全与风控规范（技术方案 §八）

#### 2.4.1 系统安全

- 本地 Agent 接口仅绑定 `127.0.0.1`，禁止监听 `0.0.0.0`
- 所有双向通信必须携带 API Key 鉴权，防止伪造请求
- 大模型密钥仅存服务端，统一管理调用
- 定期轮换系统 API Key

#### 2.4.2 账号安全

- 闲鱼 Token 永不离机，服务端零接触
- 本地磁盘加密存储，防止文件泄露
- 登录失效仅上报状态，不上传凭证内容
- 支持一键清空本地凭证

#### 2.4.3 平台风控

- 消息发送强制间隔限流，禁止秒回
- **无人工审核环节**：AI 生成后直接下发发送（已裁定，与《需求-客户端-消息自动回复》口径一致；早期文档的"默认人工审核模式"作废）
- 模拟真人回复时长随机延迟
- 异常流量自动熔断暂停发送

## 三、业务规则与约束

- 云端后台地址为打包时写死，不存本地配置
- 配置项默认值：最大监听数 3；消息合并滑动窗口时长 5 秒；登录 token 供 Electron 和 Python 两端共用
- 闲鱼 Cookie/Token 仅存本地、加密存储，永不上传云端、永不离机，服务端零接触
- 本地 HTTP 服务仅绑定 127.0.0.1，禁止监听 0.0.0.0
- 本机与云端通信携带登录 token 鉴权；系统内部双向通信必须携带 API Key 鉴权，防止伪造请求
- Token 加密：磁盘仅存密文，启动时解密加载到内存，仅内存中明文使用，进程退出自动释放
- Token 入库前必须先本地调用闲鱼接口验证，验证通过才加密存储
- 消息发送强制间隔限流，模拟真人行为（随机延迟），禁止秒回
- 大模型密钥仅存服务端，本地不可见；系统 API Key 定期轮换

## 四、异常与边界场景

| 场景 | 处理要求 |
|------|----------|
| Token 输入无效 | 本地调用闲鱼接口验证不通过，不加密存储 |
| 进程退出 | 内存中明文 Token 自动释放，磁盘始终只有密文 |
| 闲鱼登录失效 | 仅上报状态，不上传凭证内容 |
| 本地文件泄露风险 | 本地磁盘加密存储防护；支持一键清空本地凭证 |
| 异常流量 | 自动熔断暂停发送 |
| 多账号扩展 | 每个闲鱼账号 = 一个本地 Agent 进程 = 一个 `agent_id`，Token 全部散落在各本地机器，服务端零凭证风险 |
