# 需求-客户端-日志（★无管理页面，仅落日志文件）

> 来源：《客户端需求.md》§十七 日志轮转（§十一「日志页」**已取消**）（内容重组收录，原文件保留未动）
> 关联：[技术方案-客户端-日志系统](../技术方案/技术方案-客户端-日志系统.md)

## 一、功能概述（总）

### 1.1 功能定位

日志是客户端运行过程的可追溯手段：**只落本地日志文件，不提供管理页面**。系统运行日志与消息收发记录（收到买家消息、AI 回复内容、发送结果）统一写入日志文件，供用户离线打开文件排查；文件自动轮转，避免无限膨胀。

> ★**已裁定取消「日志页」**：客户端左侧菜单只有**账号管理 / 设置**两项（★「云端管理」菜单同样已裁定取消），不再提供日志页；不再提供日志的界面查看、级别筛选、清空、导出能力。需要排查时直接打开日志文件。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | 日志内容 | 系统运行日志 + 消息收发记录（买家消息、AI 回复、发送结果）统一落文件 |
| F2 | 日志文件轮转 | 单文件 10MB 上限，最多保留 5 个历史日志文件，超限自动删除最旧文件 |
| F3 | 日志级别 | 只记录 INFO 及以上，不产生 DEBUG |

### 1.3 功能边界

- 日志由本地 Python 服务产生，实现归 [技术方案-客户端-日志系统](../技术方案/技术方案-客户端-日志系统.md)
- 消息收发记录对应的业务流程归 [需求-客户端-消息自动回复](需求-客户端-消息自动回复.md)
- **不提供**：日志页、界面筛选、清空、导出（均已取消）
- 云端侧的日志与监控归云端，不在本文件范围

## 二、功能详述（分）

### 2.1 日志内容与落盘

- 日志内容包含两类：系统运行日志、消息收发记录（收到买家消息、AI 回复内容、发送结果）
- 落盘位置：`%APPDATA%/goodfish/logs/`（打包后目录可写，禁止写 exe 同级目录）
- 级别：INFO / WARNING / ERROR，**客户端不产生 DEBUG 日志**
- **查看方式**：用户直接打开日志文件；应用内不提供查看页面

### 2.2 日志轮转

- 本地日志文件自动轮转
- 单文件大小上限：10MB
- 最多保留 5 个历史日志文件
- 超过上限自动删除最旧的日志文件

## 三、业务规则与约束

- 日志内容包含两类：系统运行日志、消息收发记录（买家消息、AI 回复、发送结果）
- 级别枚举：INFO / WARNING / ERROR（默认 INFO，不产生 DEBUG）
- 单文件大小上限 10MB；最多保留 5 个历史日志文件；超过上限自动删除最旧的日志文件
- 轮转为自动执行，无需用户干预
- ★**无日志管理页面**：不提供列表查看、级别筛选、清空、导出

## 四、异常与边界场景

| 场景 | 处理要求 |
|------|----------|
| 单个日志文件达到 10MB | 自动轮转，产生新日志文件 |
| 历史日志文件超过 5 个 | 自动删除最旧的日志文件 |
| 需要离线排查问题 | 直接打开 `%APPDATA%/goodfish/logs/` 下的日志文件 |
