## 一、功能概述（总）

### 1.1 功能定位

账号管理是客户端的默认首页，供用户统一管理本机的闲鱼账号 Cookie 凭证：添加账号、查看账号列表与状态、删除账号，并作为监听启停操作的入口，解决"多闲鱼账号凭证本地统一管理"的问题。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|------|--------|------|
| F1 | 账号列表页 | 表格分页展示已添加账号，Cookie 本身不在列表列显示 |
| F2 | 操作列 | 开始监听/停止监听、详情（查看完整 Cookie）、删除 |
| F3 | 删除确认逻辑 | 正在监听的账号删除前二次确认，确认后先停止监听再删除 |
| F4 | 添加账号流程 | 粘贴 Cookie → 本地验证有效性 → 自动拉取闲鱼 ID/昵称 → 去重后入库 |
| F5 | 状态展示 | 是否有效（对勾/叉）、监听状态（监听中/未监听）可视化展示 |

### 1.3 功能边界

- 本文件只覆盖账号列表、添加与删除的交互规则；开始/停止监听的内部逻辑归 [需求-客户端-监听控制](需求-客户端-监听控制.md)
- Cookie 的加密存储与本地数据结构归 [需求-客户端-安全与本地配置](需求-客户端-安全与本地配置.md)
- 添加账号后自动触发一次商品同步为 TODO 暂不实现，归 [需求-客户端-商品同步](需求-客户端-商品同步.md) 的 TODO

## 二、功能详述（分）

### 2.1 账号列表页（默认首页）

- 顶部：「添加账号」按钮
- 主体：表格分页展示
- 表格列：闲鱼 ID、闲鱼昵称、是否有效、监听状态、创建时间、备注、操作
- Cookie 本身不在列表列显示

### 2.2 操作列

| 按钮 | 说明 |
|------|------|
| 开始监听 / 停止监听 | 切换监听状态 |
| 详情 | 弹窗查看完整 cookie（默认脱敏 `***`，点击显示完整） |
| 删除 | 删除该条 cookie 记录（正在监听的账号需先确认停止） |

### 2.3 删除确认逻辑

- 如果该账号正在监听，点删除时弹出确认提示：
  > "该账号正在监听，会停止监听，是否确认删除？"
- 用户确认后 → 先停止监听 → 再删除记录
- 用户取消 → 不做任何操作

### 2.4 添加账号流程

1. 点击「添加账号」按钮
2. 弹出对话框，包含：
   - Cookie 输入框（多行粘贴），一次只输入一个
   - 备注输入框
3. 点击「确认」
4. 本地调闲鱼接口验证 Cookie 有效性
5. 验证通过 → 自动拉取闲鱼 ID、闲鱼昵称
6. 检查该闲鱼 ID 是否已存在
   - 已存在 → 提示"该账号已添加，请勿重复添加"
   - 不存在 → 连同备注一起存入本地数据库
7. 验证失败 → 提示错误信息，不存入

### 2.5 状态展示

| 状态字段 | 展示方式 |
|----------|----------|
| 是否有效 | 绿色对勾 = 有效，灰色叉 = 失效 |
| 监听状态 | 绿色"监听中" / 灰色"未监听" |

## 三、业务规则与约束

- 同一个闲鱼账号只能有一条 cookie 记录，因此同一账号只会有一个监听实例，不存在重复监听问题
- Cookie 本身不在列表列显示；详情弹窗默认脱敏 `***`，点击才显示完整
- 添加账号时一次只输入一个 Cookie
- Cookie 有效性验证在本地调用闲鱼接口完成，验证通过才连同备注一起存入本地数据库
- 正在监听的账号必须先停止监听，才能删除记录

## 四、异常与边界场景

| 场景 | 处理要求 |
|------|----------|
| 添加时该闲鱼 ID 已存在 | 提示"该账号已添加，请勿重复添加"，不存入 |
| 添加时 Cookie 验证失败 | 提示错误信息，不存入 |
| 删除正在监听的账号 | 弹出确认提示，用户确认后先停止监听再删除记录；用户取消则不做任何操作 |

## 五、验收标准

| 编号 | 验收项 | 判定标准 |
|------|--------|----------|
| A4 | 多账号管理 | 支持添加、删除、查看多个闲鱼账号 cookie |
| A5 | Cookie 脱敏 | 列表不显示完整 cookie，点详情才看完整 |
| A11 | 账号去重 | 同一闲鱼账号不能重复添加 |
| A26 | 删除监听中账号确认 | 删除正在监听的账号时弹出确认提示，确认后先停再删 |
