# 需求-云端-图片消息

> 来源：《云端技术方案.md》§十一 文件存储（买家聊天图片链路）、《云端需求.md》§五 验收表 A12 行（内容重组收录，原文件保留未动）
> 关联：[技术方案-云端-文件存储](../技术方案/技术方案-云端-文件存储.md)

## 一、功能概述（总）

### 1.1 功能定位

图片消息是买家发来图片时的自动回复支持能力：客户端把买家聊天图片上传到云端对话服务取得图片 URL，云端在消息处理时把该图片 URL 传给多模态模型识别图片内容，用于生成 AI 回复。

### 1.2 子功能清单

| 编号 | 子功能 | 说明 |
|---|---|---|
| 1 | 图片上传接口 | 客户端将买家聊天图片转 PNG 后上传（POST /api/ai/image，带 token），云端存服务器本地磁盘并返回访问 URL |
| 2 | 图片静态访问 | 提供免鉴权的图片访问 URL，供大模型厂商拉取 |
| 3 | 多模态识别 | 消息处理时对大模型传图片 URL（OpenAI 多模态格式）识别图片 |
| 4 | 长期留存 | 图片文件与对话历史同生命周期，长期保留，不做过期清理 |

### 1.3 功能边界

- 图片的下载、上传触发与失败降级在客户端侧完成，详见[客户端监听.md](../客户端监听.md) §2.4、§3.8.1、§3.9 第 9 步与 §3.5.1 `image` 配置。
- 消息处理主流程归[需求-云端-AI对话回复.md](需求-云端-AI对话回复.md)；本文件只覆盖图片消息相关链路。
- 存储原则：所有文件一律存【服务器本地磁盘】，不上云存储；**不使用 `ruoyi-file` 模块**，文件由归属服务自行提供上传与下载接口。

## 二、功能详述（分）

### 2.1 买家聊天图片链路

```
客户端用闲鱼 Cookie 下载图片 → 转 PNG → POST /api/ai/image（带 token）上传
    ↓
对话服务存服务器本地磁盘（image.storage_dir，UUID 文件名）→ 返回访问 URL
    ↓
/api/ai/reply 携带 image_url 字段（值为对话服务图片 URL）
    ↓
对大模型传该 URL（OpenAI 多模态格式 {"type":"image_url","image_url":{"url":...}}）
```

### 2.2 存储与访问约定

| 项 | 约定 |
|---|---|
| 归属服务 | **对话服务（goodfish-ai-service）** |
| 存储位置 | 服务器本地磁盘（`image.storage_dir`），UUID 文件名 |
| 静态访问 | `GET /api/ai/image/view/{filename}` 需加入网关白名单（`security.ignore.whites`）——大模型厂商拉取图片无法携带 token；**仅此路径放行**（上传 `POST /api/ai/image` 仍需鉴权）；文件名用 UUID，不可枚举，目录不可列 |
| 公网可达 | `public_base_url` 指向经网关的公网域名（厂商侧拉取需公网可达） |
| 消息记录 | `ai_conversation_message.content` 存该 URL；历史回放复用同一 URL，**不重复上传** |
| 保留策略 | **长期保留、不做过期清理**（与对话历史同生命周期）：不设 `image.retention_hours`，无 `tasks/cleanup.py` 清理任务 |

## 三、业务规则与约束

1. 客户端上传格式为 PNG；云端对话服务存服务器本地磁盘，UUID 文件名。
2. 图片访问 URL 需经网关公网域名可达且免鉴权（网关白名单），供大模型厂商拉取。
3. 消息记录只存 URL：`ai_conversation_message.content` 存该 URL，历史回放复用同一 URL，不重复上传。
4. 图片文件与对话历史同生命周期：**长期保留，不做过期清理**（不设保留时长配置项，不设清理任务）。

## 四、异常与边界场景

| 场景 | 处理要求 |
|---|---|
| 客户端下载 / 上传图片失败 | 降级为占位文本 `[图片]`，不阻断回复流程 |
| 大模型厂商拉取图片（无法携带 token） | `GET /api/ai/image/view/{filename}` 加入网关白名单免鉴权（仅此路径）；UUID 文件名不可枚举，目录不可列 |
